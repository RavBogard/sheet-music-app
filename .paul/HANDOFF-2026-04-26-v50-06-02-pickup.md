## What's Next: Plan v50-06-02 (Reconciliation modal §6.9)

### Scope (per ARCHITECTURE.md §6.9)

- **"Remote changed — keep mine / take theirs" reconciliation banner/modal** subscribed to engine's `DRAIN_VERSION_MISMATCH` event (engine state `'conflict'`).
- Reads the `failed`-status outbox row + remote doc to render a diff ("your edit was: X / remote is: Y").
- Routes user choice through `engine.resolveConflict(localId, choice, { newExpectedUpdatedAt })`:
  - `'mine'`: re-queues with the new server `updatedAt` so the next drain attempt succeeds with the user's edit
  - `'theirs'`: deletes the failed outbox row and discards the local edit (engine returns to 'dirty' or 'idle')
- a11y scan via jest-axe (mounted-and-interactive states for the modal).

### Substrate ready (delivered by v50-06-01)

- `engine.getState() === 'conflict'` is reliably reachable via VersionMismatchError
- `failed`-status outbox rows have `localId`, `lastError`, `payload`, `expectedUpdatedAt` all populated
- `engine.resolveConflict(localId, choice, opts)` API verified end-to-end via two-writer test
- Cross-tab-lock primitive verified deterministic (30/30) — same primitive coordinates the modal across tabs
- `wireSyncEngineToStore` channel exposes `(state, queued, lastError)` via `onStateChange` — modal subscribes here
