<objective>
## Goal
Org-scope the **public web setlist read paths** so brotherslazaroff.live shows
ONLY Brothers Lazaroff setlists (currently empty), never CRC's. Closes the live
cross-tenant read on `/perform` at BOTH the SSR admin fetch and the client
Firestore subscription.

## Purpose
v11-02 walled the MCP layer; the public web path was never scoped, so the
consumer surface (`/perform`) serves every tenant's setlists — CRC's real
setlists (Parashat Sh'lach, Shir Shabbat, Gavin Stein B'nei Mitzvah) render on
BL's domain. This is the cross-tenant-wall break (constraint 4) Daniel saw. It is
the core of the v11-04 consumer surface and is broken in prod right now.

## Output
Org-scoped `getAllSetlists`/`getUpcomingSetlists`/`getRecentSetlists`; per-host
dynamic `/perform`; org-filtered client subscription; composite Firestore index;
regression tests proving cross-tenant non-leak.
</objective>

## AC-1: SSR read is org-scoped
```gherkin
Given the prod deployment serving both centralreform.live and brotherslazaroff.live
When an anonymous visitor loads brotherslazaroff.live/perform
Then the SSR RSC payload contains ONLY setlists with orgId="brotherslazaroff"
  (currently zero → empty state), and ZERO CRC setlists
And centralreform.live/perform continues to show exactly CRC's setlists (unchanged)
```

## AC-2: Client subscription is org-scoped
```gherkin
Given /perform has hydrated and the client Firestore subscription has taken over
When the live `subscribeToAllSetlists` feed replaces the SSR seed
Then the client query filters to the current org (from useOrg()) and never
  surfaces another tenant's setlists after hydration
```

## AC-3: Default-org behavior preserved (no CRC regression)
```gherkin
Given a request with no resolvable org (absent/invalid x-org-id header)
When getAllSetlists runs
Then it defaults to orgId="crc" (mirrors v11-01/v11-02), so CRC behavior is
  byte-identical to today
```

## AC-4: Cross-tenant non-leak proven by test
```gherkin
Given setlists seeded for orgId="crc" and orgId="brotherslazaroff"
When getAllSetlists({ org: "brotherslazaroff" }) is called
Then it returns only the BL rows; calling with org "crc" returns only CRC rows
```
