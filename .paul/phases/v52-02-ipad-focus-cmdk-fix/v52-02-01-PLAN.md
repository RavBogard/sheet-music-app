<objective>
## Goal

Fix Issues 2 and 3 (iPad text-input keyboard not popping; iPad Chart picker search broken) at the **systemic root** by converting v51-01's blanket auto-focus suppression in `TouchOrPopover` from "always on `(pointer:coarse)`" to "opt-in via `suppressAutoFocus` prop". DropdownCell discrete-mode opts in (preserves no-keyboard-on-open for Key/Type/AddRow/Bulk pickers); searchable mode (Lead/ChartBind/Bulk-Lead/AddRow library lookup) does NOT, so the cmdk `CommandInput` auto-focuses on open and the iPad keyboard pops, letting the user type to filter immediately. If Issue 2 (TextCell — track-name/Notes inline-editing text input) turns out NOT to be fixed by this substrate change (because TextCell doesn't route through TouchOrPopover), Task 1 includes a focused TextCell investigation step and either extends scope or routes to a follow-up plan in v52-02 phase per v51-04 UAT-failure rule.

## Purpose

v51-04 UAT surfaced 3 of 4 iPad regressions clustering around v51-01's TouchOrPopover focus-suppression rule. The systemic fix is to make suppression opt-in rather than always-on for `(pointer:coarse)`, restoring iPad keyboard behavior on text-input surfaces while preserving the deliberate-tap pattern for discrete pickers (Key/Type) where there's no input to focus and the system keyboard popping was the original v51-01 complaint. Daniel asked explicitly: **"systemic fixes, not bandaids."** This is the substrate-level fix that closes the cluster.

Direct PROJECT.md value mapping: "Tablet-first application (band on stage uses iPads; Daniel uses iPad to build setlists)." Until the iPad keyboard pops on tap of text-input surfaces and Chart search filters typing, the band-onboarding gate is blocked.

## Output

- `TouchOrPopover` extended with `suppressAutoFocus?: boolean` prop (default `false`)
- `DropdownCell` discrete-mode wires `suppressAutoFocus={true}`; searchable mode does NOT (keeps default false → keyboard pops on tap inside the popover)
- New regression tests covering both modes
- Suite green; `tsc` + `next build` clean
- Daniel-loop UAT acceptance criterion satisfied on real iPad post-deploy
- If TextCell focus is still broken on iPad post-deploy: route a follow-up plan in v52-02 phase (per v51-04 UAT-failure rule)
</objective>
