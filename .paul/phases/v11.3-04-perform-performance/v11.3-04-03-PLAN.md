<objective>
## Goal
Cut the `/perform` cold-load **TTFB/FCP** (FIX-2 from v11.3-04-01) by removing the blocking
`getAllSetlists` Firestore query from the first-byte critical path. Today `src/app/perform/page.tsx`
is `force-dynamic` and `await`s `getAllSetlists({ limit:50, org })` synchronously before any HTML is
sent → the server can't flush a byte until Firestore returns. Move the data fetch into a streamed
`<Suspense>` boundary so the shell (the existing `PublicSetlistSkeleton`) flushes immediately and the
listing streams in — dropping the query out of TTFB/FCP. **Query logic is moved, not changed**, so
v11-04-01 per-tenant scoping and the Cycle-12 F-C12-001 wire slice stay byte-identical.

## Purpose
`/perform` cold p75 (field): TTFB 1633ms / FCP 3551ms — the band's highest-traffic surface is the
slowest. Streaming makes first paint independent of the Firestore round-trip, improving perceived
load on the iPads. **Honesty bound (from characterization § 2):** synthetic cold TTFB was 214ms vs
field 1633ms — the gap is dominated by serverless cold-start + real-user geo/network, which is
INFRA-level, not app code. Streaming removes the *query* portion of TTFB/FCP; any residual cold-start
TTFB is a Vercel-config lever (fluid compute / warmth / region), logged as a follow-up, NOT more app
churn. This plan does the clean in-app fix and measures honestly.

## Output
`src/app/perform/page.tsx` restructured: a fast shell + a streamed async child that does
`headers()` + `getAllSetlists` + `selectVisiblePublicSetlists`, with `PublicSetlistSkeleton` as the
Suspense fallback. No change to `getAllSetlists`, `selectVisiblePublicSetlists`, `PublicSetlistListing`,
or the wire payload.
</objective>
