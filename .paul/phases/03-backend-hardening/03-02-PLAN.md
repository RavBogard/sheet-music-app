Add Zod validation to the chat route, track context loading failures, add production warn logging, standardize timestamp usage, and add library cache invalidation after sync.

- Logger with production `warn` level
- Library cache invalidation on sync completion
- Timestamp usage consistency guidance (centralized toDate helper)

    - This enables production visibility for warnings (rate limit fallbacks, notification failures, etc.)

    **library-cache.ts (MED-015):**
    - Add a `broadcastCacheInvalidation()` function that uses `BroadcastChannel`:
      ```
      export function broadcastCacheInvalidation(): void {
        try {
          if (typeof window === 'undefined' || !('BroadcastChannel' in window)) return
          const channel = new BroadcastChannel('library-cache')
          channel.postMessage({ type: 'invalidate' })
          channel.close()
        } catch {
          // BroadcastChannel not supported — single-tab fallback is fine
        }
      }
      ```
    - Add a `listenForCacheInvalidation(callback: () => void): () => void` function:
      ```
      export function listenForCacheInvalidation(callback: () => void): () => void {
        if (typeof window === 'undefined' || !('BroadcastChannel' in window)) return () => {}
        const channel = new BroadcastChannel('library-cache')
        channel.onmessage = (event) => {
          if (event.data?.type === 'invalidate') callback()
        }
        return () => channel.close()
      }
      ```
    - Find the sync completion handler (likely in a library sync API route or hook) and add `clearLibraryCache()` + `broadcastCacheInvalidation()` calls after successful sync
