<objective>
## Goal
Make the Perform **reading controls** airtight on iPad: the zoom level is always
readable (WS-18), the transpose control is provably reachable on real iPad
viewports (WS-22), the "Fit" control has honest semantics (WS-26), and a
portrait PDF can be read **fully** in landscape without vertical scroll via a new
**fit-page** mode (WS-14).

## Purpose
Two of the three Camp Sabra anchor sets open PDF/text charts the band reads at a
music stand. The stress sweep flagged: the zoom % is invisible on iPad (a bare
`/`), the transpose click timed out, "Fit to width" is really a 100% reset, and
landscape portrait-PDFs overflow below the fold with no way to see the whole page.
These are the highest live-weight reading-control defects on the all-PDF
Juneteenth set and the text camp sets. Image-chart findings (WS-06/15) are
deferred to Plan 06 — the 3 weekend sets contain **no image charts**.

## Output
- `PerformanceToolbar.tsx`: zoom-% readout always visible; "Fit" control sets
  fit-mode (designed via /ui-ux-pro-max).
- `PDFViewer.tsx` + `pdf-viewer-state.ts`: fit-page rendering + pure
  `computeFitPageWidth` helper (jsdom-safe, unit-tested).
- `store.ts`: ephemeral `fitMode` state + setter.
- `e2e/v11-6-perform-stress.spec.ts`: transpose cell targets the **visible**
  breakpoint trigger (WS-22 root-cause fix) + live re-run proof.
- Tests green, `next build --webpack` clean, real-iPad UAT items appended.
</objective>

## AC-1: Zoom level always readable on iPad (WS-18)
```gherkin

```

## AC-2: Transpose control provably reachable on iPad (WS-22)
```gherkin
Given the live stress sweep opens a transposable chart on an iPad viewport
  (portrait AND landscape, on both a PDF set and a text/plain set)
When the sweep targets the transpose trigger
Then it targets the VISIBLE breakpoint trigger (never the display:none one)
And clicking it opens the TransposerMenu within 6s
And "Transpose up"/"Transpose down" apply (the +2/-1 cell passes, not times out)
And the sweep observations.json records the transpose cell as PASS for all runs
```

## AC-3: "Fit" control has honest semantics (WS-26)
```gherkin
Given a chart is open
When the player taps the "Fit" control
Then the chart fits the viewport per the active fit-mode (width or page)
And the control's label/aria-label accurately describes what it does
  (no "Fit to width" wording that silently means "reset to 100%")
```

## AC-4: Portrait PDF fully readable in landscape via fit-page (WS-14)
```gherkin
Given a single-page portrait PDF chart open on an iPad in LANDSCAPE
When fit-mode is set to "page"
Then the whole page is visible within the viewport height with no vertical scroll
  required to read it (page scaled to fit height, centered)
And fit-mode "width" preserves the current full-width behavior (byte-identical default)
And the default fit-mode on opening any chart is "width" (no regression)
```

## AC-5: Pure fit math is unit-tested and jsdom-safe (WS-14)
```gherkin
Given the fit-page width computation lives in pure pdf-viewer-state.ts
When `computeFitPageWidth` is called with container W/H, page aspect ratio, mode, zoom
Then "width" mode returns container-width * zoom (unchanged contract)
And "page" mode returns min(containerWidth, containerHeight / pageAspect) * zoom
And edge cases (0 height, 0 aspect, landscape vs portrait page) return safe values
And the helper has no react-pdf/DOM dependency (runs in jsdom)
```
