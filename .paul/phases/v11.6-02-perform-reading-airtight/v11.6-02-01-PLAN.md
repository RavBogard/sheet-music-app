<objective>
## Goal
Make Perform-mode setlist **navigation and row hydration airtight** so that
(a) opening any bonded chart row — including non-song prayer/reading rows —
shows that chart instead of bouncing to song 1, (b) a live-director
insert/swap/reorder never yanks a follower off the chart they're reading,
and (c) setlist rows reliably hydrate on iPad Safari / flaky camp wifi.

Closes WS-02 (P1, CSP hydration quick win), WS-01 (P0, bonded-non-song
bounce), and WS-09 (P1, follower-yank) from the v11.6-01 triage report.

## Purpose
The band reads charts off iPads in service. WS-01 hits THIS Friday's Shir
Shabbat—Juneteenth set, whose bonded prayer rows (Shema, Mi Chamocha, Adonai
sfatai) bounce the musician to song 1 the instant they tap them — a chart
they need is unreachable. WS-02 can leave the whole set un-hydrated on camp
wifi (rows never appear). WS-09 can pull a follower off their chart mid-song
when the director edits the set. All three break the core value: "the band
gets the right chart on their iPad each week."

## Output
- `src/proxy.ts`: CSP `img-src` permits `https://www.google.com` (Firestore
  long-poll `cleardot.gif` beacon).
- `src/components/performance/PDFOverlay.tsx`: queue includes any
  fileId-bearing row (not just `type==='song'`); `queueStart`/sync resolution
  never collapses -1→0 in a way that navigates the user away from the row
  they opened or the chart they're currently reading.
- Unit tests proving queue resolution for bonded non-song rows and the
  -1-resolution guard.
- Re-run `e2e/v11-6-perform-stress.spec.ts` open-chart cell as live proof.
</objective>

## AC-1: Bonded non-song row opens its own chart (WS-01, P0)
```gherkin

  "Shema" on the Shir Shabbat—Juneteenth set
```

```gherkin
  surviving openable row)
```

<task type="auto">
  <name>Task 2: Include bonded non-song rows in the Perform queue + guard -1 resolution (WS-01 + WS-09)</name>
  <files>src/components/performance/PDFOverlay.tsx</files>
  <action>
    Root cause (all three effects): the queue is built by filtering
    `t.fileId && (!t.type || t.type === "song")` (PDFOverlay.tsx:116, 134,
    154). A bonded non-song row (prayer/reading with a fileId) is excluded,
    so `songTracks.findIndex(setlistIndex === currentIndex)` returns -1, then
    `Math.max(0, queueStart)` (line 125) collapses to 0 and the
    queueIndex→setlist sync effect (148-162) calls `onNavigate` to song 1.

    Fix in TWO parts, applied consistently to all three effects:

    (a) WS-01 — Widen the queue membership predicate to ANY openable
        fileId-bearing row, dropping the `type==='song'` restriction:
        `.filter(({ track: t }) => !!t.fileId)`.
        Define the predicate ONCE (a small local helper or shared const in
        this file) and use it in the build effect (114-128), the
        currentIndex-sync effect (131-145), and the queueIndex-sync effect
        (148-162) so they can never diverge again. Prayer/reading charts
        become first-class navigable queue members — exactly what
        `SetlistRow` already makes openable. (Audio/metronome behavior is
        keyed on real bpm/mime downstream; a prayer chart with no bpm simply
        shows no TempoFlash — already handled at 101-108.)

    (b) WS-09 — Make -1 resolution non-destructive. When
        `songTracks.findIndex(...)` returns -1 (the opened/current row isn't
        in the rebuilt queue — e.g. a director edit removed/replaced it), do
        NOT snap to 0 and do NOT fire onNavigate. Instead:
        - On queue (re)build (114-128): if `queueStart === -1`, preserve the
          existing `queueIndex` if it's still in range, else clamp to the
          nearest valid index WITHOUT triggering a parent navigation.
        - In the queueIndex→setlist sync effect (148-162): keep the existing
          `queueIndex >= 0 && queueIndex < songTracks.length` guard so an
          out-of-range index never calls onNavigate.
        The invariant: a queue rebuild or index miss must never move the
        musician off the row they're reading.

    Keep `trackIds` (line 112) as the rebuild trigger. Preserve the
    body-scroll-lock and TempoFlash effects unchanged.
    Avoid: changing the store `setQueue` signature; adding non-fileId
    (header/section) rows to the queue; introducing a new dependency;
    converting the effects to fire onNavigate during a rebuild.
  </action>
  <verify>New/updated unit test (see Task 3) green; `tsc --noEmit` exit 0; re-run the `open-chart` cell of `e2e/v11-6-perform-stress.spec.ts` against prod on the Juneteenth set — opening a bonded prayer row shows its chart, no bounce to song 1.</verify>
