<objective>
## Goal
Make **PDF chart rendering reliable on iPad** so the band never gets stranded
on a chart that won't appear and always knows when a chart has more than one
page. Closes the PDF-render P1/P2 cluster: WS-05 (render-stage stuck spinner —
no watchdog/Retry once bytes arrive; blank `<Page width=0>` on a 0-width
container), WS-07 (multi-page PDFs stack with no page indicator / page-2
hidden below the fold), WS-16 (manual-retry budget never resets on rotate →
terminal dead-end).

## Purpose
The Friday **Shir Shabbat—Juneteenth** weekend set is all-PDF. Today a
render-stage hang or a transient 0-width measure (iPad rotate during load)
leaves a musician staring at an infinite "Rendering…" spinner or a blank page
with no Retry — the fetch-only 60s timeout doesn't cover it. Multi-page charts
silently hide page 2+. Once the 3-retry budget is spent, even a rotate can't
recover. These are direct "can't read the chart in service" failures on the
live PDF set.

## Output
- `src/components/music/PDFViewer.tsx`: render-stage watchdog (Retry instead of
  infinite spinner), a `width > 0` guard (no blank zero-width pages), a
  visible multi-page indicator, and a retry-budget reset on a rotate-scale
  resize.
- `src/components/music/__tests__/pdf-viewer.test.tsx`: new — mocks `react-pdf`
  to exercise the wrapper-level states (watchdog→Retry, page indicator,
  width-guard, retry-reset). Actual pdfjs render behavior → real-iPad UAT
  (react-pdf does not render in jsdom).
</objective>

<acceptance_criteria>

## AC-1: Render-stage hang surfaces a Retry, never an infinite spinner (WS-05)
```gherkin
Given a PDF whose bytes have loaded (source set) but pdfjs rendering does not
  complete (onLoadSuccess never fires) within the render watchdog window
When the watchdog elapses
Then the viewer shows an error state with a Retry button (not a perpetual
  "Rendering…" spinner)
And the watchdog is cleared the moment rendering succeeds (no false trip).
```

## AC-2: A zero-width container never renders blank pages (WS-05)
```gherkin
Given the measured container width is 0 (e.g. a transient iPad rotate-during-load)
When the Document would render its pages
Then pages are NOT rendered at width 0 (no blank/clipped page); a measuring
  placeholder shows until width > 0, then pages render at the real width.
```

## AC-3: Multi-page PDFs expose a page indicator (WS-07)
```gherkin
Given a PDF chart with more than one page
When it renders on iPad
Then a visible indicator communicates the page count (e.g. "Page X of N"),
  so the musician knows there are more pages below the fold
And a single-page chart shows no misleading multi-page affordance.
```

## AC-4: Retry budget resets on a rotate-scale resize (WS-16)
```gherkin
Given the manual-retry budget is exhausted on a chart (error, 3/3 used)
When the container is resized at rotate scale (orientation change)
Then the retry budget resets so the musician can attempt the chart again
  without leaving and re-entering.
```
