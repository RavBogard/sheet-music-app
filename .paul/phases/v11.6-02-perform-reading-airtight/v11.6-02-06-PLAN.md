<objective>
## Goal
Make image charts in Perform behave like the other viewers: the toolbar Zoom
buttons actually scale the image (WS-06), and a failed image load offers a
Retry instead of a dead "try refreshing" message (WS-15).

## Purpose
Image charts are the one viewer the v11.6-01 sweep flagged as a usability dead
end: Zoom buttons are present but inert (the toolbar moves store `zoom` but
`ImageScoreViewer` never reads it), and a load failure has no recovery. PDF and
text both honor zoom + offer Retry; image should match. NOTE: the 3 Camp Sabra
weekend sets contain NO image charts — this is lower live-weight hardening, kept
small, so the band's image charts (other weeks / other tenants) aren't a dead end.

## Output
- `ImageScoreViewer.tsx`: reads store `zoom` and scales the image in a scrollable
  container; error state gains a Retry that re-attempts the load.
- New `image-score-viewer.test.tsx` covering zoom application + retry recovery.
</objective>

<task type="auto">
  <name>Task 1: WS-06 — ImageScoreViewer honors store zoom (scrollable scale)</name>
  <files>src/components/music/ImageScoreViewer.tsx</files>
  <action>
    Read `zoom` from the store: `const zoom = useMusicStore(s => s.zoom)` (selector
    form, matching PDFViewer). Apply it so the toolbar Zoom buttons (which already
    call setZoom) actually scale the image:
    - Make the outer container scrollable: add `overflow-auto` to the wrapping div
      (keep `flex items-center justify-center bg-background` so a sub-container
      image stays centered).
    - Scale the `<img>` by `zoom`. Use the CSS `zoom` property
      (`style={{ zoom }}`) — UNLIKE `transform: scale()`, CSS `zoom` grows the
      element's LAYOUT box so the `overflow-auto` container becomes scrollable and
      the player can pan a zoomed image to its edges. CSS `zoom` is supported on
      the target browsers (iPad WebKit + desktop Chrome; Firefox 126+). Keep
      `max-h-full max-w-full object-contain` so zoom 1 stays the current
      fit-to-container baseline (byte-identical default).
    - Keep native pinch-zoom working (do not add a pointer-capturing overlay).
    - Use /ui-ux-pro-max for the exact treatment (transformOrigin/centering so
      zoom feels anchored, smooth `transition` honoring prefers-reduced-motion).
    Avoid: `transform: scale()` (doesn't grow the scroll area → can't pan);
    measuring natural dimensions (unnecessary — CSS zoom handles it); changing the
    zoom-1 fit baseline.
  </action>
  <verify>`npx vitest run image-score-viewer` AC-1/AC-2 cases pass; `npx tsc --noEmit` 0.</verify>
  <done>AC-1 + AC-2 satisfied: image scales with store zoom, scrollable when zoomed, fit baseline at zoom 1.</done>
</task>

<task type="auto">
  <name>Task 2: WS-15 — image load error offers Retry that re-attempts</name>
  <files>src/components/music/ImageScoreViewer.tsx</files>
  <action>
    Replace the dead "Image failed to load — try refreshing" error block with a
    recoverable error state (parity with PDFViewer's Retry):
    - Add a `reloadNonce` state (number). The error block renders a Retry Button
      (lucide `RefreshCw`, ≥44px / h-11) that, on click, sets `status: 'loading'`
      and bumps `reloadNonce`.
    - Force the `<img>` to re-attempt the load by keying it on the nonce
      (`key={reloadNonce}`) — this REMOUNTS the img so the browser re-requests the
      SAME `url`. Do NOT append a cache-bust query param: image `url`s can be
      signed Storage URLs whose signature covers the query string, so mutating it
      would 403. Remount is signature-safe (cf. PDFViewer cache-busts because it
      fetches bytes itself; here the browser owns the request).
    - Reset `status` to 'loading' on `url` change AND keep the existing
      onLoad→'loaded' / onError→'error' handlers.
    - Keep the copy honest: e.g. "Couldn't load this image." + the Retry button.
    Avoid: appending `?_r=` to the url (signed-URL breakage); an auto-retry loop
    (manual Retry only — user-driven, no cap needed).
  </action>
  <verify>`npx vitest run image-score-viewer` AC-3 cases pass; `npx tsc --noEmit` 0.</verify>
  <done>AC-3 satisfied: error state shows a working Retry that returns to loading and re-attempts the load.</done>
