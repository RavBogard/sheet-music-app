<task type="auto">
  <name>Task 1: Add Google OAuth profile scope to GoogleAuthProvider</name>
  <files>src/lib/firebase.ts</files>
  <action>
    After each `googleProvider = new GoogleAuthProvider()` call (lines 61, 65, 73), add:
    ```
    googleProvider.addScope('profile');
    ```

    There are 3 instantiation sites in firebase.ts:
    1. Line 61 (normal init path)
    2. Line 65 (else branch — config missing)
    3. Line 73 (catch branch — init failed)

    All three need the scope added so the provider is consistent regardless of init path.

    This is the root cause of the avatar bug — without the `profile` scope, Google doesn't return the `picture` claim in the ID token, so Firebase Auth's `User.photoURL` is always null.

    DO NOT change any other Firebase configuration.
    DO NOT add the `email` scope (it's included by default).
  </action>
  <verify>
    - `npx tsc --noEmit` passes
    - `npx vitest run` — all tests pass
    - Grep for GoogleAuthProvider to confirm all sites have addScope
  </verify>
  <done>AC-1 and AC-3 satisfied: GoogleAuthProvider requests profile scope, photoURL will be populated on next sign-in</done>
</task>
