<objective>
## Goal
Org-scope the `recordings` collection end-to-end: stamp each upload with the
caller's **host org** (`x-org-id`) instead of the hardcoded `DEFAULT_ORG_ID`,
and filter the song-recordings subscription by the viewer's current org — so a
broslaz reference recording never surfaces on CRC and vice-versa.

## Purpose
Closes the v11.1-03-deferred `recordings` tenancy gap. Recordings are
band-internal reference audio; today every upload lands `orgId: 'crc'` and the
`subscribeRecordingsForSong` query has **no** org filter, so any recording shows
on both tenants by `songId`. This is the last cross-tenant data leak on the
recordings path. **Verified forward-safe: prod `recordings` collection is empty
(0 docs, probed 2026-06-22)** — no backfill, the new subscribe filter hides
nothing existing. err-public holds WITHIN a tenant; the org filter is the hard
wall ACROSS tenants.

## Output
- Upload route stamps `orgId` from the resolved host org.
- `subscribeRecordingsForSong` takes an `orgId` arg and filters on it.
- New composite index `recordings(orgId ASC, songId ASC, createdAt DESC)` +
  `firebase deploy --only firestore:indexes`.
- Updated route + popover tests; tsc 0; `next build --webpack` 0.
</objective>

  And the broslaz recordings are never delivered
