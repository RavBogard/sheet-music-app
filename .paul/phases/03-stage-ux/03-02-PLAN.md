<objective>
## Goal
Harden the PDF takeover on stage: wrap `PDFOverlay` with the existing `SectionErrorBoundary` so a PDF.js crash doesn't blank the screen, bind `Escape` to close, and remove the redundant `fixed inset-0 z-50` wrapper on the standalone `/perform/[fileId]` route.

## Purpose
If PDF.js throws mid-service (bad file, network hiccup, worker crash), the current setup shows a blank black overlay with no escape hatch — catastrophic live. ErrorBoundary gives a visible error + back action. Esc-to-close matches SwapPicker (03-01) and standard modal conventions. The `[fileId]` route's double-wrap means PDFOverlay's own `fixed inset-0 z-50 bg-background` root is stacked inside an identical wrapper — harmless today, but a bug magnet (e.g., safe-area padding applied twice, portal z-index off by one).

## Output
Minimal edits to two files. No new components. Reuses `SectionErrorBoundary`.
</objective>
