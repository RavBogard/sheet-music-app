<objective>
## Goal
Close the remaining four stage-view polish items so the live performance screen is ready for the band: per-chart transposition actually shows through on the setlist, amber cue-notes are legible under stage lighting, the liturgical header is easy to tap, and the offline indicator tells musicians how many of *their* charts are actually available.

## Purpose
Phase 3 is the gate before onboarding the band. The swap flow (03-01), PDFOverlay hardening (03-02), and notification plumbing (03-03) are all in. What remains are the four rough edges in the setlist view itself that a musician standing on stage with a tablet will notice immediately.

## Output
- `SetlistRow` reads `track.transposition` and surfaces the overridden key in the displayed key badge (public view continues to show original key).
- Amber cue-note text bumped from low-opacity (`text-amber-400/70`) to full-opacity stage-legible amber.
- Liturgical (`type: 'header'`) rows get a real tap target that leaders can use to set position — minimum 44px hit area per WCAG touch-target guidance.
- `PerformanceOfflineIndicator` reads IndexedDB (`listFileIds` from Phase 1.2) and, when offline, reports `N/M charts ready offline` for the tracks actually in the current setlist. Online state keeps the brief "RECONNECTED" pulse.
- Tests pinning each behaviour.
</objective>

<acceptance_criteria>

## AC-1: Per-chart transposition override shows in the setlist row
```gherkin
Given a setlist track has `transposition: 3` and `key: "C"`
 And the musician's profile has `defaultTransposition: 0`
 And the view is NOT public
When SetlistRow renders
Then the key badge displays the key transposed by 3 semitones (e.g. "Eb")
 And the `data-testid="key-badge"` element reflects the track override, not the profile default

Given the same track
 And `isPublicView === true`
When SetlistRow renders
Then the key badge displays the original key ("C")
 (public/guest view never reveals a specific musician's transposition)

Given a track has no `transposition` field (or `transposition === 0`)
When SetlistRow renders
Then behaviour matches today — profile `defaultTransposition` applies as before (no regression on AC from prior phases)
```

## AC-2: Amber cue-notes legible at stage distance
```gherkin
Given a song track with `notes: "Cue in after Amen"`
When SetlistRow renders
Then the notes element has a Tailwind class that resolves to full-opacity amber (not `/70`, not `/50`)
 And contrast ratio against the row's amber-tinted background meets at minimum 4.5:1 for normal text
```

## AC-3: Liturgical header hit area ≥44px and leader-actionable
```gherkin
Given a track with `type: "header"` and `title: "Shacharit"`
 And `isLeader === true`
When SetlistRow renders
Then the header row is a `<button>` (or role="button" with keyboard handler) spanning the full row width
 And its clickable height is ≥44px (min-h-11 or equivalent)
 And clicking fires `onLeaderSetPosition`

Given the same header row
 And `isLeader === false`
When SetlistRow renders
Then the row has no interactive affordance (no role="button", no cursor:pointer)
 And no accessibility noise (no tabindex, no keyboard handler)
```

## AC-4: Offline indicator reports N/M charts ready from IDB
```gherkin
Given the musician is offline
 And the current setlist has 8 song-type tracks with fileIds
 And IDB contains 6 of those 8 fileIds
When PerformanceOfflineIndicator renders
Then the pill reads "OFFLINE — 6/8 CHARTS READY" (or equivalently clear copy with both numbers)
 And the pill stays visible while offline

Given the musician is online
When PerformanceOfflineIndicator renders
Then the component returns null unless a reconnect just happened
 And when it does show the brief "RECONNECTED" pulse, no chart count is displayed

Given the setlist has zero song tracks with fileIds
When offline
Then the pill degrades gracefully to the plain "OFFLINE MODE" copy (no "0/0" fraction)
```
