<task type="auto">
  <name>Task 2: Create shared Firebase Admin mock and API test helpers</name>
  <files>
    src/__tests__/mock-firebase-admin.ts,
    src/__tests__/api-test-helpers.ts
  </files>
  <action>
    **mock-firebase-admin.ts:**

    Extract the Firebase Admin mock pattern from route-auth.test.ts into a reusable module.

    Export:
    - `mockFirestore` — the mock Firestore instance with configurable doc/collection behavior
    - `mockVerify` — the mocked verifyIdToken function
    - `setupFirebaseAdminMocks()` — function that calls `vi.mock('@/lib/firebase-admin', ...)` and returns `{ mockFirestore, mockVerify }`
    - `mockAuth(role: string)` — configures mockVerify to return a user with the given role and correct claim flags

    The mock Firestore should have a configurable `mockDoc` that tests can override:
    ```ts
    export const mockDoc = {
        exists: true,
        data: () => ({}),
        ref: { update: vi.fn() },
    }
    ```

    **api-test-helpers.ts:**

    Extract `makeReq` from route-auth.test.ts into a shared module:
    ```ts
    export function makeReq(url: string, opts?: {
        method?: string
        token?: string
        body?: Record<string, unknown>
        headers?: Record<string, string>
    }): NextRequest
    ```

    Also export common mock setups:
    ```ts
    export function mockRateLimit(): void  // vi.mock('@/lib/rate-limit', ...)
    export function mockLogger(): void     // vi.mock('@/lib/logger', ...)
    ```

    **IMPORTANT:** `vi.mock()` calls must be in the consuming test file (vitest hoists them). The helpers should export the mock *objects* and *factory functions*, not the vi.mock calls themselves. Tests will still need to call vi.mock() at file scope but can reference the shared mock objects.

    Actually, the cleaner pattern for vitest: export the mock implementations as objects, and let each test file do its own `vi.mock(...)` referencing these exports. Example:
    ```ts
    // In mock-firebase-admin.ts
    export const mockFirestore = { ... }
    export const firebaseAdminMock = {
        initAdmin: vi.fn().mockReturnValue(true),
        getFirestore: vi.fn(() => mockFirestore),
        verifyIdToken: vi.fn(),
    }
    ```
    ```ts
    // In test file
    import { firebaseAdminMock } from '@/__tests__/mock-firebase-admin'
    vi.mock('@/lib/firebase-admin', () => firebaseAdminMock)
    ```
  </action>
  <verify>
    Run: `npx tsc --noEmit` — helpers type-check correctly.
  </verify>
  <done>AC-3 satisfied (Firebase Admin mock reusable), AC-4 satisfied (API test helpers simplify route testing)</done>
</task>

<task type="auto">
  <name>Task 3: Fix flaky route-auth test and refactor to use shared helpers</name>
  <files>src/app/api/__tests__/route-auth.test.ts</files>
  <action>
    **Fix the flaky timeout:**
    The first publish test takes ~367ms because `await import('@/app/api/setlist/publish/route')` is a cold dynamic import. Fix by importing the route module once at the describe level using a `let` + `beforeAll`:

    ```ts
    describe('POST /api/setlist/publish', () => {
        let POST: (req: NextRequest) => Promise<Response>

        beforeAll(async () => {
            const mod = await import('@/app/api/setlist/publish/route')
            POST = mod.POST
        })
    ```

    Apply the same pattern to all describe blocks that use dynamic imports (publish, set-role, drive/file, email-packets).

    **Refactor to use shared helpers:**
    - Import `makeReq` from `@/__tests__/api-test-helpers`
    - Import `firebaseAdminMock`, `mockFirestore`, `mockAuth` from `@/__tests__/mock-firebase-admin`
    - Remove the local `makeReq`, `mockAuth`, `mockFirestore`, `mockDoc`, etc. definitions
    - Keep the `vi.mock(...)` calls at file scope (vitest requires hoisting)
    - Update vi.mock calls to reference shared mock objects

    **Preserve all test behavior:** Same assertions, same test names, same coverage. Only the setup changes.
  </action>

    Run: `npx vitest run src/app/api/__tests__/route-auth.test.ts --reporter=verbose` — all 9 tests pass, first publish test under 200ms.
