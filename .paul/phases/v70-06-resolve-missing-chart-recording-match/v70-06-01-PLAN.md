<objective>
## Goal
Take the Zod-validated `{ sections, tracks }` structure that v70-05's
`extractSetlistStructure` produces and **resolve** each track against the
library: annotate it with a fuzzy library chart match (id + confidence), flag
tracks with no confident chart match as `missingChart`, and attach
recording-match candidates (audio-typed library entries). This is a **pure
compute pass — NO Firestore writes**; it returns annotated proposals that
v70-07's commit step persists.

## Purpose
v70-06 is the middle of the v7.0 "feed a doc, get a setlist" pipeline:
v70-04 extracted text → v70-05 structured it → **v70-06 resolves it against
what the band already has** → v70-07 surfaces the gaps in an interview form and
commits. Without resolve, every doc-imported track would be an unbound,
chartless row. The propose-only design (Daniel-confirmed 2026-05-14) keeps
v70-06 a clean backend slice — no orphaned `recordings/*` docs if the user
abandons the import, and v70-07 owns all the actual writes.

## Output
- `src/lib/setlist-import/resolve.ts` — `resolveSetlistStructure(structure, opts?)`
  + the `ResolvedTrack` / `ResolvedStructure` types; a never-throws discriminated
  result. Library is injectable for tests.
- `POST /api/setlists/import/resolve` — JSON route, sibling of
  `import/extract-structure` + `import/extract-document` + `import/parse`.
- Unit tests (injected fixture library).
- `.paul/phases/v70-06-resolve-missing-chart-recording-match/v70-06-01-SUMMARY.md`.
</objective>

<acceptance_criteria>

## AC-1: Confident chart match annotates the track
```gherkin
Given a structure whose track title closely matches a chart-typed library
  entry (a PDF or image entry in library_index)
When resolveSetlistStructure runs
Then that track gains a `libraryMatch` of { fileId, name, confidence } where
  confidence is the normalized similarity score, and `missingChart` is false
```

## AC-2: No confident chart match flags missingChart
```gherkin
Given a track title with no chart-typed library entry above the similarity
  threshold
When resolveSetlistStructure runs
Then the track has no `libraryMatch`, `missingChart` is true, and the track is
  otherwise unchanged (so v70-07 can route it to /api/library/upload)
```

## AC-3: Audio-typed library entries become recording candidates
```gherkin
Given a track title that matches one or more audio-typed library entries
  (audio/* mimeType in library_index)
When resolveSetlistStructure runs
Then the track gains a `recordingCandidates` array of { fileId, name,
  confidence } sorted best-first; a track with no audio match has an empty
  array (or the field absent — pick one and be consistent)
```

## AC-4: Sections pass through untouched; the pass never throws
```gherkin
Given any valid { sections, tracks } structure (including an empty library)
When resolveSetlistStructure runs
Then `sections` is returned unchanged, every input track appears in the output
  exactly once preserving `order`, and the function never throws — a library
  fetch failure yields a typed { ok: false } result, not an exception
```

## AC-5: The route wraps the lib with validation + error mapping
```gherkin
Given an authenticated POST to /api/setlists/import/resolve with body
  { sections, tracks } (the v70-05 output shape)
When the request is processed
Then a successful resolve returns 200 { success: true, sections, tracks }
  with the annotated tracks; a malformed body returns 400; a library-fetch
  failure returns 502; and an unauthenticated request is rejected by
  createApiHandler before the lib is reached
```

<task type="auto">
  <name>Task 1: Create the resolve lib — library fuzzy-match, missing-chart, recording-match</name>
  <files>src/lib/setlist-import/resolve.ts</files>
  <action>
    Create the resolve lib, following extract-structure.ts's discriminated
    never-throws shape.

    1. Types:
       - `ResolvedTrack` = `SetlistTrack` (imported from `./extract-structure`)
         extended with:
         - `libraryMatch?: { fileId: string; name: string; confidence: number }`
         - `missingChart: boolean`
         - `recordingCandidates: { fileId: string; name: string; confidence: number }[]`
           (always present; empty array when no audio match)
       - `ResolvedStructure` = `{ sections: SetlistSection[]; tracks: ResolvedTrack[] }`
       - `ResolveResult` = `{ ok: true } & ResolvedStructure` |
         `{ ok: false; reason: 'library_unavailable'; message: string }`

    2. Matching algorithm — reuse the PROVEN approach already in
       `src/app/api/setlists/import/parse/route.ts` (do NOT refactor that route;
       just mirror its logic here):
       - Normalize a title with `toLowerCase().replace(/[^a-z0-9]/g, '')`.
       - For titles/names < 3 normalized chars: exact-match only (confidence 1.0).
       - Otherwise: `levenshteinDistance` (from `@/lib/string-utils`),
         `similarity = 1 - distance / Math.max(lenA, lenB)`.
       - Confidence threshold for a "confident match": `> 0.82` (same as
         import/parse). Pick the single best match above threshold.

    3. `resolveSetlistStructure(structure, opts?)`:
       - Signature: `(structure: SetlistStructure, opts?: { library?: LibraryFile[] })
         => Promise<ResolveResult>`. `opts.library` is injectable for tests;
         when absent, fetch via `getServerLibrary()` from `@/lib/server-library`.
       - Wrap the `getServerLibrary()` call in try/catch (and also treat its
         documented `{ files: [], ... }` empty-on-error return as a usable —
         not failing — empty library; only a thrown error → `{ ok: false,
         reason: 'library_unavailable' }`). The lib must NEVER throw.
       - Partition the library `files` by `mimeType`:
         - **chart entries**: `application/pdf` or `image/*` (PNG/JPEG/HEIC —
           v70-01 image charts). Used for `libraryMatch` / `missingChart`.
         - **audio entries**: `audio/*` mimeType. Used for `recordingCandidates`.
         - Verify the actual mimeType strings against real `library_index` data
           shape (LibraryFile.mimeType) during execution — partition on the
           `audio/` prefix vs `application/pdf`/`image/` rather than hardcoding
           an exhaustive list.
       - For each track (preserving `order`): compute the best chart match →
         set `libraryMatch` + `missingChart = !libraryMatch`; compute all audio
         matches above threshold, sorted by confidence desc → `recordingCandidates`.
       - Return `{ ok: true, sections: structure.sections, tracks: resolved }`.
         `sections` passes through untouched.

    Avoid: writing ANYTHING to Firestore — v70-06 is propose-only, v70-07
    commits (Daniel-confirmed 2026-05-14). Do NOT pre-create `recordings/*`
    docs. Do NOT refactor import/parse. Do NOT touch the library index / songs
    collection — read only, via getServerLibrary().
  </action>

  <done>AC-1 / AC-2 / AC-3 / AC-4 satisfied: each track is annotated with
