<objective>
## Goal
Rewrite MobileTabBar from a navigation-link bar into a live-resources action bar with three buttons: Search (popover), Setlist (navigate to current/upcoming setlist in perform mode), and Monitor (popover with QuickMonitorPanel).

## Purpose
During live services, musicians need instant access to song search, the current setlist, and monitor controls — not navigation to separate pages. The center Setlist button is the primary action (navigate to perform mode). Search and Monitor are popovers for quick access without leaving the current page.

## Output
Rewritten `src/components/nav/MobileTabBar.tsx`

## AC-1: Three-Button Action Bar Layout
```gherkin
Given a mobile viewport (below md breakpoint)
When the MobileTabBar renders
Then it shows exactly three buttons: Search (left), Setlist (center), Monitor (right)
And the Setlist button is slightly larger (w-7 h-7 icon) with subtle glow/elevation
And the bar uses material-thick backdrop with border-brand/10 (matching PerformanceToolbar)
```

## AC-2: Search Popover
```gherkin
Given the user taps the Search button
When the popover opens
Then it shows a text input for searching all songs in the library
And results appear as the user types (debounced, min 2 chars)
And tapping a result navigates to /perform/{fileId} to open that chart
And the popover closes after navigation
```

## AC-3: Setlist Navigation
```gherkin
Given the user taps the center Setlist button
When a setlist was opened this session (tracked in sessionStorage or zustand)
Then it navigates to /perform/setlist/{id} for that setlist
When no setlist was opened this session
Then it navigates to the setlist with the nearest future eventDate in perform mode
When no upcoming setlists exist
Then it navigates to /setlists as fallback
```

## AC-4: Monitor Popover
```gherkin
Given the user has monitor access and the congregation has monitor enabled
When the user taps the Monitor button
Then the QuickMonitorPanel opens in a popover (same as current behavior)
When the user does NOT have monitor access
Then the Monitor button is still shown but opens a "no access" message or is hidden
```

## AC-5: Hidden During PDF View
```gherkin
Given the user is viewing a PDF chart (pathname matches /perform/ with a file ID)
When MobileTabBar evaluates visibility
Then it is hidden (PerformanceToolbar takes over)
```

    Rewrite MobileTabBar with three action buttons replacing the current nav links:

    **Left — Search button:**
    - Icon: `Search` from lucide-react
    - Opens a Popover with a search input and results list
    - Use Firestore query on library_index collection (title field) for client-side search, OR use the existing `/api/library/search-content` endpoint via useContentSearch hook
    - Simpler approach: query library_index docs where title contains search term (client-side filter from a cached list)
    - Results show song title; tapping navigates to /perform/{fileId}
    - Close popover on navigation

    **Center — Setlist button:**
    - Icon: `ListMusic` from lucide-react
    - Slightly larger icon (w-7 h-7 vs w-6 h-6 for others)
    - Subtle glow: shadow-[0_0_12px_oklch(0.50_0.20_275/0.15)] and slight scale bump
    - On tap: navigate to current setlist in perform mode
    - Priority: (1) sessionStorage "lastOpenedSetlistId" if set, navigate to /perform/setlist/{id}
      (2) else query Firestore for nearest future eventDate public setlist, navigate to /perform/setlist/{id}
      (3) else fallback to /setlists
    - This is a navigation button (uses router.push), NOT a popover

    **Right — Monitor button:**
    - Icon: `Radio` from lucide-react
    - Opens Popover with QuickMonitorPanel (preserve existing behavior)
    - Show for all users; if no monitor access, either hide or show disabled state

    **Styling:**
    - Match PerformanceToolbar aesthetic: material-thick backdrop, border-t border-brand/10
    - Keep existing keyboard-open detection (hide when keyboard is visible)
    - Keep existing md:hidden (mobile only)
    - Add PDF view detection: hide when pathname matches /perform/ followed by a non-"setlist" segment (i.e., viewing a specific chart file)
    - Keep pb-safe for safe area inset

    **Session tracking for "last opened setlist":**
    - Use sessionStorage key "lastOpenedSetlistId"
    - Set this value when navigating TO a setlist perform page (in the Setlist button handler or in the setlist perform page itself)
    - Read it when determining where the Setlist button navigates

    **Nearest-future-setlist query:**
    - Query Firestore setlists collection where eventDate >= now, orderBy eventDate asc, limit 1
    - Cache the result briefly or query on mount
    - If no results, fallback to /setlists

    Avoid:
    - Do NOT import heavy dependencies — keep the component lightweight
    - Do NOT change how QuickMonitorPanel works internally
    - Do NOT use useContentSearch hook (it searches content/chords, not song titles) — use a simpler Firestore title search on library_index
