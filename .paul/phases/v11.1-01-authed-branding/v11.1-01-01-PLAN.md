<objective>
## Goal
Make the **authenticated** top-nav (DesktopHeader + MobileHeader) resolve its wordmark + logo from the **host org** instead of hardcoding `/logo.jpg` + the "Central Reform Congregation" alt + relying on the client congregation store's CRC `DEFAULT_CONFIG` fallback. On brotherslazaroff.live the authed nav must read "Brothers Lazaroff" with a circular **BL monogram** badge (its `logoUrl` is `""`); on centralreform.live the nav output must be **byte-identical** to today ("CRC Music" + `/logo.jpg`).

## Purpose
v11-04-02 made the public/perform + metadata surfaces org-aware via the server-side `getOrgBranding` seam, but the authed nav was never converted — it's the last consumer-visible CRC-branding leak on the 2nd live tenant. This is the P0 of v11.1: the band leader / members on broslaz currently see another tenant's identity on every authed page. (Tenancy model: the landing-page host determines the experience — branding included.)

## Output
- `getOrgBranding` gains a `logoUrl` field (crc `/logo.jpg`, broslaz `""`).
- The `(main)` layout resolves the host org from the `x-org-id` header (same seam as the root layout) and passes server-derived `serverOrgShortName` + `serverLogoUrl` down through `AppNavigation` to both headers — flash-free, SSR-correct.
- A new `OrgLogo` component renders the logo image when a `logoUrl` exists, else a circular initials monogram in the brand color (theme-token driven → indigo on CRC, navy on broslaz).
- Both nav headers use the server branding for wordmark text + logo + alt text.
- Unit tests for `OrgLogo` (image vs monogram) and the new `branding.logoUrl` values. CRC byte-identical asserted.
</objective>
