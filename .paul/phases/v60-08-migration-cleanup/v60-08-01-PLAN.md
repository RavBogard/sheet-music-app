<objective>
## Goal
Close the v50-05 → v6.0 migration by deleting the embedded-array reader fallback (server + client) and dropping the `tracks` field from `setlistSchema`/`setlistConverter`. After this plan, top-level `tracks/{id}` is the single source of truth — no code path reads or accepts an embedded `tracks[]` on `setlists/{id}` documents.

## Purpose
Removes the last load-bearing dual-read path. Every writer (W1–W7) was decommissioned in v60-07; every reader was migrated through `getTracksForSetlist` / `getTracksForSetlistClient` / `fetchTracksForSetlistClient` in v60-04/05/06. The fallback branches now exist only to support pre-backfill setlists. After v60-06-08 `--apply` lands on the 15-setlist scope, the fallback is dead weight — and the schema's `tracks: z.array(...)` is the last "embedded tracks are legal" signal anywhere in the codebase. Keeping it invites regressions where a future writer accidentally re-introduces the legacy field.

## Output
- `src/lib/server-tracks.ts`: `getTracksForSetlist` becomes single-branch (always `fetchTopLevelTracks`). `buildLocalTracks` + `toMs` helpers deleted.
- `src/lib/client-tracks.ts`: `getTracksForSetlistClient` collapses to 2 branches (Dexie or empty). `fetchTracksForSetlistClient` collapses to single-branch (always top-level fetch).
- `src/types/schemas.ts`: `tracks: z.array(setlistTrackSchema)…` removed from `setlistSchema`.
- Affected emulator + unit tests updated to drop unhydrated-fallback assertions.
- Net delta: expected ~–60 LOC source / ~–40 LOC test.
</objective>
