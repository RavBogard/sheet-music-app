<acceptance_criteria>

## AC-1: Content Hash Determinism
```gherkin
Given a PrintRequest with specific tracks and metadata
When computeContentHash is called (indirectly via generatePrintPdf)
Then identical requests produce identical hashes
And different transpositions/tracks produce different hashes
```

## AC-2: Service Flow Item Handling
```gherkin
Given a PrintRequest containing non-song tracks (headers, readings, transitions)
When the pipeline processes tracks
Then non-song tracks without fileId are skipped (not fetched)
And only song tracks with fileId contribute to appendedTracks count
```

## AC-3: Error Resilience
```gherkin
Given a PrintRequest where one track's file fetch fails
When generatePrintPdf processes the request
Then the failing track is skipped
And other tracks are still processed successfully
And stats reflect the correct counts
```

## AC-4: Transposition Integration
```gherkin
Given a PrintRequest with transposition != 0 on some tracks
When generatePrintPdf processes the request
Then chord extraction and transposition modules are loaded
And transposed tracks increment stats.transposedTracks
```

## AC-5: Cover Page Content
```gherkin
Given a PrintRequest with tracks including keys, leads, and notes
When buildCoverPage is called
Then a cover page is added as the first page
And track metadata (title, key, lead) appears on the cover
```
