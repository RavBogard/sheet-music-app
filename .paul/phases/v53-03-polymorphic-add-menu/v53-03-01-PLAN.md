<objective>

## Goal

Replace the single-purpose `AddRowPlaceholder` "Add a song or section…" trigger with the old-editor polymorphic Add menu (commit `d8c0442`'s `AddBar.tsx`) ported into the current TanStack/cmdk/Radix substrate. Daniel selected **Option B (split-button)** at /paul:discuss-phase: a primary indigo **"+ Song"** CTA opens the v53-02-substrate cmdk picker (Recent / Library / Custom three-CommandGroup pattern), and a sibling chevron Popover reveals 5 colored tiles (Section Header / Reading / Prayer / Transition / Stage Note) for one-tap insertion of non-song tracks.

## Purpose

Fixes the single biggest editor regret Daniel surfaced post-v50-02 amputation: *"the old 'add' menu was MUCH better."* (project memory). The old AddBar's colored-icon vocabulary + always-visible non-song affordances are the discoverability cue that sticky memory and the v50-05 spreadsheet substrate stripped away. Restores muscle memory + scanability for the weekly worship cycle without abandoning the spreadsheet bones. Closes the third of the three Daniel-stated v5.3 high-friction surfaces (chart-bind ✅ v53-02 / chart-cell discoverability ✅ v53-02 / Add menu — this plan).

## Output

- New `src/components/setlist/grid/AddBar.tsx` (~120-160 LOC): split-button shell with primary "+ Song" CTA + chevron `TouchOrPopover` containing a 5-tile grid; uses `TrackTypeTile` inline component for the tiles.
- Refactored `src/components/setlist/grid/AddRowPlaceholder.tsx` (-25 / +5 LOC net): becomes a thin focus-on-search-only popover content used as the primary CTA's picker (Recent / Library / Custom — three CommandGroups; Recent + Library mirror v53-02 ChartBindPopover verbatim, Custom keeps the existing `__create__${filter}` sentinel). Renamed export `AddRowPlaceholder` → `AddSongPicker` is OUT OF SCOPE — keep the existing name + signature so SetlistGrid integration stays untouched.
- `src/components/setlist/grid/SetlistGrid.tsx`: replace `<AddRowPlaceholder ... />` mount with `<AddBar ... />`; new `handleAddTrackOfType(type: TrackType)` handler routing through the same `applyEdit('set', 'tracks', ...)` single-write path that `handlePickSong` + `handleCreateFreeText` already use.
- New `src/components/setlist/grid/__tests__/AddBar.test.tsx` (~120-160 LOC, 8-12 cases): split-button structure / primary CTA opens picker / chevron opens 5-tile grid / tile click adds row of correct type / icon-color tokens present / long-press disambiguation (chevron + primary CTA `onContextMenu` neutralized) / keyboard navigation / jest-axe ZERO violations.
- Extended `src/components/setlist/grid/__tests__/AddRowPlaceholder.test.tsx` (+30-50 LOC, +2-3 cases): Recent CommandGroup renders above Library when songs have `recent[].performedAt` (mirrors v53-02 ChartBindPopover.test pattern); existing test cases for free-text + library pick remain green.
