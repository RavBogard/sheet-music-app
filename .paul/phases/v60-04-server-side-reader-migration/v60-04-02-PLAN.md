<objective>
## Goal
Migrate the two print route handlers (`/api/setlist/print/public` and `/api/setlist/print/personal`) to read tracks via the shared `getTracksForSetlist` helper introduced in v60-04-01. Two file-bundled call-site swaps; single combined commit; identical drop-in pattern to the publish-route migration.

## Purpose
The print routes are the second-loudest leaked surface after publish: they generate the PDF packets that musicians download from email links (public) and from in-app personal-transposition flows (personal). Both read `setlist.tracks || []` blindly — which has been stale for any hydrated setlist since v50-05. Migrating both closes the print-packet correctness gap before Daniel's band-onboarding cycle so musicians always see the live track list, not the stale embedded array.

## Output
- `print/public/route.ts:51` reader migrated through `getTracksForSetlist`.
- `print/personal/route.ts:49` reader migrated through `getTracksForSetlist`.
- Single combined commit per v60-01/02/03/v60-04-01 precedent.
- Existing `SetlistTrack[]` type cast preserved at each call site so downstream `.map(t => ({ ... }))` mappers (PrintRequest construction) keep their narrow shape access without widening.
</objective>
