<objective>
## Goal
Decommission the explicit dual-write bridge `mirrorTracksToTopLevel` in `src/hooks/use-add-to-setlist.ts`. Convert the three write paths (`addToSetlist`, `addDirectlyToSetlist`, the embedded undo handler) from "embedded-array write + top-level mirror" to **engine-path-only writes**: per-track `applyEdit('set', 'tracks', ...)` for new tracks, `applyEdit('delete', 'tracks', id)` for undo, and `applyEdit('update', 'setlists', { trackCount })` for parent-doc denormalization. The embedded `setlist.tracks[]` array is no longer touched by this hook.

## Purpose
v60-07 strips the embedded-array writer side of the v5.0 dual-write era. The audit (RESEARCH/audit-writes.md) identifies 27 production writers; W24 (`mirrorTracksToTopLevel`) is THE explicit "dual-write bridge" called out in the v5.4 close-notes for v6.0 decommissioning. W26 (`addToSetlist`) and W27 (`addDirectlyToSetlist`) are the only composite writers in the audit — they're the ONLY writers that touch BOTH sources in one logical operation. Removing this bridge:
1. Eliminates the most explicit dual-write surface — no more "write to embedded AND mirror to top-level" code path.
2. Establishes the v60-07 writer-removal pattern that subsequent plans (setlist-firebase.ts updateSetlist + 11 API routes) follow: engine-path applyEdit for tracks, denormalization-only updates on the parent.
3. Removes a latent failure-class: today, if `updateSetlist({tracks: updatedTracks})` succeeds but `mirrorTracksToTopLevel` fails, the embedded array has new tracks but top-level doesn't — the editor (which reads top-level for hydrated setlists) would show stale data. The unified engine-path write removes this skew.

After this plan, the library "Add to setlist" flow writes EXCLUSIVELY to top-level `tracks/{id}` + denormalized parent-doc fields. Reader fallback (server-tracks.ts + client-tracks.ts buildLocalTracks branch) still handles legacy unhydrated setlists from the dashboard / matrix / etc.

## Output
- `mirrorTracksToTopLevel` helper function REMOVED from src/hooks/use-add-to-setlist.ts (lines 22-51 today).
- `addToSetlist` (lines 146-242): replaces the `setlistService.updateSetlist({tracks, trackCount})` + `mirrorTracksToTopLevel` pair with:
  - Per-track `applyEdit('set', 'tracks', {...})` (Promise.all over newTracks)
  - One `setlistService.updateSetlist({trackCount: setlist.tracks.length + newTracks.length, hydrated: true})` parent-doc denorm-only update (no `tracks` field)
- `addDirectlyToSetlist` (lines 245-301): same refactor as `addToSetlist`.
- Undo handler inside `addToSetlist` (lines 215-238): rewritten to `applyEdit('delete', 'tracks', trackId)` per `undoTrackIds` + parent-doc trackCount decrement. Removes the `subscribeToSetlist` + `filter` + embedded-array write cycle.
- Plan SUMMARY at `.paul/phases/v60-07-writer-removal-strip/v60-07-01-SUMMARY.md`.
