<objective>
## Goal
Build the new app-native spreadsheet editor (`SetlistGrid`) end-to-end as a self-contained component plus boot the v50-03 sync engine into the production app shell — without yet swapping the route mount or deleting legacy code. By plan close, the new editor is fully functional in isolation (read, cell-edit, dropdown, drag-reorder, add/delete, sync indicator, empty state) and proven by vitest, but the live route still renders `SetlistEditorV2`. Cutover (route swap + legacy deletion) is plan v50-05-02. Touch/iPad polish, mobile-only flow, multi-select, and binding-AA verification are plan v50-05-03.

## Purpose
Phase v50-05 is the largest cut of the v5.0 milestone (~−8,400 LOC editor surface replaced by a spreadsheet-shaped editor on TanStack Table v8 + @dnd-kit + Radix Popover + cmdk, wired to v50-03 sync engine + v50-04 sticky-memory helpers). Splitting build-then-cutover into two plans keeps the working tree compilable at every plan boundary and lets vitest prove the new editor before we delete the old one. ARCHITECTURE.md §6 is the binding spec; this plan implements §6.2–§6.5, §6.8, §6.10 desktop-first.

## Output
- New `src/components/setlist/grid/*` component tree (grid + cells + top bar + sync indicator + empty state + add-row placeholder)
- New `src/hooks/use-grid-keyboard.ts` for Tab/Enter/Esc/Arrow navigation
- New `src/lib/sync/init.ts` that constructs `SyncEngine` against the production `FirestoreAdapter` and wires it into `useSyncStatus`
- Engine booted from `src/app/(main)/layout.tsx` on auth-ready (cleaned up on unmount)
- Tests: 5 new vitest files covering read render, sync indicator states, empty state CTAs, cell-edit commits, and drag/add/delete
- `.paul/phases/v50-05-spreadsheet-editor/v50-05-01-SUMMARY.md` on UNIFY

## AC-1: Grid renders tracks from Dexie via live query
```gherkin
Given a setlist `set-1` in Dexie with 3 tracks (orders 0, 1, 2; titles "Adon Olam", "Lecha Dodi", "Aleinu")
When `<SetlistGrid setlistId="set-1" />` mounts
Then exactly 3 rows render in the order 0→1→2 with correct titles
And when a 4th track is inserted directly into Dexie outside the component
Then the new row appears within one tick without a remount (live query reactivity)
```

## AC-2: Sync indicator reflects all six FSM states with aria-live announcements
```gherkin
Given the v50-03 sync FSM in a given state and the SyncIndicator mounted
When state = `idle`           Then UI shows "✓ Saved"        (green dot)  + announces "Saved"
When state = `editing`        Then UI shows "◌ Editing…"     (muted dot)  + announces "Editing"
When state = `saving`         Then UI shows "◑ Saving…"      (indigo dot) + announces "Saving"
When state = `conflict`       Then UI shows "! Conflict — review" (red dot) + announces "Conflict, please review"
When state = `failed`         Then UI shows "⊘ Failed — retry"   (red dot) + announces "Save failed"
When state = `offline` AND queued = N  Then UI shows "⊙ Offline — N queued" (amber dot) + announces "Offline, N changes queued"
And every state's foreground/background contrast meets WCAG AA (≥4.5:1 body, ≥3:1 large/UI)
```

## AC-3: Empty state primary CTA clones most-recent prior setlist
```gherkin
Given a brand-new setlist (zero tracks) for an authenticated user with at least one prior setlist
When the user clicks the "Make next week's" CTA
Then a clone of the most-recent prior setlist's tracks is created via applyEdit({op:'set'}) per track
And the new setlist's name is set to "{templateName} · {next-friday-date}"
And the EmptyState dismisses; SetlistGrid re-renders with the cloned rows
```

## AC-4: Text-cell edit commits via applyEdit; Esc discards
```gherkin
Given a Title cell containing "Adon Olam" rendered by SetlistGrid
When the user double-clicks the cell, types " Slow", and presses Tab
Then `applyEdit({op:'update', collection:'tracks', docId, patch:{title:'Adon Olam Slow'}})` is called exactly once
And focus advances to the next editable cell in the row (Type column wraps; otherwise next column)

Given a Title cell in edit mode with pending unsaved input "Adon X"
When the user presses Esc
Then the cell exits edit mode showing the original "Adon Olam" (no commit)
And applyEdit is NOT called
```

## AC-5: Dropdown cell (Key/Lead/Type) commits + propagates sticky memory
```gherkin
Given a Key cell with value "Dm" on a track whose `songId` is "adon-olam"
When the user clicks the cell, types "G", and presses Enter to select the top cmdk match
Then `applyEdit({op:'update', collection:'tracks', docId, patch:{key:'G'}})` is called
And `propagateTrackEditToSong("adon-olam", {key:'G'}, setlistId)` is also called (debounced; default 1000ms)
And the cmdk popover closes; focus returns to the cell in selected (not edit) state
```

## AC-6: Drag-reorder commits new ordering via per-row applyEdit
```gherkin
Given a setlist with rows [A:order=0, B:order=1, C:order=2]
When the user grabs row C's drag handle and drops it above row A
Then the visual order becomes [C, A, B] in place
And applyEdit is called with `{op:'update', collection:'tracks', docId:C.id, patch:{order:0}}` (or equivalent renumbering)
And the same for A→1, B→2 so the ordering invariant `order ASC` reflects the new sequence
And keyboard equivalent: Space on the drag handle enters keyboard-drag mode, Arrow Up/Down moves the row, Enter commits, Esc cancels
```

## AC-7: Add-row from library auto-seeds defaults; delete-row honors confirmation rules
```gherkin
Given a song "Adon Olam" in Dexie with `defaults: { key: 'Dm', lead: 'Rabbi D', bpm: 120 }`
When the user clicks the AddRowPlaceholder, types "Ado" in the Title cmdk filter, and selects "Adon Olam"
Then `applyEdit({op:'set', collection:'tracks', doc:{id, setlistId, songId:'adon-olam', order:max+1, title:'Adon Olam'}})` is called
And `seedTrackFromSong("adon-olam")` is invoked
And the returned defaults are applied via a follow-up `applyEdit({op:'update', collection:'tracks', docId, patch:{key:'Dm', leadMusician:'Rabbi D', bpm:120}})`
And the new row's Title cell auto-focuses

Given a row with `title: "Aleinu"` and the user right-clicks the drag handle
When they select "Delete row" and confirm in the modal
Then `applyEdit({op:'delete', collection:'tracks', docId})` is called

Given an empty row (no title) and the user presses Backspace with the row selected
Then `applyEdit({op:'delete', collection:'tracks', docId})` is called immediately (no confirmation)
```
