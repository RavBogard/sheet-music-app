Land the third (and last) v50-05 polish plan: mobile stacked-card render path below 768px (parallel to the table; not a Tailwind responsive trick), Undo via zustand temporal middleware (zundo) intercepting before applyEdit so the sync engine carries inverses to Firestore on round-trip, and WCAG AA audit (jest-axe automated + manual Lighthouse) + any focus-trap / keyboard-nav / contrast fixes surfaced.

ARCHITECTURE.md §6.11 (mobile flow) + §6.13 (WCAG AA) + Undo. The existing TanStack Table layout breaks ~640px — phones become unusable. Undo is a non-negotiable spreadsheet-shaped expectation: users edit, fat-finger something, hit Cmd-Z, expect immediate revert. WCAG AA is the band-onboarding accessibility floor. Closing v50-05-05 closes phase v50-05 (Spreadsheet editor UI cutover) — phase complete after this plan.

    ```bash
    npm install zundo --save-exact
    ```

    Create `src/lib/local/undo-store.ts`:
    - zustand store with `temporal` middleware from zundo.
    - Shape: `{ entries: UndoEntry[], pushEntry: (entry: UndoEntry) => void, clear: () => void }`.
    - `UndoEntry` = `{ op: 'update' | 'set' | 'delete', collection: 'tracks' | 'songs' | 'setlists', docId: string, prevDoc: LocalTrack | LocalSong | LocalSetlist | undefined, newDoc: ... | undefined, ts: number }`.
    - Cap entries at 50 (FIFO drop oldest in `pushEntry`).
    - Coalesce burst edits per cell: expose `pushEntryDebounced(entry, key, ms)` — same key (e.g. `${docId}:${field}`) within `ms` (default 500ms) collapses to one entry whose `prevDoc` is the FIRST captured before the burst, and `newDoc` is the LATEST. Implementation: per-key Map of pending timers + first-captured prevDoc; on timer fire, finalize the entry and push.
    - The `temporal` middleware itself doesn't drive Cmd-Z — it gives us `useStore.temporal.getState()` access to undo/redo. We DON'T use the temporal middleware's automatic snapshotting. Instead, our store manually pushes entries via `pushEntry` (since we want fine-grained control over WHAT becomes an undo unit — coalescing per cell). Reconsider: zundo's temporal is a wrapper that hooks state setters; for our manual-push model, plain zustand without temporal might suffice. **Decision recorded inline:** use plain zustand + a pure-data entries array; zundo wrapper not needed. Simpler, less indirection.
    - Selectors: `getUndoStack(): UndoEntry[]`, `getRedoStack(): UndoEntry[]`, `popUndo(): UndoEntry | undefined`, `popRedo(): UndoEntry | undefined`. Store maintains both stacks; pushing a new entry clears redo stack.
    - The store is ephemeral — no persistence (zustand's default).

    Update `src/lib/local/write.ts`:
    - Read the prevDoc from Dexie BEFORE the applyEdit transaction.
    - After successful applyEdit, push a snapshot to undo-store via `pushEntryDebounced` keyed on `${docId}:burst` (or `${docId}:${field}` if op=update with a single field). For 'set' / 'delete' ops, push immediately (these aren't burst-coalesced).
    - **Critical:** undo-store push happens AFTER applyEdit succeeds, NOT before. If applyEdit fails, no undo entry. This avoids the "user undoes a thing that didn't actually persist" surprise.
    - Provide a `withoutUndo` flag in applyEdit options for engine-internal calls (e.g. order cascade in Duplicate row should be ONE undo entry, not N — so the cascade calls pass withoutUndo:true and the Duplicate handler manually pushes one combined entry).
    - Backward-compat: applyEdit's existing signature stays; new behavior is additive (snapshot read before, push after). Existing callers gain undo support automatically.
    - Avoid: making applyEdit async-await on the undo push (it's fire-and-forget — shouldn't block user-perceived save latency).

    Update `src/components/setlist/grid/SetlistGrid.tsx`:

      - update → applyEdit('update', collection, docId, prevDoc fields)

    - For Duplicate row + bulk-set + bulk-delete: combine into ONE undo entry (the handler reads all prevDocs, fires applyEdit-cascade with withoutUndo:true, then pushes one composite entry). Composite entry's inverse is N parallel applyEdit calls.
