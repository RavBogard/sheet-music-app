<objective>
## Goal
Build the document text-extraction foundation for v7.0's doc-driven setlist
creation: a server-side lib that turns an uploaded `.docx` / `.pdf` / `.txt` file
into raw text, and an API route that wraps it. NO UI — this is a foundation slice
the later phases (v70-05 Gemini extraction, v70-07 commit) build on.

## Purpose
v7.0's theme is "feed a doc, get a setlist." The pipeline is
`v70-04 extract text → v70-05 Gemini structured extraction → v70-06 resolve →
v70-07 interview form + commit`. This plan is step 1: get the raw text out of
whatever document Daniel feeds (the May 15 Shir Shabbat `.docx` is the v70-05
canary). v70-05 cannot start without reliable text extraction.

## Output
- `mammoth` added as a dependency (`.docx` → text).
- `src/lib/setlist-import/extract-document.ts` — `extractDocumentText(buffer, opts)`
  dispatching by format: `.docx` via `mammoth`, `.pdf` via the existing
  `pdfjs-dist` server-side pattern, `.txt` trivially. Returns a discriminated
  result (`{ ok: true, text, format, charCount }` | `{ ok: false, reason, message }`).
- `POST /api/setlists/import/extract-document` — multipart upload → extracted text.
- Unit + route tests.
</objective>

<acceptance_criteria>

## AC-1: .txt and .docx extraction
```gherkin
Given a .txt file buffer
When extractDocumentText is called with it
Then it returns { ok: true, format: 'txt', text, charCount } with the file's UTF-8 text

Given a .docx file buffer
When extractDocumentText is called with it
Then it returns { ok: true, format: 'docx', text, charCount } with the document's
    raw text content (paragraph text, via mammoth.extractRawText)
```

## AC-2: .pdf extraction
```gherkin
Given a text-based .pdf file buffer
When extractDocumentText is called with it
Then it returns { ok: true, format: 'pdf', text, charCount } with the concatenated
    text content of all pages
And extraction runs server-side with no worker / no DOM dependency
    (the pdfjs-dist legacy build pattern already used by pdf-chord-extractor.ts)
```

## AC-3: Unsupported / unreadable input is a clean failure, not a crash
```gherkin
Given a file whose format is not .docx / .pdf / .txt (e.g. .png, .xlsx)
When extractDocumentText is called with it
Then it returns { ok: false, reason: 'unsupported_format', message } — it does NOT throw

Given a corrupt or empty file of a supported format
When extractDocumentText is called with it
Then it returns { ok: false, reason: 'extraction_failed' | 'empty', message } — it does NOT throw
```

## AC-4: The route wraps the lib with upload validation
```gherkin
Given an authenticated request with a multipart 'file' field
When POST /api/setlists/import/extract-document is called
Then a supported file returns 200 { success: true, text, format, fileName, charCount }
And an unsupported format or oversized file returns 400 with an error message
And a missing file returns 400
```

  <name>Task 1: Add mammoth + build the extract-document lib</name>
  <files>package.json, src/lib/setlist-import/extract-document.ts</files>
  <action>
    Add the `mammoth` dependency: `npm install mammoth` (it ships its own types).

    Create `src/lib/setlist-import/extract-document.ts`:
      - Export a discriminated result type, e.g.
        `type ExtractResult = { ok: true; text: string; format: 'docx'|'pdf'|'txt'; charCount: number } | { ok: false; reason: 'unsupported_format'|'extraction_failed'|'empty'; message: string }`.
      - Export `detectDocumentFormat(fileName: string, mimeType?: string): 'docx'|'pdf'|'txt'|null`
        — mimeType first (application/vnd.openxmlformats-officedocument.wordprocessingml.document
        → docx, application/pdf → pdf, text/plain → txt), extension fallback
        (`.docx` / `.pdf` / `.txt`). Returns null for anything else.
      - Export `async extractDocumentText(buffer: Buffer, opts: { fileName: string; mimeType?: string }): Promise<ExtractResult>`:
        - Resolve format via detectDocumentFormat; null → `{ ok: false, reason: 'unsupported_format' }`.
        - `.txt` → `buffer.toString('utf-8')`.
        - `.docx` → `mammoth.extractRawText({ buffer })` — use the `.value` (raw
          paragraph text); mammoth `.messages` can be ignored for raw-text mode.
        - `.pdf` → reuse the EXISTING server-side pdfjs pattern from
          `src/lib/pdf-chord-extractor.ts` (dynamic `import('pdfjs-dist/legacy/build/pdf.mjs')`,
          `GlobalWorkerOptions.workerSrc = ''`, `getDocument({ data: new Uint8Array(buffer) })`,
          loop pages → `page.getTextContent()` → join the `item.str` values; insert
          `\n` between pages). If `pdf-chord-extractor.ts` already exposes a reusable
          loader or a "get all text" helper, prefer calling/exporting that over
          duplicating the loader — but keep the change to pdf-chord-extractor.ts
          minimal (extract-and-reuse only, no behavior change to chord extraction).
        - Wrap mammoth + pdfjs calls in try/catch → `{ ok: false, reason: 'extraction_failed', message }`
          (never throw — AC-3).
        - After a successful extraction, if the trimmed text is empty →
          `{ ok: false, reason: 'empty', message: 'No text found in document' }`.
        - On success → `{ ok: true, text, format, charCount: text.length }`.

    Avoid: OCR / image handling (v7.1 — out of scope); bundling pdfjs into client
    code (the dynamic `import()` of the legacy build is what keeps it server-only —
    follow pdf-chord-extractor.ts exactly); throwing from extractDocumentText.
  </action>
  <verify>`npx next build` compiles. `npx vitest run src/lib/setlist-import/` once Task 3's tests exist (or a quick `node -e` smoke that imports the lib).</verify>
  <done>AC-1 + AC-2 + AC-3 satisfied: extractDocumentText handles .docx/.pdf/.txt and returns a clean discriminated failure for unsupported/corrupt/empty input.</done>
