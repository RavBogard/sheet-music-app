# Phase v11.4-03 Plan 01: Remembered ad-hoc recipients — MCP contacts (D8 item 3) Summary

**Leaders can now remember an ad-hoc recipient (a person with no app account — name + email/phone) as a reusable, org-scoped contact via MCP, and see their saved contacts surfaced in preview_publish — closing D8 item 3 on the authoring surface where Daniel actually works. Sending to a contact reuses the existing recipients[] path (no publish-signature change). All gates green; contacts rules deployed to prod.**

## Accomplishments

- **`contacts` collection + rules:** new org-scoped collection; `firestore.rules` `/contacts` block is leader/admin READ (org-isolated via `orgReadOk` — a leader address book, NOT member-facing) + leader create/update/delete with `orgCreateOk`/`orgUpdateOk`. Deployed to prod (`firebase deploy --only firestore:rules`, compiled + released). 6-case emulator rules test proves the wall.
- **MCP tools** (`contacts.ts`): `list_contacts` / `create_contact` / `delete_contact`, each leader-gated (`assertEditor`), org-scoped (`orgFrom(extra)`). create validates name + at least one of email/phone and dedupes by email (in-memory scan — no composite index); delete has a cross-org `contact_not_found` wall. Registered in `index.ts` with agent-facing descriptions that tell the model this is for remembering an ad-hoc recipient and that sending reuses `recipients[]`.
- **preview_publish.savedContacts[]:** the org's saved contacts surfaced (informational; recommendation gate untouched) so the agent can offer them when previewing a publish.
- **`Contact` type** in `models.ts`.

## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| MCP contacts, not browser UI | The browser PublishDialog is orphaned (mounted nowhere); MCP is Daniel's authoring surface (ratified 2026-06-11) | Value lands where Daniel works; no investment in dead UI |
| New `contacts` collection | Ad-hoc recipients are non-account humans (no uid) — shoehorning into users/roster would create phantom accounts | Clean separation; naturally org-scoped |
| No `contactIds` on publish/preview | Keeps the load-bearing publish signature + v11-06-02 no-arg-injection seam untouched; sending already works via email-only recipients[] | Minimal surface; preview SURFACES contacts, agent passes them as recipients |
| Email dedupe via in-memory scan | Address books are small; avoids a composite (orgId,emailLower) index + an extra stored field | No index, no schema cruft |
| contacts read = leader/admin only | A contact list is a leader's private address book, not member-facing content (unlike recordings) | err-public still holds (it governs chart/setlist data, not leader address books) |
