# SUMMARY — v11.3-01-01 (BUG-5: anon chart deep-link serving)

## What was built
Reworked `src/app/api/library/file/[id]/route.ts` from a default-auth, `db-*`-only legacy
route into a **public chart-byte proxy mirroring `/api/drive/file/[fileId]`**:
- `createApiHandler(..., { requireAuth: false })` — removes the `withAuth` gate that 401'd
  anon with `missing_bearer` before any id handling.
- `isTrusted = ctx.auth || hasBrowserFetchMetadata(req) || valid crl_live_ bearer` — byte-for-byte
  the sibling's defense-in-depth gate (a bare curl with none of these is still blocked).
- `chart` rate-limit tier (600/min, IP-keyed) instead of `api` (60/min) — NAT-fleet-safe.
- Existence check BEFORE the auth gate → bogus id 404s `file_not_found` (no misleading 401).
- Serves by id shape: `db-*` → `digitized_charts` xmlContent (now anon-public, with the
  legacy `Content-Disposition` filename); else (`upload-*`/UUID/Drive) → shared `fetchFileById`
  (Storage→Drive) with public CDN cache headers + `X-Served-From`.
- Added regression test `route.test.ts` (6 cases).

## Verify-first finding (Task 1) — severity refined, fix unchanged
- **Root cause (code + prod-corroborated):** the route used `createApiHandler` with the DEFAULT
  auth gate, so anon → 401 `missing_bearer` (`api-auth.ts:74`) for ALL ids, even `db-*`. The
  working sibling `/api/drive/file` is `requireAuth:false` + `isTrusted` + `chart` + `fetchFileById`.
- **Prod probe (anon, fake ids):** `/api/library/file/upload-*` → 401 missing_bearer; `/api/library/file/db-*`
  → 401; `/api/drive/file/<fake>` (+/− Sec-Fetch) → 404 (existence-before-gate). Confirms the gate diff.
- **Client trace:** ALL Perform-render paths (TextScoreViewer, PDFViewer/PDFOverlay, AudioViewer,
  use-offline, prefetch, cache-utils) fetch via `/api/drive/file` unconditionally. `parseFileId`
  (utils.ts:41) routes `db-*` → `/api/library/file`, `upload-*` → `/api/drive/file` — used only by
  MobileRowCard "Open chart in new tab" + admin pdf-health-scanner. **No app path sends `upload-*` to
  the legacy route** → no client edit needed (utils.ts untouched).
- **Severity:** the report's `/api/library/file/upload-*` 401 was a synthetic `browser_evaluate`
  endpoint probe. The BUG-5 P1 "blank cold-device Perform render" escalation is **NOT real** (Perform
  uses `/api/drive/file`, anon-OK). The genuine user-facing defect is anon **"Open chart in new tab"
  on legacy `db-*` MusicXML** (401 pre-fix) + the oracle-contradiction that the route is named anon-✅
  but gated. BUG-5 → **P2**. The fix is unchanged and closes both.
