<objective>
## Goal
Stabilize the v50-06 substrate before the reconciliation modal lands in v50-06-02:
1. Root-cause and fix the cross-tab-lock test flake — the same lock primitive
   coordinates the reconciliation modal across tabs, so an intermittent failure
   here would translate to intermittent conflict-resolution behavior in prod.
2. Thread honest `expectedUpdatedAt` through the track update path (deferred from
   v50-05-01) so the production adapter's existing precondition check actually
   fires when two writers race the same doc — i.e. surface `VersionMismatchError`
   end-to-end so v50-06-02 has something real to react to.
3. Prove substrate readiness with a two-writer integration test driving the
   property-failures harness — concurrent updates to one doc must produce exactly
   one `VersionMismatchError` and the engine must transition to the conflict
   state without losing the local edit.

## Purpose
v50-06-02 (reconciliation modal — "Remote changed: keep mine / take theirs")
needs three things to exist before any UI work makes sense:
- A reliably exclusive cross-tab leader (so two tabs aren't both deciding the
  modal's state).
- An honest expected-version on every update so conflicts get *detected* (today
  the editor passes `expectedUpdatedAt: undefined`, so the adapter's
  precondition is dormant and conflicts silently last-write-win).
- A working `VersionMismatchError → 'awaiting-resolution'` event flow on the
  engine so the modal can subscribe to the state and `engine.resolveConflict()`
  can complete the loop.

This plan stops short of the modal itself. It hardens the floor.

## Output
- Cross-tab-lock root cause documented; test deflaked with a stress loop that
  catches regressions deterministically.
- `FirestoreAdapter.commitOutboxRow` returns the new server `updatedAt` on
  success; engine writes it back to the local row inside the same "delete the
  outbox row" transaction, so the next user edit picks up the fresh version.
- SetlistGrid track-update call sites pass `expectedUpdatedAt: track.updatedAt`
  via `applyEdit`.
- Two-writer property/integration test asserts conflict detection.
- SUMMARY.md at `.paul/phases/v50-06-concurrent-edit-safety/v50-06-01-SUMMARY.md`.
</objective>

        still fires; on success, capture the snapshot's NEW updatedAt by
        re-reading after commit (NOT inside the tx — `runTransaction` is

        return { updatedAt: (snapAfter.data()?.updatedAt as Timestamp)?.toMillis() }`.
        This is one extra read per write — acceptable; v50-06-02 reconciliation
        depends on this freshness. If profiling later flags it, the adapter
        can be refactored to compute the server timestamp client-side via
        `Timestamp.now().toMillis()` before the write and pass that through
        explicitly, but that diverges from server-authoritative.
      - For `'delete'`: return `{}`.
      - All return-paths inside `try`. Exception paths re-throw as before

    Step 2c — engine writes back local row.updatedAt on success:
    - In `src/lib/sync/engine.ts` drainOnce, around the existing success path:
      ```ts
      // current:
      await this.adapter.commitOutboxRow(row)
      await this.db.outbox.delete(row.localId!)
      ```

      Becomes:
      ```ts
      const result = await this.adapter.commitOutboxRow(row)
      await this.db.transaction('rw', this.db.outbox, this.db[row.collection], async () => {
          await this.db.outbox.delete(row.localId!)
          if (result.updatedAt !== undefined && row.op !== 'delete') {
              const existing = await this.db[row.collection].get(row.docId)
              if (existing) {
                  await this.db[row.collection].put({ ...existing, updatedAt: result.updatedAt } as never)
              }
          }
      })
      ```
      Atomicity: outbox delete + local writeback land together; if the
      local row was deleted in the meantime (user pressed Backspace
      mid-flight), the `if (existing)` guard skips the writeback rather
      than resurrecting a deleted row. Keep the per-doc drain ordering
      contract intact — `'sending'`-row reset on start covers the
      crash-mid-writeback case.
