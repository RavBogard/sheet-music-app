<objective>
## Goal
Close the read-side of the local-first sync loop. Stand up Firestore `onSnapshot` listeners for `setlists/{id}` + `tracks/*` (filtered by setlistId) so any leader-tab edit propagates to follower tabs/devices via direct Dexie writes — eliminating the v50-06-02 'theirs' staleness gap and replacing the deleted v50-02 live-swap UI with the implicit real-time setlist sync v5.0 promised. Add airplane-mode integration scenarios beyond v50-06-01's two-writer race (sequential offline edits queued in outbox → reconnect → drain in order, no data loss). Audit `/perform/setlist/[id]` end-to-end against the v50-05-01 top-level `tracks/{id}` collection shape and confirm it renders correctly when leader edits propagate live during a service.

## Purpose
v50-06-01 stabilized the substrate; v50-06-02 surfaced conflicts. Both shipped the *write* side of bulletproof. v50-06-03 ships the *read* side. Today, three observable gaps remain:
1. After 'Take theirs' resolution, the loser's local row stays stale until reload — modal already showed the user the remote value, but the editor doesn't reflect it. (v50-06-02 SUMMARY explicitly defers this to v50-06-03.)
2. Cross-leader live-edit visibility is missing — the deleted v50-02 live-swap UI's implicit replacement (real-time setlist sync) is unbuilt.
3. The performance view (`/perform/setlist/[id]`) still uses the legacy `useSetlistPerformance` hook, which reads `setlists/{id}.tracks[]` (legacy embedded array) — not the new top-level `tracks/{id}` collection that v50-05-01 writes. Production is split-brain until v50-07 migration; the perf view audit determines whether it's read-correct on either shape today and what (if anything) needs to land before cutover.

This is the final plan in v50-06. After it closes, v50-07 (migration + kitchen-sink Playwright + cutover) is the only phase remaining before the milestone closes.

## Output
- New `src/lib/sync/snapshot-listener.ts` exporting `startSnapshotListener({ setlistId, db })` returning an unsubscribe function — subscribes to `doc(setlists/{id})` + `query(tracks where setlistId == setlistId)` and writes results into Dexie via direct `db.{setlists|tracks}.put` (NOT `applyEdit` — server data is authoritative, mirrors `SetlistGridHydrator`'s priming pattern)
- "Skip if our own outbox has a pending row for this docId" guard — prevents the listener from clobbering an in-flight local edit
- LWW guard — only `put` if remote `updatedAt > local.updatedAt` (matches `SetlistGridHydrator`)
- Listener wired into `init.ts` + mounted from `SetlistGridHydrator` (per-route lifetime, NOT app-global — perf view gets its own subscription via the audit task)
- Property-failures harness gains a "passive listener" engine variant + sequential offline-edits-queue-and-drain scenario
- `/perform/setlist/[id]` audit findings documented; if it cannot read the new doc shape, smallest possible read-side adapter lands here (read-only, NO write path changes)
- `.paul/phases/v50-06-concurrent-edit-safety/v50-06-03-SUMMARY.md` capturing what shipped, the perf-view findings, the v50-06 phase close hand-off to v50-07
</objective>

    ```ts
    export interface SnapshotListenerOpts {
      setlistId: string
      db: LocalDb                                    // injectable for tests
      firestoreDb?: Firestore                        // injectable for tests; defaults to @/lib/firebase
      logger?: { warn: (msg: string, err?: unknown) => void }
    }
    export function startSnapshotListener(opts: SnapshotListenerOpts): () => void
    ```

    Behavior:
    - Subscribe to `doc(firestoreDb, 'setlists', setlistId)` via `onSnapshot`.
    - Subscribe to `query(collection(firestoreDb, 'tracks'), where('setlistId','==',setlistId))` via `onSnapshot`.
    - On each setlist delivery: read snapshot.data(), normalize Timestamp.toMillis() for updatedAt, then `await db.transaction('rw', db.setlists, db.outbox, async () => { ... })`:
        1. `pending = await db.outbox.where('[status+...]').filter(r => r.collection==='setlists' && r.docId===setlistId && (r.status==='idle' || r.status==='sending' || r.status==='failed')).first()` — if any pending write for this docId, **skip the put**.
        2. `local = await db.setlists.get(setlistId)`. If `(local?.updatedAt ?? 0) >= remote.updatedAt`, skip (LWW).
        3. Otherwise `await db.setlists.put({ ...remote, id: setlistId, updatedAt: remote.updatedAt })`.
    - On each tracks-query delivery: iterate `snapshot.docChanges()` and apply the same per-doc guard (outbox where collection='tracks' AND docId===change.doc.id) + LWW + put. Use bulkPut for `added`/`modified`; for `removed`, call `db.tracks.delete(id)` UNLESS a pending outbox row exists for that id (don't kill an in-flight local insert).
    - Errors from Firestore listener (auth, permission-denied, transient): swallow + log via opts.logger?.warn — never throw out of the callback. The listener is best-effort; engine writes remain authoritative.
    - The `unsubscribe` returned closes both onSnapshot subscriptions.

    In `init.ts`: export `startSnapshotListener` directly from the new module (re-export). Do NOT auto-mount in `bootEngineOnce` — listeners are per-route lifetime; consumers (SetlistGridHydrator, perf view) will mount/unmount themselves in Task 3.

    Tests in `snapshot-listener.test.ts` (vitest + fake-indexeddb + a hand-rolled FakeFirestore that calls registered onSnapshot callbacks on demand):

    - Removed-doc with pending insert: pre-seed outbox 'set' for that track id; deliver `removed`; assert local row preserved.
    - Listener error: invoke the registered onSnapshot's `onError` callback; assert no throw + logger.warn called once.
