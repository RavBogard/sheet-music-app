<objective>
## Goal
Decide on a design for the `/api/bridge/setup-code` credential-exchange flow that **reduces the blast radius** of a leaked/replayed 10-char setup code. Produce a DECISION.md selecting one of the candidate approaches and a follow-up implementation plan scope.

## Purpose
Audit finding **S02** (FINDINGS.md line 16-18): a valid redemption currently returns the raw `FIREBASE_PRIVATE_KEY` / service-account JSON. v4.2 P1.3 raised code entropy to ~50 bits and added a dedicated 5/min rate-limit tier, but the *credential itself is still the full admin service account*. If a code is ever leaked mid-window (10 min TTL, single-use), the redeemer gets god-mode Firestore access forever.

This is a deferred P0 + CRIT-003 carry-over. It's decision-gated: the fix depends on which threat model we accept and how much complexity we're willing to carry for a single-congregation deployment.

## Output
- `.paul/phases/v43-03-bridge-credentials/03-01-DECISION.md` documenting:
  - The chosen option, rationale, and explicit what-we-accept
  - Threat model (who we're defending against, what we're not defending)
  - Follow-up implementation plan skeleton (scope for 03-02-PLAN.md)
- No code changes in THIS plan — this is research+decision only.
</objective>

           Pros: SA key never transits as plaintext; passphrase out-of-band (Rabbi Daniel types it at install)

         - **C. IAM per-install service-account key (GCP-side provisioning)**
           Pros: revocable per-install; principled least-privilege
           Cons: requires GCP IAM API integration; more moving parts; ops burden
         - **D. Short-lived custom token + admin-SDK proxy API**
           Pros: bridge holds no admin creds directly; can be revoked centrally
           Cons: latency for every admin op; large refactor of bridge; changes bridge architecture significantly
         - **E. Status quo + documentation**
           Pros: zero work
           Cons: doesn't address S02 at all
      4. For each option: effort (XS/S/M/L), residual risk (High/Med/Low), operational cost
