<objective>
## Goal
Make a publish/notify impossible without explicit recipient selection (D8 items 1+2), on
BOTH surfaces — closing the generic-blast class (the v11.2 BUG-9 root) permanently:
- **MCP `publish_setlist`** (the actual blast risk): a real publish (non-dryRun) with
  `recipients` undefined must NOT auto-derive-and-send the whole org roster. It refuses and
  points the caller at `preview_publish` (which still surfaces the default org-scoped audience
  as candidates). Explicit `recipients[]` continues to work.
- **Browser `PublishDialog`**: the per-musician toggle governs the WHOLE recipient
  (in-app + push + email), not just email — a true recipient picker, default all-selected.

## Purpose
The BUG-9 cross-tenant blast and every "sent to the wrong people" failure trace to implicit
fan-out. Daniel's PRIMARY authoring surface (MCP) currently sends to the entire org roster on
a bare `publish_setlist`; that is exactly what D8 item 1 ("never generic") prohibits. This is
also the hard prerequisite for v11.4-04 (default-both membership backfill) — once nothing
auto-blasts, default-both membership is safe.

## Output
- `setlist-publish.ts`: real publish refuses on undefined recipients (no writes, no sends);
  dryRun/preview unchanged (observability).
- `PublishDialog.tsx`: selection set governs all channels; deselected musicians get nothing.
- Regression tests (emulator MCP + browser) citing D8 item 1 + tenancy invariant 3 (BUG-9).
</objective>

  checkbox toggles `emailOptOut` (email only); it always posts the FULL `musicians[]` → in-app +
  push reach everyone assigned regardless of the toggle.
