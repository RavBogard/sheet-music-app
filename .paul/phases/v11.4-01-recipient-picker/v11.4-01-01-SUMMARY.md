# Phase v11.4-01 Plan 01: Recipient picker + no-auto-blast (D8 items 1+2) Summary

**A publish/notify can no longer fan out to an implicitly-derived generic roster on either surface: MCP `publish_setlist` refuses a real publish with undefined recipients (`recipients_required`, dryRun/preview still previews the candidate audience), and the browser `PublishDialog` per-musician toggle now governs ALL channels (in-app + push + email) with an all-selected default — closing the v11.2 BUG-9 blast class and unblocking v11.4-04. CRC's common path is byte-identical; all gates green.**

## Accomplishments

- **D8 item 1 (MCP, the actual blast risk):** in `publishSetlist`, the `args.recipients === undefined` branch now refuses a real publish with `recipients_required` and points the caller at `preview_publish`. dryRun is exempt — it falls through to `resolveDefaultRecipients` so the candidate audience is still surfaced ([[feedback_dryrun_is_observability]]). Header doc updated to the new contract. Every prior gate (assertEditor, rate-limit, caller-org wall, owner-shape gates, stale-version, chart-health) is untouched and ordered as-is.
- **D8 item 2 (browser):** `PublishDialog` `emailOptOut: Set` → `selected: Set` defaulting to ALL assigned musicians. The row toggle adds/removes from `selected`; on publish only the selected subset is posted as `musicians` (in-app + push) AND `emailRecipients` (email). Publish disabled at zero selection. Selection resets to all on open/close.
- **a11y (/ui-ux-pro-max gate):** each musician row is `role="checkbox"` + `aria-checked` (selection conveyed beyond color), `aria-label="Notify <name>"`, ≥44px touch target (`min-h-[44px] py-2.5` — band's 11" iPads), `cursor-pointer`, visible focus ring, and deselected rows carry an `opacity-60` + muted-text non-color cue. A one-line caption states deselected people receive nothing.
- **route.ts:** byte-minimal — one D8 clarifying comment that `musicians[]` IS the explicit recipient set; the ≥1-musician 400 guard already prevents an empty/implicit audience.
- **Tests:** new `v11.4-01` emulator describe block (AC-1 refuse/no-write/no-dispatch · AC-2 dryRun previews · AC-3 explicit sends · AC-3b explicit-empty honored), each citing D8 item 1 / tenancy invariant 3 (BUG-9). New `PublishDialog.test.tsx` (first `.tsx` test in the repo) asserts deselection removes from `musicians[]`+`emailRecipients[]` and empty disables publish.

## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| `recipients_required` lives in the recipients-resolution branch (after chart-health), `!dryRun`-gated | Honors the PLAN's "keep every existing gate ordered as-is"; dryRun naturally falls through to the existing default-derivation so AC-2 observability needs no extra code | Minimal surface; chart-health/preview semantics unchanged |
