<objective>
## Goal
Fix **H4** — the CRC branding leak on the broslaz `/perform/setlist/[id]` route (and its
`track/[trackId]` sub-route): the shared nav renders "CRC Music" + `/logo.jpg` instead of the
host org's brand. Make `perform/setlist/layout.tsx` resolve the host org server-side (the v11.1-01
`(main)/layout.tsx` pattern) and pass branding into `<AppNavigation>` so desktop + mobile headers
are host-correct on first paint, flash-free.

## Purpose
Hard tenancy invariant-1 leak (oracle `docs/ACCESS-POLICY.md` v0.4): a broslaz consumer viewing a
setlist sees the wrong band's identity in the top nav. The browser app is the band/consumer surface
— a branding leak here is exactly the kind of "not bulletproof" defect this milestone targets. This
is the last known CRC-branding leak on a broslaz consumer route (v11.1-01 fixed the `(main)` group;
this route group was never covered because it lives outside `(main)`).

## Output
- `perform/setlist/layout.tsx` converted from a `"use client"` pass-through to an async **server**
  layout that resolves `x-org-id` → `getOrgBranding` and threads branding props to `AppNavigation`.
- A vitest regression test asserting BL host → BL branding props, crc/absent host → crc branding
  (byte-identical), citing the H4 stress cell.
- An H4 regression cell appended to the run-3 stress prompt.
</objective>
