<objective>
## Goal
Fix **H5** — the anon chord-cache **write** 401. The `PATCH /api/library/chord-cache` route is
gated `role: 'musician'`, but the Perform transpose flow calls it for **every** viewer (incl. anon)
via `saveNativeKey(fileId, key, 'auto')` (`use-smart-transposer.ts:139`) on auto key-detection.
Anon → 401 → console noise + the detected native key never persists → every anon visitor re-detects
(recompute). Open the PATCH to anon for the **benign derived/display fields** (auto `nativeKey`,
`lastUsedKey`, `lastUsedTransposition`) while keeping the **trust flag** (`chordsVerified` /
`chordsVerifiedBy`) authed-only, and add the `api` rate-limit the PATCH currently lacks.

## Purpose
Oracle D-Q2 (ACCESS-POLICY v0.4): anon transpose is OPEN + rate-limited; this is the
cost-control + cache-correctness half already established for the GET (read) and POST (persist
scan) on this same route in v11.3-01-02 — anon may persist benign derived data so the next visitor
gets a cache hit. The native key is exactly that tier (the POST already lets anon persist the
scanned chord positions the key-detection is derived from). The 401 is pure noise + wasted recompute
on the consumer Perform surface — the kind of "not bulletproof" defect this milestone targets.

## Output
- `PATCH /api/library/chord-cache` becomes `requireAuth: false` with a field-level guard:
  anon (and any non-musician) may write `nativeKey` (forced `nativeKeySource: 'auto'`),
  `lastUsedKey`, `lastUsedTransposition`; `chordsVerified` / `chordsVerifiedBy` require an authed
  musician+; a manual `nativeKeySource` requires an authed musician+.
- The `api` rate-limit (already on GET/POST) added to PATCH — shared bucket, no double-punish.
- Regression tests for the anon-allowed vs authed-only field split.
</objective>
