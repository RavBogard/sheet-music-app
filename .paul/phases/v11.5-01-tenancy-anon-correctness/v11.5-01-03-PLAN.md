<objective>
## Goal
Fix **H9** — band_leaders are locked out of in-place library-metadata edits. Relax
`editEnrichment` (the shared helper behind the `edit_enrichment` + `edit_library_entry` MCP tools)
from **admin-only** to **admin-OR-band_leader** for a curation-safe field subset, while ADDING the
org-scoping that this code path lacks today, so a band_leader can re-tag a chart in place (no
delete-and-re-import) but can never edit a chart belonging to another tenant.

## Purpose
The browser app is the consumer surface; **MCP is the authoring surface**, and v11.4-04 ratified
band_leaders as the authoring tier ("one unified team authors both bands"). David (band_leader) hit
the gap in the field: `edit_library_entry` is `assertAdmin`-gated (`library-review.ts:634`), so his
ONLY metadata write is `update_song` (key/bpm) — he cannot change a chart's **tags** without
delete-and-re-import, which breaks gig bonds and is impossible for direct-uploads lacking a Drive
source. This makes the authoring tier non-functional for routine curation. **Safety:** the same code
path has ZERO tenancy check today (admin-trusted), so the relaxation MUST add org-scoping or it opens
a cross-tenant authoring hole (err-public hard wall ACROSS tenants).

## Output
- `editEnrichment` accepts an editor-tier caller (admin|band_leader) + the caller's resolved org.
- band_leaders may edit `tags / title / key / bpm / leadMusician`; `collection` stays admin-only
  (rejected with a rich `forbidden_field` envelope for band_leaders).
- band_leader edits are org-scoped: a row whose `orgId` ≠ the caller's connector org returns
  `row_not_found` (never reveals cross-tenant existence) — mirrors `update_song`'s `tenantMismatch`.
- admin behavior is byte-identical to today (no new scoping, all fields, any org).
- emulator-backed authz regression test; tool description strings corrected ("Admin-only" → tier).
</objective>
