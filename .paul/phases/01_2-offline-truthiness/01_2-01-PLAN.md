<objective>
**Goal:** Make the offline indicators tell the truth. Files the UI shows as "offline ready" must actually be retrievable without a network, and the performance view must prefer the local blob over refetching.

**Purpose:** Wave 2 research confirmed: v2.5 Phase 6.1 removed the service worker and uninstalled `@ducanh2912/next-pwa`. `SwCleanup.tsx` still actively unregisters any stragglers. Nothing writes to Cache Storage anymore, yet `isFileCached()` / `getOfflineStats()` / the "offline ready" pills on SetlistCards / the HeroCard ratio / the Performance offline banners all still consult Cache Storage and confidently report success. `use-offline.ts:99–116` counts failed fetches as success. Musicians will arrive at a low-Wi-Fi sanctuary with no charts and a green checkmark. This is the #2 blocker for band onboarding.

**Output:** An IndexedDB blob store is the single source of truth. Downloads write bodies; viewers read them; pills count them. No code path keeps trusting `caches.match()`.
</objective>

**Task 1 — Create the IDB blob store.**
- File: `src/lib/offline-idb.ts` (new)
- Action: thin wrapper over `idb` (already a likely transitive dep) or raw `indexedDB`. Database name `crc-offline`, single object store `files` keyed by `fileId`, value shape `{ fileId: string, blob: Blob, mime: string, size: number, savedAt: number }`. Export: `putFile`, `getFile`, `hasFile`, `deleteFile`, `listFileIds`, `clearAll`.
- Graceful degradation: if `indexedDB` is undefined (SSR, old browser), every function resolves to the "empty" answer (`false` / `null` / `[]`) and `putFile` no-ops.
- Verify: unit tests (Task 5) cover every function.

**Task 2 — Rewrite the download paths in `use-offline.ts`.**
- File: `src/hooks/use-offline.ts`
- Action:

<boundaries>

**DO NOT CHANGE:**
- `SwCleanup.tsx` — it exists to unregister stragglers; leave it.
- The library-index cache path (`library-cache.ts`). That's a separate, working IDB cache for the file *list*; we only replace the *blob* cache story.
- The `/api/drive/file/[id]` endpoint — signed Google Drive fetches work as-is.
- The authenticated read gate on the endpoint.

**SCOPE LIMITS:**
- No service worker revival. v2.5 ripped it out deliberately; Phase 1.2 stays SW-free.
- No background sync / queueing. If a download fails, the user retries.
- No encryption of IDB blobs. Acceptable for this app (PDFs are already served to authenticated users; IDB is per-profile on the user's device).
- No auto-pre-load of every setlist. Keep the explicit "Pre-load setlist" action as the opt-in trigger.

</boundaries>
