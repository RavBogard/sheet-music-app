<objective>
## Goal
Add `fetchTracksForSetlistClient(setlistId, setlistData)` — a client-side equivalent of `server-tracks.ts::getTracksForSetlist` that queries the top-level `tracks` collection via the Firestore Web SDK when hydrated, and falls back to the embedded array when not. Migrate `TemplatesSection.handlePickSetlist` (admin-only Import-from-Setlist flow) to consume it. Closes the only remaining client-side surface that reads tracks via direct one-shot `getDocs` against `setlists/*` without listener / Dexie pre-population.

## Purpose
TemplatesSection is admin-only and fetches recent setlists via a one-shot `getDocs(query(collection(db, 'setlists'), ...))` — no Firestore listener is mounted, so the snapshot listener never delivers tracks to Dexie. The existing `getTracksForSetlistClient` requires Dexie data and is therefore unsuitable. The existing `server-tracks.ts::getTracksForSetlist` is Admin-SDK only (`FirebaseFirestore.Firestore` type) and can't be called from the client. This plan introduces the missing client-side admin-style fetcher and migrates the only consumer.

After this plan, every client-side reader of "what's in this setlist" is one of: (a) Dexie-subscription-backed (`useSetlistPerformance`, `useDexieTracksForSetlists`, `SetlistDrawer` click-time), or (b) Firestore-direct-fetch-backed (`fetchTracksForSetlistClient`, this plan). Embedded `setlist.tracks[]` reads remain only as fallback branches inside the canonical helpers.

## Output
- `fetchTracksForSetlistClient(setlistId, setlistData)` in `src/lib/client-tracks.ts` — 2-branch async helper (hydrated → Firestore top-level `tracks` query, sorted by order; unhydrated → embedded fallback)
- ≥3 new unit tests covering hydrated path, unhydrated path, missing-tracks edge case
- `TemplatesSection.handlePickSetlist` becomes async; awaits `fetchTracksForSetlistClient` with `{ hydrated, tracks }` synthetic setlistData; passes resolved tracks to `convertSetlistToTemplate`
- `SetlistSummary` interface extended with `hydrated: boolean` field (populated from `data.hydrated`)
- Plan SUMMARY at `.paul/phases/v60-06-dashboard-reader-migration/v60-06-06-SUMMARY.md`
- Single combined commit per session precedent

    ```ts
    /**
     * v60-06-06: Client-side equivalent of server-tracks.ts::getTracksForSetlist.
     * 2-branch reader for surfaces that lack Dexie pre-population (admin-side
     * one-shot fetches via getDocs, not Firestore listeners). Mirrors the
     * server-tracks shape but uses the Web SDK.
     *
     *  - Hydrated: query top-level `tracks` collection where setlistId matches,
     *    sort by order ascending, return SetlistTrack[].
     *  - Unhydrated (or hydrated undefined): return the embedded `setlistData.tracks`
     *    array if present; else empty array.
     *
     * The 3-branch Dexie-aware helper (getTracksForSetlistClient) remains the
     * right choice for surfaces with snapshot-listener-populated Dexie. This
     * helper covers the Firestore-direct-fetch admin / one-shot cases.
     */
    export async function fetchTracksForSetlistClient(
        setlistId: string,
        setlistData: { hydrated?: boolean; tracks?: unknown },
    ): Promise<SetlistTrack[]> {
        if (setlistData?.hydrated === true) {
            const q = query(
                collection(db, "tracks"),
                where("setlistId", "==", setlistId),
            )
            const snap = await getDocs(q)
            const rows = snap.docs.map((d) => {
                const data = d.data() as Record<string, unknown>
                return {
                    ...data,
                    id: d.id,
                } as SetlistTrack
            })
            rows.sort((a, b) => (a.order ?? 0) - (b.order ?? 0))
            return rows
        }
        return (setlistData?.tracks as SetlistTrack[] | undefined) ?? []
    }
    ```
