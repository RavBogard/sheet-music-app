<objective>
## Goal
Migrate the matrix endpoint (`/api/setlists/matrix`) off the embedded-array `setlist.tracks` reader and onto the canonical `getTracksForSetlist(db, setlistId, setlistData)` Admin-SDK helper from `@/lib/server-tracks`. Last reader-migration plan in v60-06 — closes the only remaining server-side surface that still consumes `...data` with its trailing embedded `tracks` field.

## Purpose
The matrix endpoint backs the dashboard's 8-week schedule grid (3 weeks back → 4 weeks forward) used to surface "what's in each slot across recent + upcoming services." It currently reads `setlist.tracks` via the spread `...data` at line 67-76, then matches tracks to liturgical slot rows at line 112-121. Any hydrated setlist (post-v50-05) has stale embedded tracks — the matrix grid would show outdated cell contents until/unless the embedded array gets updated. After this migration, the grid reflects live top-level `tracks/{id}` for hydrated setlists and falls back to embedded for legacy. With this and v60-06-08 (15-setlist backfill) shipped, **v60-07 can strip the embedded-array writer with no remaining server reader leakage points.**

## Output
- `matrix/route.ts` calls `getTracksForSetlist(db, doc.id, data)` per setlist doc, parallelized across the (small N, typically ≤8) bulk-fetched setlists via `Promise.all`.
- Spread no longer includes embedded `tracks`: helper result wins (whether hydrated or legacy fallback).
- Grid-matching code at lines 104-127 reads from the helper-derived `setlist.tracks` — shape unchanged (still `SetlistTrack[]`-compatible).
- Plan SUMMARY at `.paul/phases/v60-06-dashboard-reader-migration/v60-06-07-SUMMARY.md`.
- Single combined commit per session precedent (v60-04-01..03 / v60-06-01..06).
</objective>
