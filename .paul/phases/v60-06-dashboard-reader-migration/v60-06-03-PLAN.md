<objective>
## Goal
Migrate two more dashboard read surfaces (`SetlistCards` offline-cache check + `use-upcoming-prep` enrichment) onto the denormalized `setlist.fileIds` + `setlist.songCount` fields produced by the v60-06-02 reconciler, with embedded-array fallback for legacy un-hydrated setlists. Title-aware surfaces (PrepRecommendations + UpcomingTimeline.ExpandedTrackList) are explicitly deferred to v60-06-04.

## Purpose
Continues the v6.0 Wave 3 migration spine — every dashboard read of "what's in this setlist" must route through denormalized parent-doc fields (or, in v60-06-04+, a Dexie-aware reader) before v60-07 strips the embedded `setlists/{id}.tracks[]` writer. This plan retires the two surfaces that need only fileIds + counts (no per-track title/key access), reusing the v60-06-02 fallback pattern verbatim.

## Output
- `SetlistCards.tsx` reads `setlist.fileIds ?? embedded` for offline-cache check
- `use-upcoming-prep.ts` reads `setlist.fileIds` for cross-setlist batch query and `setlist.songCount` / `setlist.fileIds` for per-setlist enrichment
- Plan SUMMARY at `.paul/phases/v60-06-dashboard-reader-migration/v60-06-03-SUMMARY.md`
- Single combined commit
</objective>

    Note: the original loop did NOT exclude `t.type === 'header'`, but in practice headers don't carry fileIds. The denormalized path is the authoritative source; the fallback aligns to the reconciler's filter (which excludes headers). This is a no-op for real data.
