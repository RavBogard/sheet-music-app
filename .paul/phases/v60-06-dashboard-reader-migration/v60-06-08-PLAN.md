<objective>
## Goal
Create a one-shot Firestore backfill script (`scripts/backfill-tracks-v60.ts`) that migrates the 15 most-recent setlists from the legacy embedded `tracks[]` array shape to the v6.0 single-source-of-truth shape: top-level `tracks/{id}` rows + denormalized parent-doc fields (`hydrated`, `trackCount`, `songCount`, `fileIds`). Each setlist is snapshotted to `migration_snapshots/{setlistId}` BEFORE mutation for safe rollback. Final v60-06 plan — closes the phase and unblocks v60-07 embedded-array writer strip on the historical-setlist surface.

## Purpose
v60-06-01..07 closed every READER leakage point (server-side via `getTracksForSetlist`, client-side via the 3-helper inventory, denormalized dashboard fields via the SetlistGridHydrator cascade). But pre-v50-07-03 setlists still have:

- `setlist.tracks[]` embedded array (the legacy source)
- `setlist.hydrated !== true` (never opened in the editor → lazy-hydration cascade never fired)
- NO `tracks/{id}` rows in the top-level collection
- NO `trackCount` / `songCount` / `fileIds` denormalized fields

After v60-07 strips the embedded-array writer, future writes won't maintain `setlist.tracks[]`. The current helper fallback branch (`buildLocalTracks` in `server-tracks.ts`) keeps legacy reads working, but ONLY for legacy setlists that still have the embedded array. The two are independent failure modes:

1. **Reader correctness post-v60-07 writer strip:** any legacy setlist that the user opens after v60-07 ships and then edits will lose its embedded `tracks[]` (the writer no longer maintains it). Without backfill, the editor opens, runs the lazy-hydration cascade (still works post-v60-07 because the cascade is in `SetlistGridHydrator`, not the writer), and the data survives. So readers are technically fine. BUT —

2. **Reader correctness for setlists Daniel NEVER opens in the editor:** the matrix endpoint (v60-06-07) + dashboard surfaces (v60-06-01..06) consume `tracks` (via helper) and denormalized fields (`trackCount` / `songCount` / `fileIds`). For unhydrated setlists with embedded array, the helper's 2nd branch (`buildLocalTracks`) returns the embedded shape — works. For unhydrated setlists post-v60-07 writer strip whose user never opens the editor, NOTHING ever populates `tracks/{id}` or the denormalized fields. The dashboard count cells show fallback values derived from the embedded array — still works because v60-07 strips the WRITER, not the existing data. BUT the embedded array becomes stale across users (cross-device library staleness — exactly v60-09's mandate).

The backfill closes this by proactively migrating the 15 most-recent setlists — the ones in the matrix endpoint's 8-week window + the ones Daniel touches week-to-week. Post-backfill, those setlists are fully hydrated: every reader hits the top-level path; every denormalized field is populated; the helper fallback branch becomes a safety net for outliers, not the primary path.

Scope cap (15 most-recent BY DATE DESC) matches the matrix endpoint's 3-back / 4-forward window with a safety margin. Older historical setlists stay on the embedded shape — they're archive material; v60-08 cleanup will decide whether to delete the embedded array or leave it as historical residue.

               prevTrackCount: setlist.trackCount,

                   const trackId = t.id ?? `${doc.id}-${index}`

                       id: trackId,
                       setlistId: doc.id,

                trackCount: snap.prevTrackCount === undefined ? FIELD_DELETE_SENTINEL : snap.prevTrackCount,
