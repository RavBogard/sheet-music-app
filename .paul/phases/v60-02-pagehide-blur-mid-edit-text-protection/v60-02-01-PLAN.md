<objective>
## Goal
On page-hide events (`pagehide` + `visibilitychange` → `hidden`), commit every in-flight text edit and give the sync engine a brief window to drain its outbox **before** the browser actually suspends the tab. Closes the iPad-Safari "swipe-away-the-tab loses my typing" class of bugs that produced the v5h3 save-loss recurrences.

## Purpose
The v5.4 P0 sprint and the v5h3-01 postmortem both traced multiple save-loss incidents to the same pattern: Daniel types into a cell, swipes the tab away (or iOS suspends the app), the cell never fires `onBlur`, so the draft never reaches the outbox. v60-01 silenced the spurious conflict modal that surfaced these losses; v60-02 actually prevents the loss. Together they close the orthogonal-UX Wave 1 of v6.0 before the engine migration spine in Wave 3.

## Output
- Mid-edit text in `TextCell` (desktop grid + iPad grid) auto-commits on `pagehide`/`visibilitychange:hidden`.
- Mid-edit text in `MobileRowCard` inline inputs/textarea auto-commits on the same events.
- A single page-lifecycle hook installed at engine boot calls `whenEngineIdle(2000)` on `pagehide` so the outbox gets a chance to flush before suspension.
- Unit tests proving each path fires `onCommit` on the synthetic event and that the engine hook awaits idle.
</objective>

          assert `onCommit` called once with the draft + editing state cleared.

          `Object.defineProperty` + dispatch `visibilitychange`, same assertions.
