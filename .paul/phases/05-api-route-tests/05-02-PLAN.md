<objective>
## Goal
Test 2 scheduling API routes: assign and remind. These are the most complex scheduling routes — assign handles batch musician assignment with duplicate detection, new-song detection, multi-channel notifications (email/SMS/push/in-app), and setlist sync. Remind sends reminders to pending musicians with optional 48-hour filtering.

## Purpose
Assign is the core scheduling workflow entry point — regressions here break the entire musician coordination flow. Remind is the follow-up mechanism that ensures musicians respond. Both need coverage for auth, validation, notification side-effects, and error paths.

## AC-1: assign route creates assignments with correct status
```gherkin
Given a POST to /api/scheduling/assign with valid musicians array
When the band_leader submits the request
Then core-tier musicians get status 'confirmed' (autoConfirmed: true)
  and non-core musicians get status 'pending'
  and the response includes count of assigned musicians
```

## AC-2: assign route handles duplicates and errors
```gherkin
Given a POST to /api/scheduling/assign
When a musician already has an assignment for that setlistId
Then that musician is skipped (not re-created, not counted as assigned)
  and existing assignments are not modified
```

## AC-3: assign route sends multi-channel notifications
```gherkin
Given a POST to /api/scheduling/assign with musicians
When assignments are created
Then email is sent if emailEnabled (default true)
  and SMS is sent only if smsEnabled AND phone present
  and in-app notification is created if pushEnabled (default true)
  and FCM push is sent if pushEnabled
  and notification preferences from user doc are respected
```

## AC-4: assign route syncs setlist musicians array
```gherkin
Given a POST to /api/scheduling/assign
When assignments are created for new musicians
Then the setlist document's musicians array is updated with new entries
  and already-present musicians are not duplicated
```

## AC-5: remind route sends reminders for pending assignments
```gherkin
Given a POST to /api/scheduling/remind
When a setlistId is provided
Then it queries pending assignments for that setlist
  and sends email + SMS + in-app notification for each
  and returns reminded count, emailsSent, smsSent
```

## AC-6: remind route filters by 48-hour window without setlistId
```gherkin
Given a POST to /api/scheduling/remind with no setlistId
When pending assignments exist
Then only assignments with eventDate within 48 hours are reminded
  and assignments without eventDate are excluded
  and assignments beyond 48 hours are excluded
```

```gherkin
Given all new test files added
When running `npx vitest run`
Then all 760+ existing tests pass with no regressions
```
