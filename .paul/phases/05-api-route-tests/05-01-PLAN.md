<acceptance_criteria>

## AC-1: respond route validates ownership and status
```gherkin
Given a POST to /api/scheduling/respond
When the assignment exists and belongs to the caller
Then it updates status to confirmed/declined, adds notification, removes from setlist on decline
  and returns 404 for missing assignments
  and returns 403 when responding to another user's assignment
  and returns 400 when assignment is not pending
```

## AC-2: unassign route cancels and notifies
```gherkin
Given a POST to /api/scheduling/unassign by a band_leader
When the assignment exists
Then it sets status to 'cancelled', sends notification, removes from setlist musicians array
  and returns 404 for missing assignments
```

## AC-3: suggest route filters and sorts musicians
```gherkin
Given a GET to /api/scheduling/suggest with setlistId
When musicians exist with various instruments and tiers
Then it excludes already-assigned musicians
  and sorts by tier (core > regular > guest)
  and optionally filters/prioritizes by instrument match
  and returns 400 without setlistId
```

## AC-4: history route returns analytics
```gherkin
Given a GET to /api/scheduling/history
When scheduling_history and scheduling_assignments exist
Then it returns paginated history with limit
  and computes musician stats, instrument frequency, response rate
  and optionally filters by musicianUid
```

## AC-5: calendar-feed generates valid iCal
```gherkin
Given a GET to /api/scheduling/calendar-feed/[token]
When a valid feed token maps to a musician
Then it returns text/calendar content with VCALENDAR/VEVENT blocks
  and returns 400 for short/invalid tokens
  and returns 404 for unknown tokens
```

Given all new test files added
When running `npx vitest run`
Then all 734+ existing tests pass with no regressions
```

            orderBy: vi.fn(() => chain),
            limit: vi.fn(() => chain),
            get: vi.fn(async () => ({ empty: docs.length === 0, docs })),
        }
        return chain
    }
    ```
