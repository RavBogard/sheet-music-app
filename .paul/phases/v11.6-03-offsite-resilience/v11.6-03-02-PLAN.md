<objective>
## Goal
Close the two camp-relevant off-site gaps (scope-C slice 1): WS-12 — an offline
Firestore `onSnapshot` error must NOT blank an already-open set; and WS-13 — give
the player a DEFINITIVE "all N charts saved for offline" readiness signal before
they leave wifi (today it's silent best-effort + a soft indicator).

## Purpose
The two Camp Sabra sets are text/plain on flaky camp wifi. WS-12: in
incognito/memory-cache mode an offline snapshot error currently replaces the whole
open set with a full-screen error (SetlistPerformClient.tsx:190-222 has no
already-loaded guard) — losing the set mid-service. WS-13: precache is best-effort
and silent (use-perform-entry-precache.ts:72-76), so a player can leave wifi
believing charts are cached when some aren't. Decision C (Daniel 2026-06-18).

## Output
- SetlistPerformClient: the error screen is suppressed when the set is already
  hydrated (keep showing it; optional non-blocking reconnect/offline hint).
- SaveOfflineButton: a definitive N-of-N cached readiness state (all-saved vs
  partial) so off-site departure is an informed choice.
</objective>
