<objective>
## Goal
Add a Schedule tab to the mobile bottom bar, strip the dead blockout/availability UI from the Schedule page and UnifiedCalendar, and delete the unused `musician_availability` composite index.

## Purpose
The band is onboarding ~one month out. They will live on mobile and need Schedule one tap away. The Schedule page still references blockout/availability concepts that were abandoned (per v4.2 milestone scope: "no per-musician scheduling features"); those surfaces must become a read-only calendar of upcoming services + setlists only. The stale Firestore index is noise in ops.

## Output
- Mobile bottom bar has a 4th primary tab "Schedule" → `/schedule`
- Schedule page shows upcoming services + setlists; `UnifiedCalendar` has no blockout/availability mode or counts
- `firestore.indexes.json` no longer lists the `musician_availability` composite index
- All tests green, tsc clean
</objective>
