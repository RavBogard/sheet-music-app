## Goal
Fix the production Firestore crash on mobile caused by corrupted IndexedDB left behind by the old PWA service worker. After this plan, users with stale SW state will auto-recover instead of seeing "Something went wrong."

## Purpose
Musicians hitting this crash on their phones can't use the app at all. This is a P0 production fix.

## Output

- `SwCleanup.tsx` — Enhanced to also clear Firestore IndexedDB databases alongside SW unregistration
- `error-boundary.tsx` — Auto-recovery for Firestore assertion errors (clear IDB + reload)
</objective>

## Bug Details
Error on mobile after sign-in:
```
FIRESTORE (12.9.0) INTERNAL ASSERTION FAILED: Unexpected state (ID: b815)
TypeError: Cannot read properties of null (reading 'Te') at nW ... at sE.getTargetData
```

Root cause: The old PWA service worker was unregistered (SwCleanup), but its IndexedDB
persistence data was left behind. Firestore's `persistentMultipleTabManager()` reads
corrupted target metadata from IndexedDB and crashes in `getTargetData`.

The current `catch (e1)` in firebase.ts only catches errors during `initializeFirestore()`,
but this crash occurs AFTER initialization, during the first Firestore query when
persistence actually reads the corrupted IndexedDB data.
</context>
