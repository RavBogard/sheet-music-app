<objective>

## Goal
Restore public + cold-load setlist visibility on the dashboard. Drop the
`!authUser?.uid` early-return gate at `src/hooks/use-setlist-dashboard.ts:87`
so unauthenticated users (incognito browsers) AND signed-in users on slow
mobile cold-loads (where authUser hasn't hydrated yet) both see the
setlists collection. Firestore rules already allow public read on
`setlists/*` (since v60-12 / `firestore.rules:86`); the JS gate is
over-restrictive and now the only thing blocking the read.

## Purpose
Daniel UAT 2026-05-13 reported two P0 production blockers:
- **Issue 1:** Incognito browser at centralreform.live shows no upcoming
  setlist. Public users (band members not signed in, congregants curious
  about service) cannot view the published setlist they're meant to see.
- **Issue 5:** Mobile dashboard "flashes upcoming setlists for a second
  then displays blank boxes; clicking quickly before they disappear leads
  to perpetual loading." Same gate fires on mobile cold-load when
  authUser hasn't resolved yet — the subscription early-returns and the
  initial cached state gets replaced with empty.

Both root-cause to the same single line. Single-file hotfix.

## Output
- `src/hooks/use-setlist-dashboard.ts` — drop `!authUser?.uid` from the
  effect's early-return; subscription always runs; comment updated to
  reference v60-12 public-read rules.
- `.paul/phases/v60-13-sync-engine-resilience/v60-13-01-SUMMARY.md`
