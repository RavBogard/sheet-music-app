<objective>
## Goal
Collapse the `toast.loading → toast.dismiss → toast.success/error` triples that handle the dismiss step incorrectly. Where the dismiss takes no argument, fix the latent bug (it dismisses every visible toast, not just the loading one).

## Purpose
Sonner supports `toast.success(message, { id: loadingToastId })` to replace a loading toast in place. Three handlers in the codebase already use this pattern correctly; two more dismiss-then-show, and one dismisses *all* toasts (a real bug — kills any unrelated banner that happens to be open). Aligning the rest is a 6-line fix with zero behavioural risk for the correctly-targeted variant and a real UX improvement for the dismiss-all case.

The broader Phase 4 backlog ("inline badges to replace routine successes" + "error toasts on ~10 silent-catch paths") is intentionally not in this plan: each call site needs per-handler judgement about whether silence is intentional, and the inline-badge UX is undefined enough to warrant its own brainstorm.

## Output
- Two `toast.dismiss(id) + toast.success/error(...)` pairs in `use-setlist-dashboard.ts` collapsed to single `toast.success/error(..., { id })` calls.
- `use-creation-wizard.ts` captures the loading id from `toast.loading()` and uses it for the success/error replacement instead of `toast.dismiss()` (no-arg).
</objective>
