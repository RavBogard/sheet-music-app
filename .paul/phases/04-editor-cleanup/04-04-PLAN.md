<objective>
## Goal
Unify three sources of instrument metadata: (1) the human-string array hardcoded in `OnboardingCard.tsx`, (2) the slug-keyed `REQUIRED_INSTRUMENTS` set in `musician-suggestions.ts`, and (3) the duplicated slug array in `api/scheduling/suggest-band/route.ts`. Everything points at the canonical `INSTRUMENT_PRESETS` registry in `src/lib/musician-profile.ts`.

## Purpose
Today, OnboardingCard saves strings like `"Guitar"` to `musicianProfile.instrument`, but Settings saves slug keys like `"acoustic_guitar"` — same field, two shapes. Downstream consumers (suggestions, scheduling, auto-transposition) expect slugs and silently mis-handle the onboarding-set values. This is a latent data mismatch.

## Output
- New export `INSTRUMENT_OPTIONS` (or `BASIC_INSTRUMENTS`) from `musician-profile.ts` — a small curated list of onboarding-friendly slugs drawn from `INSTRUMENT_PRESETS`.
- `OnboardingCard.tsx` reads from that export; its `<option value>` stores slugs (consistent with Settings); display uses the preset's `label`.
- `REQUIRED_INSTRUMENTS` promoted to an export in `musician-profile.ts` (or adjacent `musician-suggestions.ts` if it already lives there) so the scheduling-route copy is deleted.
</objective>
