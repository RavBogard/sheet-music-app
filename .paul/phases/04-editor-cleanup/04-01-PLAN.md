<objective>
## Goal
Kill three pieces of duplicated/wrong-shaped logic that keep making future plans harder: four local `canEditSetlist`-shaped predicates, three `formatEventDate` copies, and the `useUpcomingPrep` hook's stuck-loading state when the user has no upcoming services.

## Purpose
Phase 4 is technical-debt cleanup before editor-ergonomics UI work. Every subsequent plan in this phase (modal consolidation, track-row buttons, error-toast sweep) needs a stable "can this user edit this setlist?" check and a single date-formatter. Fixing the stuck-loading dashboard spinner removes a real user-visible bug before band onboarding.

## Output
- `src/lib/setlist-permissions.ts` exporting `canEditSetlist(setlist, auth)` — single canonical predicate.
- All four (or more) ad-hoc call sites migrated to the helper.
- Three `formatEventDate` copies collapsed to the canonical one in `src/lib/firestore-helpers.ts`.
- `useUpcomingPrep` reflects the subscription's `loading` state instead of `setlists.length === 0`.
- Regression tests for both helpers + a targeted test for the stuck-loading case.
</objective>

    1. Create `src/lib/setlist-permissions.ts`:
       ```ts
       import type { Setlist } from '@/lib/setlist-firebase'

       export interface SetlistAuthContext {
         uid: string | null | undefined
         isBandLeader: boolean
         isAdmin: boolean
       }

       /**
        * Single source of truth for "can this user edit this setlist?".
        * Covers the four predicate shapes scattered across the codebase today.
        * Legacy docs without ownerId (v2.5 P8.1 decision) are editable by anyone
        * who already has read access — match existing SetlistDashboard behaviour.
        */
       export function canEditSetlist(
         setlist: Pick<Setlist, 'ownerId'> | null | undefined,
         auth: SetlistAuthContext
       ): boolean {
         if (!setlist) return false
         if (auth.isAdmin || auth.isBandLeader) return true
         if (!setlist.ownerId) return true // legacy-accessible
         return auth.uid === setlist.ownerId
       }
       ```
    2. Migrate in-scope call sites:
       - `src/components/setlist/SetlistDashboard.tsx:194` and `:226` — replace `setlist.ownerId === user?.uid || isAdmin || isBandLeader` with `canEditSetlist(setlist, { uid: user?.uid, isBandLeader, isAdmin })`.

    3. Create `src/lib/__tests__/setlist-permissions.test.ts`:
