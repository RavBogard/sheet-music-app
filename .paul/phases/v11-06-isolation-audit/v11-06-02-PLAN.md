<objective>
## Goal
The MCP-layer adversarial axis of the v11-06 close-gate audit: prove a caller CANNOT
escape their tenant via the MCP surface. Two escape vectors:
1. **Host-spoof / header confusion** — the caller's tenant is resolved EXCLUSIVELY from the
   verified bearer token (`verifyBearer(req).orgId` → `AuthInfo.extra.orgId` → `orgFrom(extra)`).
   A forged/mismatched `x-org-id` header (or any other request header) MUST NOT change it.
2. **Argument-injection** — no MCP tool may accept a caller-suppliable `org`/`orgId`/`tenant`
   parameter. Caller org is always `orgFrom(extra)`, never read from a tool's `args`. Lock this
   as a durable invariant so a future tool can't silently add an org selector that escapes the wall.

## Purpose
Closes the "MCP org-scope escape" + "host-spoof tenant confusion" axes from the ROADMAP v11-06
focus. v11-02 proved per-tool read/write isolation (caller org passed as the resolved 3rd arg);
this plan proves the LAYER ABOVE — that the resolved org itself is un-spoofable and not
caller-selectable. Cross-tenant isolation is security-critical (constraint 3/4); a spoofable
org seam or an org-accepting tool arg would defeat every per-tool wall at once.

## Output
- `host-spoof-org-authority.emulator.test.ts` — verifyBearer + orgFrom adversarial coverage.
- `mcp-org-arg-injection.test.ts` — registry-introspection invariant (no org-selecting tool arg).
- `v11-06-02-SUMMARY.md` — both invariants proven (feeds the v11-06-03 AUDIT.md).
</objective>

<acceptance_criteria>

## AC-1: bearer is authoritative — a spoofed x-org-id header cannot change the resolved org
```gherkin
Given a BL bearer token (token doc orgId='brotherslazaroff') and a CRC bearer token (orgId='crc'/absent)
When verifyBearer is called on a Request that ALSO carries a spoofed `x-org-id` header naming the OTHER tenant
Then the returned orgId equals the TOKEN's org (brotherslazaroff for the BL bearer, crc for the CRC bearer)
And the x-org-id header has zero effect (both spoof directions tested)
```

## AC-2: orgFrom is the sole org seam with safe defaults
```gherkin
Given an AuthInfo.extra carrying a bearer-derived { uid, orgId }
When orgFrom(extra) is called
Then it returns extra.authInfo.extra.orgId verbatim
And returns DEFAULT_ORG_ID ('crc') when orgId is absent/empty (back-compat, never cross-tenant-open)
And THROWS "Unauthenticated MCP request" when uid is missing
And no field other than the bearer extra (no header, no injected key) influences the result
```

## AC-3: no MCP tool accepts a caller-suppliable org selector (no argument-injection escape)
```gherkin
Given every MCP tool registered via the register*Tools(server) entrypoints in tools/index.ts
When each tool's inputSchema is introspected
Then NONE exposes an org-selecting input key (/^(org|orgId|orgIds|tenant|tenantId)$/i)
And therefore caller org is exclusively orgFrom(extra) — never read from a tool's args
```
