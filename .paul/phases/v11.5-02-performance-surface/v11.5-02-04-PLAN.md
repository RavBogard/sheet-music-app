<objective>
## Goal
Make per-chart zoom **stick per device**: when a user zooms a chart in Perform mode, that
zoom is remembered for THAT chart (keyed by `fileId`) and restored the next time the chart
opens — across navigation, reopen, and orientation change. Add a one-tap **Fit** reset
(tappable zoom-% label) so any chart can be snapped back to its auto-fit baseline, which is
the bulletproof landscape-recovery affordance. LAST plan of phase v11.5-02 — closing it
transitions the phase.

## Purpose
H1 in the v11.5 brief = "landscape auto-fit + persisted per-chart calibration." Verified
against current code: fit-to-width + landscape reflow ALREADY work (PDFViewer renders
`width*zoom` where `width` tracks the container via ResizeObserver and refits on rotate;
SmartScoreViewer recomputes its fit baseline on rotate). The genuinely-missing capability is
**persisted per-chart calibration**: today `zoom` is a single session-global value
(`store.ts` partialize) — one zoom across all charts, lost on reload. The band needs each
chart to remember the zoom that reads well on the iPad. Daniel ratified scope **per-device
(localStorage)** 2026-06-14: zoom is a viewing preference (eyesight / screen size), MUST NOT
override another musician's view — so NO shared Firestore write, unlike the live-director key
change. Bulletproof > novel.

## Output
- `store.ts`: a persisted `chartZoom: Record<fileId, number>` map; `setZoom` writes through to
  the current chart's entry; per-chart restore on every queue transition; `zoom` dropped from
  the global partialize (superseded by per-chart).
- `PerformanceToolbar.tsx`: the zoom-% label becomes a tappable **Fit** control that resets
  the current chart to its auto-fit baseline (zoom = 1).
- Tests proving per-chart persistence + restore + Fit reset.
- SUMMARY.md.
</objective>

<acceptance_criteria>

## AC-1: Per-chart zoom is remembered across navigation
```gherkin
Given a setlist is open in Perform mode with charts A and B
When the user zooms chart A to 140% and navigates to chart B (still 100%) and back to chart A
Then chart A renders at 140% and chart B renders at 100%
And chart B's zoom was never affected by chart A's calibration
```

## AC-2: Per-chart zoom survives reload (per-device persistence)
```gherkin
Given the user zoomed chart A to 140% in this session
When the Perform view is reloaded (new page load, same device) and chart A is reopened
Then chart A renders at 140% (restored from localStorage), not the default
And the calibration is device-local — it was NOT written to Firestore / the track doc
```

## AC-3: Fit reset returns a chart to its auto-fit baseline
```gherkin
Given chart A is currently zoomed to 140%
When the user taps the zoom-percentage / Fit control in the PerformanceToolbar
Then chart A renders at its auto-fit baseline (zoom = 1 → full-width for PDF, fit-width for MusicXML)
And chart A's remembered calibration is updated to that baseline (1)
```

## AC-4: Orientation change preserves the chart's calibration
```gherkin
Given chart A is calibrated to 120% in portrait
When the iPad is rotated to landscape
Then the chart re-fits to the new container AND the 120% multiplier is still applied on top
And rotating back to portrait still shows 120%
```

    Add a persisted, per-chart zoom map and make `zoom` a derived/restored value rather than a
    single global. Keep the public `zoom` field + `setZoom` signature unchanged so the viewers
    (PDFViewer/SmartScoreViewer) need NO edits.

    1. State: add `chartZoom: Record<string, number>` (key = chart `fileId`, value = zoom
       multiplier). Initialize `{}` in the store body and in `reset()`.
    2. `setZoom(z)`: keep `set({ zoom: z })`, AND write through to the current chart:
       resolve the current fileId from `get().playbackQueue[get().queueIndex]?.fileId`; if present,
       set `chartZoom: { ...get().chartZoom, [fileId]: z }`. (No current fileId — e.g. the
       standalone single-chart route that uses `setFile`, not the queue — just sets `zoom`; see
       SCOPE LIMITS.) Clamp consistency: callers already clamp to [0.5, 2.0]; do not re-clamp here.
    3. Restore per chart on EVERY queue transition, mirroring how `transposition` is restored from
       `track.transposition` today. In `setQueue`, `nextSong`, `prevSong`, `jumpToSong`, add
       `zoom: get().chartZoom[track.fileId] ?? 1` to the same `set({...})` that already sets
       `transposition` (use the resolved current track — `items[startIndex]` / `nextTrack` /
       `prevTrack` / `track`). Default `1` = auto-fit baseline.
    4. `partialize`: persist `chartZoom` (REMOVE the now-superseded global `zoom` key — per-chart
       restore replaces it; keep `audio`). Result: `({ chartZoom: state.chartZoom, audio: {...} })`.
    Avoid: adding a new field to `QueueItem`/`SetlistTrack` (fileId is already the key); calling
    `applyEdit` or any Firestore/network write (Daniel ratified per-device — localStorage only);
    re-clamping in `setZoom` (would diverge from the toolbar's clamp and the [0.5,2.0] contract).

<boundaries>
## DO NOT CHANGE
- `PDFViewer.tsx`, `SmartScoreViewer.tsx`, `ImageScoreViewer.tsx` — viewers already multiply user
  zoom on top of their fit/width baseline; restoring the right `zoom` per chart is sufficient. No
  viewer edits.
- `live-director.ts`, `applyEdit`, `tracks/{id}` schema, Firestore rules — per-device scope means
  ZERO shared-write surface. Do not add a `calibration` field to `SetlistTrack`/`QueueItem`.
- The [0.5, 2.0] zoom clamp + 0.1 step in `PerformanceToolbar`.

## SCOPE LIMITS
- **Per-device only** (localStorage). No cross-device / cross-band sharing of zoom (Daniel ratified 2026-06-14).
- **Crop deferred** (greenfield — recon; not in this plan).
- **Image charts** use native pinch and don't read `store.zoom` → calibration does not apply to them. Acceptable.
- **Standalone `/perform/[fileId]` route** (uses `setFile`, no queue) gets the global default (zoom 1);
  per-chart persistence covers the setlist Perform path (the band surface). Not widened here.
- No PDF fit-to-PAGE / fit-to-height work — fit-to-width + rotate reflow already exist and meet the
  landscape requirement; Fit reset is the recovery affordance.
</boundaries>
