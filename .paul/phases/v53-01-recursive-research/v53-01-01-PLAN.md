<objective>
## Goal

Run 3 parallel research tracks against the v50-05 spreadsheet editor's three highest-friction surfaces (ChartBind picker, polymorphic Add menu absence, chart verification gap), git-spelunk the pre-v50-02 old editor for port-back-worthy patterns, capture real-iPad UAT for ChartBind sub-modes, and synthesize into RESEARCH-SYNTHESIS.md that gives v53-02..04 a confirmed root-cause + design-options foundation — so execution phases fix the *systemic* cause and port back the *right* old-editor patterns, not surface symptoms or full reverts.

## Purpose

Daniel's explicit ask for v5.3: **"systemic fixes, not bandaids"** + **"the old 'add' menu was MUCH better"** + **explicit non-goal: scrap the spreadsheet editor.** Three user-visible regrets cluster around v50-05 substrate decisions (single-purpose AddRowPlaceholder, missing chart-verification peek, ChartBindPopover search reported broken). Without research, phase 2–4 planning would have to guess at root causes (cf. v5h-01 §2 "3 wrong handoff hypotheses" pattern) AND would miss the inventory of port-back-worthy patterns the old editor had — risking either insufficient fixes OR over-eager reverts that re-introduce the data-flow fragility v50-05 was built to eliminate.

## Output

- 3 track research reports in `.paul/phases/v53-01-recursive-research/track-{a,b,c}-*.md`
- 1 iPad UAT capture file documenting real-device repro for ChartBind sub-modes
- 1 `RESEARCH-SYNTHESIS.md` consolidating findings + phase-2..4 scope recommendations + open questions for Daniel
- No source code modified
</objective>
