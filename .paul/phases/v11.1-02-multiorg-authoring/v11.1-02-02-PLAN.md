<objective>
## Goal
Give admins a UI control in the `/manage` People list to set a band leader's **org membership** — CRC / Brothers Lazaroff / Both — writing the `orgIds` to BOTH the Auth custom claim and the `users/{uid}` doc in lockstep. This is Build A of the phase: it grants the multi-org membership that v11.1-02-01's host-derived authoring then consumes (admin grants membership → leader connects Claude Desktop per-tenant to author).

## Purpose
Today `orgIds` is set only by hand-run scripts (`fix-david-orgids-claim`, `backfill-user-orgids`). Daniel asked for an in-UI admin toggle so onboarding a leader to a tenant (or to both) is a click, not a script. Completes the leader-membership tier of the locked tenancy model.

## Output
- `orgIds` on the `UserProfile` type + converter (so the People list can read/display it).
- `/api/admin/set-role` also persists `orgIds` to the `users/{uid}` doc (already writes the claim) — keeps doc + claim + roster filtering consistent.
- A tri-state org-membership control on band_leader/admin rows in `UserRow` (admin-only), + a current-membership badge.
- Emulator test proving claim+doc both get `orgIds`, role preserved, admin-only, known-org validation.
</objective>

## Key facts (traced 2026-06-09)
- Admin UI EXISTS: `/manage` (`src/app/(main)/manage/page.tsx`, server-gated `user.isBandLeader`, passes `serverIsAdmin`) → `ManageClient` → People tab → `PeopleSection` → `UserRow`. shadcn/ui `Select`/`Switch`/`Badge`/`AlertDialog`.
- `UserRow` per-row role `Select` (lines ~262-283) → `requestRoleChange` → AlertDialog → `updateUserRole(uid, newRole)` (`users-firebase.ts:128`).
- `/api/admin/set-role` (`route.ts`): schema `{ targetUserId, newRole(enum), orgIds?: string[] }`; **admin-only** (`createApiHandler({ role:'admin' })`). Txn updates `users/{uid}` doc `{ role, claimsUpdatedAt }` (NOT orgIds). Then `setCustomUserClaims({ ...existing, role, ...(orgIds?{orgIds}:{}) })` — **orgIds → CLAIM only**. Validates `isKnownOrg` already.
- The People list reads the `users` collection via `subscribeToAllUsers` (`users-firebase.ts:107`) → `UserProfile`. `UserProfile` does NOT yet carry `orgIds`. Roster filtering (v11-05-02 `rowOrgIds`) reads `users/{uid}.orgIds` from the doc → the doc MUST carry orgIds for both UI display and roster correctness.
- Known orgs: `crc`, `brotherslazaroff` (`registry.ts` ORGS / `isKnownOrg`). Default membership (absent claim/doc) = `['crc']` (`getOrgIdsFromClaims` / `rowOrgIds`).
- Admin vs band_leader: set-role is admin-only at the backend; band leaders can VIEW /manage but role/membership writes 403 for non-admin. Gate the new control to `isAdmin` in the UI to avoid a UX 403.
