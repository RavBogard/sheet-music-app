<objective>
## Goal
Make a multi-org leader's MCP bearer pin to the **tenant domain they connect Claude Desktop to**, validated against their own `orgIds` claim — so authoring on `brotherslazaroff.live/api/mcp` mints a `brotherslazaroff` bearer and lands setlists in broslaz, while `www.centralreform.live/api/mcp` stays crc. This is the permanent fix for the live bug where Daniel's MCP-authored setlist landed `orgId:'crc'` and was invisible on broslaz.

## Purpose
Daniel (and future multi-org leaders) currently CANNOT author for a non-primary org: the self-service + OAuth mint paths both call `getPrimaryOrgForMinting(uid)` → `orgIds[0]` = 'crc', and MCP forbids a caller-suppliable org selector (v11-06-02). Daniel chose "authoring org = connection domain" (2026-06-09) because it's consistent with the locked host-determines-experience tenancy model and preserves the v11-06-02 isolation lock entirely (no MCP tool ever gains an org arg). This unblocks the core weekly value: Daniel authors broslaz setlists conversationally via Claude + MCP.

## Output
- A server-only `resolveMintOrg(uid, requestedOrg)` resolver (host org if ∈ caller's orgIds, else safe fallback to primary).
- The 2 user-facing mint paths (OAuth token exchange + self-service `/api/mcp/tokens`) derive the bearer's org from the request host (the proxy's `x-org-id`) through that resolver.
- Emulator test proving host-derived minting + membership validation + crc regression + the v11-06-02 invariant still holds.
- Deploy + a verified canonical broslaz MCP base URL; Daniel's hands-on Claude-Desktop author-broslaz confirmation appended to UAT-PENDING.
</objective>

## Key facts (traced 2026-06-09)
- `createMcpToken(uid, label, orgId = DEFAULT_ORG_ID)` (`src/lib/mcp/tokens.ts:45`) already pins the token doc's `orgId`; `verifyBearer` reads it as the SOLE per-request org authority (`src/lib/mcp/auth.ts:142-143`). The bearer IS org-pinned — only the mint-time org choice is wrong.
- OAuth token route mints at `src/app/api/mcp/oauth/token/route.ts:99-103`: `const orgId = await getPrimaryOrgForMinting(authCode.uid)` then `createMcpToken(...)`. Self-service route mints at `src/app/api/mcp/tokens/route.ts:36`: same `getPrimaryOrgForMinting(ctx.auth.uid)`.
- `getPrimaryOrgForMinting` (`membership-server.ts:46-49`) returns `getUserOrgIds(uid)[0]`. `getUserOrgIds` reads the Firebase Auth `orgIds` custom claim via `getOrgIdsFromClaims` (`membership.ts:19-28`), default `['crc']`.
- The proxy already forwards a host-resolved `x-org-id` header (`resolveOrgIdByDomain` strips `www.`; registry maps `brotherslazaroff.live`→`brotherslazaroff`, `centralreform.live`→`crc`). `coerceOrgId()` validates a string as a known org id (defaults crc).
- brotherslazaroff.live serves the same app (confirmed: authed dashboard renders there). So `brotherslazaroff.live/api/mcp` + `/api/mcp/oauth/*` route to the same handlers with the broslaz host.
- v11-06-02 invariant test: `src/lib/mcp/__tests__/mcp-org-arg-injection.test.ts:74` asserts NO MCP tool inputSchema exposes an `org|orgId|orgIds|tenant|tenantId` key. This design does NOT touch tool schemas (org pinned at mint, not per-call), so that test must remain green UNCHANGED.
