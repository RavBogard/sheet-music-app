<objective>
## Goal
Add a way to edit a setlist's **name, event date, service type, and rabbi**
AFTER creation. A pencil/edit icon button in the setlist editor's top bar
(`SetlistGridTopBar`) opens a mobile-friendly Sheet with a form for those four
fields; Save writes through the v6.0 sync engine via `applyEdit`, Cancel is
non-destructive.

## Purpose
Daniel UAT 2026-05-13 (long-standing "Issue 2"): "there appears to be no way to
modify the name / date / etc... of a setlist that has already been created."
The v60-14 fix addressed the *creation wizard* date reset — but editing an
*existing* setlist's metadata was never built. Today Daniel has to delete +
recreate a setlist to fix a typo'd name or a moved service date. This closes
that gap. Daniel-directed jump 2026-05-14 (out of roadmap sequence, before
v70-06).

## Output
- `SetlistMetaEditSheet.tsx` — a Sheet-based metadata edit form (name / date /
  service type / rabbi) that commits via `applyEdit('update', 'setlists', …)`.
- `SetlistGridTopBar.tsx` — a pencil edit-icon button beside the setlist name.
- `SetlistGrid.tsx` — mounts the Sheet, owns its open state, and reads the live
  setlist doc so the header + form reflect edits immediately.
- Tests for the Sheet commit/cancel paths and the top-bar trigger button.
- A `.paul/UAT-PENDING.md` entry for Daniel's iPad verification.
- `.paul/phases/v70-09-setlist-metadata-editor/v70-09-01-SUMMARY.md`.
</objective>

  <files>src/components/setlist/grid/SetlistMetaEditSheet.tsx</files>
  <action>
    Create the Sheet-based metadata editor component.

    **Props:**
    - `setlistId: string`
    - `open: boolean`
    - `onOpenChange: (open: boolean) => void`
    - `initial: { name: string; eventDate?: number | undefined; rabbi?: string;
      templateType?: Setlist['templateType'] }` — current values to seed the form
      (parent passes these from the live setlist doc).
    - Optional `applyEdit` injection prop defaulting to the real
      `@/lib/local/write` export (mirrors `SetlistGridHydrator`'s testability
      pattern — lets the test assert the enqueued patch without booting Dexie).

    **Form:**
    - Local form state seeded from `initial` (via `useState`, re-seeded with a
      `useEffect` on `open` going false→true so reopening shows fresh values).
    - **Name** — `Input` (`@/components/ui/input`) with a `Label htmlFor`.
    - **Event date** — mirror `CreationWizard.tsx`'s date pattern exactly:
      a `Button` showing the formatted date (or "Pick a date") that opens a
      `Popover` containing `Calendar` (`@/components/ui/{popover,calendar}`).
      Read CreationWizard for the exact `format(...)` usage and `selected`/
      `onSelect` wiring — reuse it, do not invent a new date UX.
    - **Service type** — `Select` (`@/components/ui/select`, full
      Trigger/Value/Content/Item structure) over the 6 `templateType` enum
      values from `Setlist` in `src/types/models.ts`: `shabbat_morning`,
      `friday_night`, `rosh_hashanah`, `yom_kippur`, `festival`, `other`.
      Human-readable labels ("Shabbat Morning", "Friday Night", "Rosh Hashanah",
      "Yom Kippur", "Festival", "Other").
    - **Rabbi** — a plain `Input` (the `Setlist.rabbi` field is a free-text
      `string`). DELIBERATE scope choice: NOT the congregation-rabbiProfiles
      `Select` the CreationWizard uses — that pulls a congregation-context
      dependency this minimal slice does not need. Free-text Input keeps the
      component self-contained; a profile Select is a possible later polish.
    - Use `SheetHeader` / `SheetTitle` / `SheetFooter` from `sheet.tsx`.

    **Save handler:**
    - Build `patch` containing ONLY fields that changed vs `initial` (diff each
      field; if nothing changed, close the sheet and return WITHOUT calling
      applyEdit — AC-4).
    - For `eventDate`: determine the correct serialization by reading
      `src/types/schemas.ts` (`firestoreTimestampSchema`), `buildLocalSetlist`
      in `src/app/(main)/setlists/[id]/page.tsx` (LocalSetlist stores eventDate
      as a ms `number`), and how `service.createSetlist` (use-creation-wizard.ts)
      passes it. Pick the format that survives the Dexie write + outbox→Firestore
      fanout + reload — the AC-2 round-trip test is the proof. Do NOT guess;
      match what the rest of the system round-trips.
    - Call `applyEdit({ op: 'update', collection: 'setlists', docId: setlistId,
      patch })`. On success: show a success `toast` (match CreationWizard's toast
      usage) and `onOpenChange(false)`. On failure: show an error toast, keep
      the sheet open so Daniel can retry (Submit-feedback UX rule).
    - Disable the Save button while the applyEdit promise is in flight
      (loading-buttons UX rule).

    **Cancel / Escape:** `SheetClose` / `onOpenChange(false)` — no writes. The
    Sheet's built-in Escape + overlay-click already call `onOpenChange`.

    **Design (from /ui-ux-pro-max consult during planning):**
    - Touch targets >=44px on every control (`min-h-[44px]`); `gap-2` minimum
      between the Save/Cancel buttons.
    - Every field gets a `<Label htmlFor>` paired to its input id.
    - Save = primary brand button; Cancel = ghost/secondary `Button` variant.
    - Match the app's dark-first glass aesthetic — reuse `sheet.tsx`'s existing
      surface styling; do not restyle the Sheet primitive.

    Avoid: writing unchanged fields into the patch (pollutes the outbox + the
    edit-log); a desktop-centered Dialog (must be a Sheet — AC-5); a bespoke
    date picker (reuse CreationWizard's Calendar/Popover).
  </action>
  <verify>npx tsc --noEmit — SetlistMetaEditSheet.tsx is type-clean</verify>
  <done>AC-1 (form renders pre-filled), AC-2/AC-3 (Save builds a changed-only
    patch + applyEdit), AC-4 (no-change/cancel = no write), AC-5 (Sheet, labels,
    44px targets) are all implementable from this component</done>
