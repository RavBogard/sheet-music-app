<objective>

## Goal
Add a way to edit a setlist's name, date, service type, and other metadata
AFTER it's been created. Currently Daniel reports "there appears to be no
way to modify the name / date / etc... of a setlist that has already been
created."

## Purpose
Daniel UAT 2026-05-13: "there appears to be no way to modify the name /
date / etc... of a setlist that has already been created."

Common workflow: create setlist with template → tweak name → reschedule
date if service moves. Without this, Daniel has to delete + recreate.

## Output
- A small "Edit setlist metadata" affordance in the setlist editor (likely
  a kebab/settings menu on the SetlistGrid header) opening a modal/sheet
  with name + date + service-type + lead-rabbi fields
- Writes route through `applyEdit('update', 'setlists', {...})` so the
  v6.0 sync engine handles propagation
- Tests for the modal commit path
- `.paul/phases/v70-09-setlist-metadata-editor/v70-09-01-SUMMARY.md`

</objective>

<acceptance_criteria>

## AC-1: Daniel can edit setlist name post-creation
```gherkin
Given a setlist exists at /setlists/{id}
When Daniel opens it and triggers "Edit setlist details" (kebab → menu item)
  AND types a new name
  AND clicks Save
Then the setlist's name field updates locally immediately
  AND an applyEdit('update', 'setlists', {name: ...}) is enqueued
  AND the dashboard reflects the new name within ~1s of sync
```

## AC-2: Daniel can edit event date / service type / lead rabbi
```gherkin
Given the same modal open
When Daniel changes the event date / service type / lead rabbi
  AND clicks Save
Then all changed fields persist via applyEdit
  AND the SetlistGrid header / cards reflect the changes
```

## AC-3: Mobile-friendly
```gherkin
Given Daniel uses the modal on iPad
Then it opens as a Sheet (not desktop-style centered modal)
  AND form inputs are touch-friendly (≥44px touch targets)
  AND the date picker uses native input type="date" if v60-14 fix lands first
```

## AC-4: Cancel path is non-destructive
```gherkin
Given Daniel makes changes in the modal
When he clicks Cancel or presses Esc
Then no writes happen
  AND the setlist data is unchanged
```
