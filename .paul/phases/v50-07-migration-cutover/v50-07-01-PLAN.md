<objective>
## Goal
Run `scripts/migrate-v50.ts --dry-run` against production Firestore AND audit
production data shape for three v5.0-relevant questions, then write a DRY-RUN
report that drives v50-07-02 scope decisions. **NO writes to production.**
**NO changes to `migrate-v50.ts`.** Pure discovery + decision input.

## Purpose
v50-07 is the final phase before v5.0 milestone close. The migration is
irreversible past `--apply`, so v50-07-01 is the safety gate: figure out what
production actually contains before deciding whether the existing script is
sufficient OR needs extension for two known gaps:
1. Reshape legacy `setlists/{id}.tracks[]` → top-level `tracks/{id}` collection
   (perf-view audit Outcome 2 from v50-06-03)
2. Scrub orphan v50-02 data (AI-chat / song-groups / liveState collections that
   v50-02 deleted code for but left data in place per close note)

The current `migrate-v50.ts` only does the v50-04 song-defaults backfill
(`songs/{id}.defaults` from setlist `tracks[]` history). It does NOT do
either of the above. v50-07-01 confirms this assumption against real prod
data and produces the audit report that drives v50-07-02 scope.

## Output
- `DRY-RUN-REPORT.md` capturing:
  - Dry-run output (affected song count, sample defaults)
  - Setlist count + how many have legacy `tracks[]` arrays + total embedded
    track count
  - Top-level `tracks/{id}` collection count + setlists referenced
  - Split-brain delta (setlists with embedded tracks but no top-level rows;
    setlists with top-level rows but no embedded tracks; setlists with both)
  - Orphan v50-02 data presence: `chats/*`, `songGroups/*` (or
    `config/songGroups`), any `liveState` field on setlists, any setlist with
    `liturgicalSlot` field
  - Idempotency marker check: does `system/migrations/v50` already exist?
  - Recommendation block: which v50-07-02 sub-scopes are needed
- HUMAN-VERIFY checkpoint: user reviews + chooses path forward
- SUMMARY.md closing the loop
</objective>

```gherkin

Then it contains:
  - Setlists with embedded tracks but ZERO top-level tracks (legacy-only)
  - Setlists with top-level tracks but EMPTY embedded tracks (post-v5.0-only)
  - Setlists with BOTH (split-brain candidates needing reconciliation)
And each bucket is reported with both count AND a sample of up to 5 setlist IDs
```

```gherkin

And each answer cites the specific count(s) from AC-2..AC-6 that drove it
```
