<objective>
## Goal
Close the v5.0 milestone by wiring Sentry alarms into the v50-03 + v50-06 +
v50-07-03 sync substrate (so silent failure paths become observable in
production), authoring the manual UAT test plan + smoke checklist Rabbi
Daniel + one band member will execute against real production, and shipping
the band onboarding doc + first-week monitoring playbook. Push to production.

## Purpose
Three things gate v5.0 milestone close:

1. **Observability.** v50-07-04's kitchen-sink proves invariants under
   chaos AT THE HARNESS LAYER. Production is the actual test bed. Sentry
   alarms on save-path failures (lazy-hydration fan-out, dead-letter rows,
   snapshot listener errors) turn the bulletproof claim into a measurable
   property in production: "if a failure mode fires, we see it within
   minutes; if Sentry is quiet for a week, the loop is whole."

2. **UAT.** The user's stated bar is "bulletproof and easy and intuitive
   before onboarding the band". Bulletproof is what the harness proves. Easy
   and intuitive is what UAT proves. The plan ships the test plan +
   checklist; UAT execution itself is post-plan (Rabbi Daniel + one band
   member exercising real production over 1–2 weekly cycles).

3. **Onboarding.** A short doc guiding Rabbi + band members through the new
   editor (open setlist, edit cells, bind charts, sync indicator semantics,
   what-to-do-if-something-looks-wrong) so the cutover is self-service from
   the band's side. First-week monitoring playbook tells the user (Rabbi
   Daniel as developer/owner) what each Sentry alert means and how to
   respond.

## Output
- New `src/lib/sync/sentry-capture.ts`: thin `captureSyncFailure(err, context)`
  helper that standardizes tags (feature, setlistId, op, collection,
  attempts) for every sync-substrate capture site
- Sentry capture wired at 6 silent-failure sites:
  - SetlistGridHydrator lazy-hydration fan-out catch (1 site)
  - engine.ts dead-letter transition (1 site at line 366)
  - snapshot-listener.ts setlist apply / tracks apply / setlist subscription
    error / tracks subscription error (4 sites)
- Unit tests for sentry-capture (proving captures flow through to the
  Sentry SDK with the right tags + level + extra context)
- New `.paul/phases/v50-07-migration-cutover/v50-07-05-UAT-PLAN.md`:
  weekly-workflow scenarios (clone last week, tweak songs, transpose, save)
  + per-scenario expected behavior + smoke checklist
- New `.paul/phases/v50-07-migration-cutover/v50-07-05-SHIP-CHECKLIST.md`:
  deploy verification steps + band onboarding doc (1-page user guide) +
  first-week monitoring playbook (which Sentry alerts mean what; rollback
  procedure)
- Pushed to `origin master`; Vercel auto-deploys
</objective>

```gherkin
Given the new src/lib/sync/sentry-capture.ts module
When a sync-substrate failure path calls captureSyncFailure(err, context)

  - the original error
  - tags: { feature: context.feature, ...stringified-context-fields }
  - extra: the full context object
  - level: 'error' for dead-letter / WriteAtomicityError; 'warning' for
    listener errors and lazy-hydration fan-out failures
And captures are no-ops in test mode (Sentry SDK uninitialized) — never throws
```
