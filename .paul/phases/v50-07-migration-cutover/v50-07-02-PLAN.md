<objective>
## Goal
Implement Option C (Hybrid Lazy Hydration) prerequisites for the data layer:
1. Patch the pre-existing MARKER_PATH bug in `migrate-v50.ts` so the migration
   script will actually run against real Firestore in any future apply.
2. Build a `scrub-livestate.ts` one-shot that strips the orphan `liveState`
   field from the 10 setlists carrying it (per v50-07-01 audit).
3. Apply the scrub against production with rollback snapshots.

## Purpose
Option C selected: lazy hydration in v50-07-03 will convert legacy setlists on
edit-open. Before that lands, two pieces of housekeeping must complete:

- **MARKER_PATH must work.** The migration script as written would crash on
  first apply against real Firestore — fix it so any future hand-rolled
  migration (e.g., a song-catalog bootstrap if priorities change) can run.
- **`liveState` orphan must go.** v50-02 deleted the code that consumed
  `liveState`; the field is dead weight on 10 setlists. Scrubbing now
  prevents future confusion (e.g., when v50-07-03 lazy hydration reads each
  setlist, it should see only fields the v5.0 model recognizes).

## Output
- `scripts/migrate-v50.ts` patched: `MARKER_PATH = 'system/v50Migration'`
  (2-segment doc path; previous 3-segment path was structurally invalid).
- Test fixtures updated to match.
- `scripts/scrub-livestate.ts` (new, ~150 LOC): dry-run + apply + rollback;
  reuses the `MigrationFirestore` interface pattern from `migrate-v50.ts`;
  per-setlist snapshot to `migrations/livestate-scrub/snapshot/{setlistId}`
  (4-segment doc path) before each `FieldValue.delete()` write; idempotency
  marker at `system/livestateScrub` (2-seg doc).
- Production scrub applied: 10 setlists' `liveState` field removed.
- Vitest unit tests for the scrub script (in-memory adapter; mirrors
  migrate-v50.test.ts patterns).
</objective>
