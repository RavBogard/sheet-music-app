## Goal

Close Issues 1 + 4 from v52-01 synthesis at the systemic root:

- **Issue 4 (kebab "red line" / unclickable on all platforms):** Remove the always-disabled kebab from `SetlistGridTopBar.tsx:61-75` (and its dead `onOverflow` prop + unused `MoreVertical` import). - **Issue 1 (red "Failed" SyncIndicator with no in-app recovery):** Wire `onRetryFailed` end-to-end so the failed-state SyncIndicator becomes a real action button. ## Purpose

v52-01 synthesis (Track B Q1/Q2/Q3 firming) confirmed:
- The `failed` FSM state is **terminal** with no auto-recovery (state-machine.ts:36-41 preserves it across all events).
- `SyncIndicator.onRetryFailed` is **never provided** in production code (the prop exists but the parent doesn't pass a handler), so the failed-state button is permanently disabled.
- v51-h01 added the visible inline lastError pill but no recovery affordance — making the indicator more honest about failure but more confusing about how to recover.
- The kebab in SetlistGridTopBar is hard-disabled (`disabled={!onOverflow}`, never receives the prop) and is the visual "red line" Daniel sees adjacent to the v51-h01 error pill.

Daniel's explicit ask: **systemic fixes, not bandaids**. v52-03 ships the recovery UX that v50-03 outboxes have always needed but never had a UI for. After this lands, the iPad red-Failed loop becomes self-healing without DevTools intervention.

Direct PROJECT.md value mapping: **"bulletproof and easy and intuitive" before onboarding band**. A persistent red Failed with no in-app recovery breaks both "bulletproof" (data sits stuck in outbox forever) and "intuitive" (user has no idea what to do).

        // for the terminal `failed` FSM state. Only deletes rows with
        // status === 'failed'; pending / sending rows are preserved
        // (in-flight work must not be lost).

        import { db as defaultDb, type LocalDb } from '@/lib/local/db'
        // ^^ Verify exact import path via Grep at apply-time;
        // src/lib/local/db.ts or src/lib/sync/db.ts depending on layout.

        export interface ClearFailedResult {
            removed: number
        }

        export async function clearFailedOutboxRows(
            options: { db?: LocalDb } = {}
        ): Promise<ClearFailedResult> {
            const db = options.db ?? defaultDb
            const failedRows = await db.outbox
                .where('status')
                .equals('failed')
                .toArray()
            for (const row of failedRows) {
                if (row.localId !== undefined) {
                    await db.outbox.delete(row.localId)
                }
            }
            return { removed: failedRows.length }
        }
