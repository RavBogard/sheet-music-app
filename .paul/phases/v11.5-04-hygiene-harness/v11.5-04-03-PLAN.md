## Key facts established at plan time (recon 2026-06-16)
- Monitor-bus assignments are NOT a uid-keyed collection. They live in the single
  `config/monitor` doc (`db.collection("config").doc("monitor")`, CRC-only — test
  accounts are crc-stamped) under `busAssignments: Record<string,
  BusAssignment | BusAssignment[] | null>`, keyed by **bus-index string**. Each
  `BusAssignment` carries `userId` (NOT `uid`). An empty slot is written as `null`
  (mirrors `BusAssignmentPanel`). So the H8 cascade must read the doc, walk the map,
  filter entries by `userId === uid`, null-out emptied slots, and write back —
  `deleteByQuery` does not apply.
- `create_test_account` today hardcodes the bearer token `orgId: DEFAULT_ORG_ID`
  (test-tokens.ts ~L272) and writes no org membership to the user doc/claims.
- Chunked TTL: `UPLOAD_SESSION_TTL_MS = 10*60*1000` (library-upload-session.ts L134)
  is shared by BOTH `request_chart_upload_url` (signed-URL, single PUT — 10 min is
  fine) and `beginChunkedChartUpload` (multi-chunk through MCP args — too tight).
- `checkRateLimit` is `async` (returns `Promise<NextResponse|null>`). The test mocks
  it with `mockReturnValueOnce(NextResponse.json(...))` → type error; should be
  `mockResolvedValueOnce`.
