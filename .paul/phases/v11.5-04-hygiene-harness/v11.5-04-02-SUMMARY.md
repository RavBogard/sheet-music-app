# Phase v11.5-04 Plan 02: Library hygiene (junk filter + ingestion guard) Summary

**One shared, browser-safe `isJunkLibraryRow` predicate now hides test/junk rows (`.DS_Store`, audio/office artifacts, orphaned/duplicate/archived, test-uid uploads) from the consumer library browse and the chart-bind picker, and the Drive-sync path no longer ingests non-chart artifacts into `library_index`. The MCP read tools keep identical behavior (the extracted predicate is the same code).**

| AC-1: Consumer browse hides junk | **Pass** | `getServerLibrary` filters each raw doc via `isJunkLibraryRow({name,mimeType,status,uploadedBy})` before the schema parse + before `maxModified` (counts/lastModified exclude junk). |

## Accomplishments

- Closed the run-3 finding that junk showed on consumer browse AND the bind-picker — both now filtered.
- Closed the **ingestion gap**: Drive sync historically only skipped folders, which is how `.DS_Store`/audio/office junk entered; now blocked at the source (HTTP/MCP upload already rejected them).
- Unified the junk definition across browser surfaces and MCP tools in one pure module (no drift).

## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| Extract predicate to pure module, library.ts delegates | Client component can't import library.ts (pulls firebase-admin → bundle break); single source of truth avoids browser/agent drift | Future consumer filters reuse junk-filter.ts |
| Bind-picker graceful degradation | Dexie `LocalSong` carries only title+status (no uploadedBy); adding a Firestore read just for the picker = scope creep | `[role-*]` test rows clear via Plan-03 deletion; browse (fully-fielded) is the primary gate |
| Thread `ingestFiles` (not a write-loop `continue`) | The copy phase calls `.update()` which fails on a non-existent row; junk must be excluded from copy+purge too | Junk never written, copied, or purge-scanned |
