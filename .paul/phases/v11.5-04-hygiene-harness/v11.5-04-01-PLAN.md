<objective>
## Goal
Close the two error-contract items of v11.5-04: **M-11** — `contact_not_found`
must carry HTTP-like `code: 404` (not the default 500); **M-10** — the
`publish_setlist` tool schema must document the D8 recipient-resolution
contract. Both are correctness/contract fixes on the MCP surface; no runtime
behavior change beyond the error code.

## Purpose
Agents (Daniel's authoring surface) branch retry-vs-fix on `error.code`. A
missing/cross-org contact returning 500 reads as "server bug, retry" when it is
actually "fix your id" (404). And `publish_setlist` is the live publish path —
its schema is the only contract an agent sees for how recipients resolve;
today it under-documents the ad-hoc vs uid vs audience-preset rules (D8).

## Output
- `ERROR_CODE_MAP` gains `contact_not_found: 404`.
- `publish_setlist` `description` + `recipients` `.describe()` document the D8 contract.
- An emulator test asserting the 404 on a missing-contact path.
</objective>

## AC-2: publish_setlist schema documents the D8 contract (M-10)
```gherkin
Given an agent inspects the publish_setlist tool schema

  an ad-hoc `{name, email}` (no account); `audience` preset applies ONLY when
  `recipients` is omitted; saved contacts (list_contacts/create_contact) are
  reused by passing them as `recipients[]` entries
  And publish_setlist runtime behavior is unchanged (doc-only edit)
```
