<objective>
## Goal
Phase 2 Plan 02 — Wizard + NamePrompt polish. Three ROADMAP items:

1. **Drop template step from "+ New" wizard.** Template picking stays accessible as a dropdown inside the Details step (preserving auto-population), but 90% of weekly flow ("just name it and go") skips the extra click-through. Enter key in name input triggers Create.
2. **Data-driven rabbi list in `OverflowMenu`.** Replace hardcoded `["Daniel", "Karen", "Randy"]` with `useCongregation().scheduling.rabbiProfiles` — the source the wizard's Details step already uses.
3. **Split `NamePrompt` / `EditDetails`.** Currently one modal with the title "Name Your Setlist" is reused for editing existing setlists via `isOpen={showNamePrompt || showEditDetails}`. Split into two modals so the edit path gets an honest title, a richer form (name + date + rabbi + notes), and a pre-populated layout suited to its context.

## Purpose
The weekly flow is: open app → clone last week OR "+ New" → tweak a few songs → publish. Anything that adds a click to that flow is friction on the happy path. Dropping the template step shaves one screen for the majority case. The hardcoded rabbi list is a landmine — adding or removing a rabbi today means a code push. Splitting the name-prompt modal removes confusing copy ("Name Your Setlist" for an already-named setlist) and unlocks future editor-only fields without polluting the create path.

## Output
- Single-step wizard (Details-only); Template picker becomes a dropdown inside Details; Enter in name field advances/creates
- `OverflowMenu` rabbi list sourced from congregation store with a fallback
- `NamePrompt` reduced to create-new (name + optional date)
- New `EditDetails` modal (name + date + rabbi + service notes); used only for the `showEditDetails` path
- Updated creation-wizard test to reflect single-step flow
- SUMMARY.md
</objective>
