<objective>
## Goal
Phase 2 Plan 03 — Dashboard + editor-navigation polish. Three independent ROADMAP items:

1. **Setlist list ordering: past desc.** `upcoming` already sorts ascending (soonest first). `pastOrNoDate` is unsorted — make it descending by `eventDate` so the most recently past setlist (often last week's clone source) is at the top; null-dated entries trail.
2. **Role-aware dashboard hero CTA.** Current hero always offers "Open Setlist" unless imminent (→ Perform). Musicians (non-band-leader) rarely edit — they want to play. Make the primary CTA `Perform` for musicians regardless of imminence; keep existing `isImminent ? Perform : Open` behavior for band leaders/admins.
3. **Referrer-based editor back button.** `SetlistEditorV2.handleBack` unconditionally routes to `/perform/setlist/{id}` (existing) or `/setlists` (new). If the user arrived from a different page (dashboard, schedule, perform view), go back there instead. Fallback to the current behavior when `document.referrer` is empty or off-origin.

## Purpose
Band lead's weekly flow lives on the dashboard; ordering and the hero CTA set the default action for musicians too. The back button bug is tiny but chronic — tapping "back" in the editor shouldn't teleport someone out of the schedule grid or library search they came from.

- `SetlistEditorV2.handleBack` tries `document.referrer` first, falls back to the current behavior

<task type="auto">
  <name>Task 3: Referrer-based back button in SetlistEditorV2</name>
  <files>sheet-music-app/src/components/setlist/v2/SetlistEditorV2.tsx</files>
  <action>
    Rewrite `handleBack` (around line 102) to honor `document.referrer`:

    ```
    const handleBack = useCallback(() => {
        if (onBack) return onBack()
        try {
            const ref = typeof document !== 'undefined' ? document.referrer : ''
            if (ref) {
                const refOrigin = new URL(ref).origin
                if (refOrigin === window.location.origin && ref !== window.location.href) {
                    router.back()
                    return
                }
            }
        } catch { /* malformed referrer — fall through to default */ }
        router.push(initialSetlistId ? `/perform/setlist/${initialSetlistId}` : "/setlists")
    }, [onBack, router, initialSetlistId])
    ```

    Notes:
    - Guards: `typeof document !== 'undefined'` for SSR; URL() may throw on malformed referrers; `refOrigin === window.location.origin` prevents leaving the app via back when arriving from email links or search engines; `ref !== window.location.href` prevents a no-op back-to-self loop when the editor is the sole history entry.
    - `router.back()` uses the browser history stack, which honors the actual in-app path; the referrer check is just a same-origin gate so we don't router-back into garbage.
    - The `onBack` escape hatch (caller-provided) is preserved — test harnesses and any specific routing that wants to override the default still works.
  </action>
