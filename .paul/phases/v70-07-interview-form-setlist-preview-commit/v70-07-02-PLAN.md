<objective>
## Goal
Add a "Document" import path to `ImporterModal`: a third input option that uploads
a .docx/.pdf/.txt service-outline doc, chains the v70-04→05→06 extract pipeline
(`extract-document` → `extract-structure` → `resolve`), then walks the user through
a structured interview form (parser-unfillable metadata) and a read-only setlist
preview that surfaces resolved chart matches, missing charts, and recording
candidates. Stops at the preview — the commit/persist step is plan 03.

## Purpose
This is the user-facing surface of v7.0's headline feature: "Feed a doc, get a
setlist." v70-04/05/06 built the backend chain (text → AI structure → library
resolution) with zero UI. This plan makes it usable: Daniel can upload the May 15
Shir Shabbat doc and see a fully-resolved setlist proposal with gaps flagged —
without leaving the existing import modal.

## Output
- `ImporterModal.tsx` — new "Upload Document" input option + `interview` and
  `preview` steps; the extract→structure→resolve client chain.
- `src/lib/setlist-import/interview-defaults.ts` — pure helpers: parse a service
  date from a filename, infer a service type from document keywords.
- Unit tests for the new helpers.
</objective>

<acceptance_criteria>

## AC-1: Document upload runs the extract→structure→resolve chain
```gherkin
Given the ImporterModal is open on the input step
When the user selects a .docx / .pdf / .txt file under the "Upload Document"
  option and submits
Then the modal POSTs the file to /api/setlists/import/extract-document,
  feeds the returned text to /api/setlists/import/extract-structure, feeds the
  returned { sections, tracks } to /api/setlists/import/resolve, stores the
  resolved structure plus the original filename in state, and advances to the
  interview step
And if any step fails (network, 4xx/5xx, or a 422 malformed-extraction), a
  toast surfaces the server's error message and the modal returns to the input
  step
```

## AC-2: Interview form collects parser-unfillable metadata
```gherkin
Given the extract chain succeeded and the interview step is showing
When the interview step renders
Then it shows a structured form (NOT a chat) with: a setlist name field, a
  REQUIRED service date pre-filled by parsing the uploaded filename, a service
  type select pre-selected by inferring from the document text (date-based
  inference as fallback), and an optional rabbi field
And the "Next: Preview" action is disabled until a service date is set
```

## AC-3: Preview shows the resolved setlist with gaps surfaced
```gherkin
Given the interview form has a service date set
When the user advances to the preview step
Then the setlist renders grouped by section in document order, as max-density
  text rows (no cover art), each track row showing title / key / vocal lead and
  a chart-status indicator that is either the matched library chart (name +
  confidence) or an amber "missing chart" flag, plus a marker when the track has
  recording candidates
And a header reflects the interview values (name, date, service type)
And a "Create Setlist" action is present but inert — it is wired to the commit
  route in plan 03
```
