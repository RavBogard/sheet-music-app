<objective>
## Goal
Org-scope BOTH template collections so a tenant sees/edits only its own templates,
with CRC provably unchanged and zero CRC data migration:
- `setlistTemplates` (MCP/admin): filter `list_templates` by caller org, stamp
  `orgId` on create, and wall cross-tenant `get/update/delete/clone-from-template`
  behind a not-found error (no `cross_tenant_denied` leak).
- `templates` (client liturgical slot overrides): namespace the doc-id by org so two
  tenants can't collide on the same liturgical key; CRC keeps the bare key (no
  migration), non-CRC orgs use `${org}__${key}`.

## Purpose
Closes the v11-02-02 templates deferral. Templates are an authoring surface
(MCP-first per the project pivot); cross-tenant template visibility is a tenant-
correctness break that the v11-06 isolation audit will gate on. Mirrors the proven
v11-02-03 MCP write-scoping pattern (`orgFrom`/`rowOrg` + not-found wall).

## Output
- `setlistTemplates` reads/writes org-scoped via `orgFrom(extra)`/`rowOrg(doc.orgId)`.
- `templates` reads/writes namespaced per org (CRC = bare key, others = `${org}__key`).
- `setlistTemplates` backfill (existing docs → `orgId='crc'`) with dry-run + rollback.
- Emulator-backed scoping test proving BL cannot see/touch a CRC template and vice-versa.
- SUMMARY at `.paul/phases/v11-05-collection-scoping/v11-05-01-SUMMARY.md`.
</objective>

<acceptance_criteria>

## AC-1: setlistTemplates list is org-scoped
```gherkin
Given a CRC template and a Brothers Lazaroff (BL) template exist in setlistTemplates
When a BL bearer calls list_templates (no ownerUid/templateType filter)
Then only the BL template is returned, and the CRC template is absent
And when a CRC bearer calls list_templates the CRC template is present and the BL one absent
```

## AC-2: cross-tenant setlistTemplate access hits a not-found wall
```gherkin
Given a CRC template with id T_crc
When a BL bearer calls get_template / update_template / delete_template /
     clone_setlist_from_template with templateId = T_crc
Then the call returns the template_not_found error (NOT cross_tenant_denied, no leak)
And T_crc is unmodified
```

## AC-3: create stamps caller org
```gherkin
Given a BL bearer
When it calls create_template_from_setlist (or create_template)
Then the new setlistTemplates doc carries orgId = "brotherslazaroff"
And a subsequent BL list_templates includes it while a CRC list_templates does not
```

## AC-4: client `templates` overrides are org-isolated, CRC unmigrated
```gherkin
Given CRC has a custom liturgical override saved under doc-id "shabbat_morning"
When a BL session saves an override for the same liturgical key
Then it is written to doc-id "brotherslazaroff__shabbat_morning" (CRC's bare-key doc untouched)
And useCustomTemplates for a BL session never surfaces CRC's "shabbat_morning" override
And a CRC session continues to read/write the bare "shabbat_morning" doc-id exactly as before
```

## AC-5: backfill is safe and idempotent
```gherkin
Given existing setlistTemplates docs without an orgId field
When the backfill runs in dry-run
Then it reports the count of unstamped docs and writes nothing
When the backfill runs with --apply
Then every legacy doc is stamped orgId="crc" with an idempotency marker, re-runnable as a no-op
And a documented rollback path exists
```
