<objective>
## Goal
Org-scope the `users` roster so a tenant's musician list shows only its own
members, supporting MULTI-ORG membership (a person can belong to several orgs):
- Mirror the `orgIds[]` auth claim onto `users/{uid}.orgIds` at the existing
  sync-claims seam (keeps the queryable field in sync on every sign-in).
- Filter the cross-tenant roster reads — `list_musicians`, MCP `suggest_band`,
  and `/api/scheduling/suggest-band` — by `where('orgIds','array-contains',callerOrg)`.
- Script (deferred to phase-close, run with the other backfills): backfill
  `orgIds[]` onto all user docs from their claims, and fix David's claim to
  `['crc','brotherslazaroff']` so he stays in CRC's roster AND appears in BL's.

## Purpose
Closes the v11-02-02 roster deferral. `list_musicians`/`suggest_band` currently
return EVERY org's musicians (roster.ts:206, suggest-band route:37) — a cross-tenant
exposure. Multi-org membership is now real (David leads at CRC and runs BL), so the
filter must be `array-contains`, and the membership source is the auth claim
(mirrored to the doc for queryability — Daniel decisions 2026-06-09).

## Output
- `users/{uid}.orgIds` kept in sync from claims at sign-in; roster reads org-filtered.
- Backfill + David-claim-fix scripts (run at phase close, dry-run first).
- Emulator proof that a tenant's roster excludes other tenants' musicians, and a
  multi-org member appears in BOTH.
- SUMMARY at `.paul/phases/v11-05-collection-scoping/v11-05-02-SUMMARY.md`.
</objective>

## AC-1: orgIds claim is mirrored onto the user doc at sync
```gherkin
Given a user whose auth claim carries orgIds=['crc','brotherslazaroff']
  and whose users/{uid} doc has a stale/absent orgIds field
When that user hits the sync-claims route (sign-in)
Then users/{uid}.orgIds is written to ['crc','brotherslazaroff']
And a user already in sync triggers no write (idempotent)
And a claimless user resolves to ['crc'] (getOrgIdsFromClaims default) on the doc
```

## AC-2: roster reads are org-scoped via array-contains
```gherkin
Given a CRC musician, a BL musician, and David (orgIds ['crc','brotherslazaroff'])
When a CRC caller runs list_musicians / suggest_band
Then the result includes the CRC musician AND David, and EXCLUDES the BL-only musician
And when a BL caller runs them, the result includes the BL musician AND David, and EXCLUDES the CRC-only musician
```

## AC-3: legacy unstamped user docs are not silently dropped from CRC
```gherkin
Given the backfill stamps orgIds=['crc'] on every claimless user doc (and David → ['crc','brotherslazaroff'])
When the backfill runs in dry-run
Then it reports counts and writes nothing
When run with --apply
Then every claimless user carries orgIds=['crc'] (idempotent re-run), so CRC's roster is unchanged after the filter goes live
```

## AC-4: David's claim fix keeps him in CRC

```gherkin
Given David's auth claim is currently orgIds=['brotherslazaroff'] only

And he appears in BOTH CRC and BL list_musicians
```
