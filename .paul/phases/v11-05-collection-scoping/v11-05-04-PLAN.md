<objective>
## Goal
Make the `config/congregation` singleton per-org so each tenant gets its own
congregation identity (name, shortName, location, printFooter, scheduling
config, features). CRC keeps the bare `config/congregation` doc id (ZERO
migration, byte-identical); other orgs use `config/congregation__{orgId}`
(e.g. `config/congregation__brotherslazaroff`). Reads resolve the doc id from
the caller/host org; a missing per-org doc gracefully falls back to defaults.

## Purpose
The congregation doc drives app chrome (name/shortName via the client
`congregation-store`), print footers, scheduling (rabbiProfiles), and the MCP
`get_congregation_context` tool. Today every tenant reads the single CRC doc →
BL surfaces show "Central Reform Congregation". This is the last shared-singleton
in v11-05; closing it unblocks v11-05-05 (CreationWizard/vocab, which needs an
org-scoped congregation) and the v11-06 isolation audit.

## Output
- `congregationDocId(org)` helper (crc → 'congregation', else 'congregation__{org}').
- All server reads + the client store + the MCP tool resolve the per-org doc.
- A seeded `config/congregation__brotherslazaroff` doc (BL identity, band vocab).
- `v11-05-04-SUMMARY.md`.
</objective>
