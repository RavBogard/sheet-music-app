# Phase v11.4-02 Plan 01: Org-branded comms (D8 item 4) Summary

**Publish, gig-packet, and resend emails now brand by the publishing setlist's org — Brothers Lazaroff emails read "Brothers Lazaroff" (BL from-name, dark-teal header, wordmark image, BL footer) while CRC's emails stay byte-identical. Branding is sourced from `rowOrg(setlist.orgId)` on all four send paths; the BL from-address is env-overridable with a verified-sender fallback so sends never break before the BL domain is verified in Resend. All gates green.**

## Accomplishments

- **`branding.ts`:** new `EmailBranding` type + `EMAIL_BRANDING` registry + `getEmailBranding(org)`, kept deliberately separate from the browser-chrome `OrgBranding` (whose `themeColor` differs from the email header) so CRC's email strings stay byte-identical. CRC = today's hardcodes; BL = its name/teal-header/wordmark/footer.
- **`email.ts`:** `sendSetlistEmail`/`emailAllMembers`/`buildSetlistEmailHtml` are org-aware via an optional `org` (default crc). from-name + header bg + footer + optional wordmark image derive from `getEmailBranding`; the header image uses an absolute URL (`getOrgBranding(org).baseUrl + path`). `getFromEmail(org)` resolves a per-org sender with a shared verified fallback. Buttons, body, song table, subject logic, and the rate-limit spacing are untouched.
- **4 send paths threaded:** MCP `publishSetlist` (`setlistOrg`), `/api/setlist/publish`, `/api/setlist/resend-email`, `/api/setlist/email-packets` (each `rowOrg(setlist.orgId)`). Pure org-threading — no auth/validation/rate-limit change.
- **Tests:** new `email.test.ts` (HTML builder crc-byte-identical vs BL-branded + from-line via a mocked Resend) and 3 `getEmailBranding` cases in `branding.test.ts`.

## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| Separate `EMAIL_BRANDING` registry | CRC email header `#1a1a2e` ≠ `OrgBranding.themeColor` `#0e0d18`; reusing the chrome seam would change CRC's email | CRC byte-identical guaranteed; email concerns isolated |
| Org from the setlist, not the request host | A BL setlist must email BL-branded regardless of which surface/host triggered the send; matches v11.2-02 audience scope | Correct + surface-independent; every send path already loads the setlist |
| BL from-address env-gated w/ verified fallback | brotherslazaroff.live isn't a verified Resend sender yet; hard-coding it would break BL sends | from-NAME always brands; flip `RESEND_FROM_EMAIL_BROSLAZ` later = zero code change (ops follow-up → UAT) |
| Header-image string owns its leading `\n      ` | Guarantees the empty (crc) branch produces no stray whitespace → byte-identical | Safe template conditional |
