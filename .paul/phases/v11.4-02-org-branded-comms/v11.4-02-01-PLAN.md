<objective>
## Goal
Make publish notification emails AND gig-packet (personalized packet) emails carry the
**publishing setlist's org branding** — from-name, header, footer, and (for orgs that have
one) a wordmark image — so a Brothers Lazaroff publish reads as "Brothers Lazaroff", not
"CRC Music". CRC's emails stay **byte-identical** (D8 item 4).

## Purpose
v11.4 makes publish/notify explicit and leader-driven; D8 item 4 closes the last
multi-tenant gap on the comms surface: today every email is hardcoded "CRC Music <…
@centralreform.live>" with a CRC header/footer, so a BL band member who gets a setlist
email sees the wrong congregation's brand. Branding must follow the SETLIST'S org (the
tenant being published), which every send path already loads.

## Output
- `branding.ts`: a per-tenant `EmailBranding` registry + `getEmailBranding(org)` (CRC values
  reproduce today's hardcoded strings exactly → byte-identical).
- `email.ts`: `sendSetlistEmail` / `emailAllMembers` / `buildSetlistEmailHtml` become
  org-aware (optional `org`, default `crc`); from-name + header + footer + optional wordmark
  derive from `getEmailBranding`; from-address is per-org env-overridable with a safe shared
  fallback.
- 4 call sites pass the setlist's org (`rowOrg(setlist.orgId)`).
- Unit tests: CRC byte-identical snapshot + BL branded assertions.
</objective>
