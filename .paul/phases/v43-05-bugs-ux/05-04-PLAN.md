<objective>
## Goal
Close audit finding **U02** — sticky `AddBar` (bottom-[72px]) on the setlist editor must hide when the mobile keyboard is open, so the "+ Add Item" bar doesn't overlap inputs the user is typing into (service notes, title rename, inline track edits) on iPhone/iPad portrait.

## Purpose
Musicians and leaders on iPad with the on-screen keyboard currently get a floating "+ Add Item" button covering whatever input they tapped. Core weekly workflow (editing the setlist) regresses on mobile — band-onboarding blocker.

## Output
- AddBar accepts the visualViewport hide pattern already used by MobileTabBar
- Unit test covering show/hide behavior via visualViewport mock
- `05-04-SUMMARY.md`
</objective>

## AC-1: AddBar hides when soft keyboard opens
```gherkin
Given the setlist editor on a mobile viewport with AddBar visible
When the user focuses a text input and the visualViewport height drops below 75% of window.innerHeight
Then AddBar is hidden (display:none via `hidden` class)
And nothing else on the page reflows unexpectedly
```

## AC-2: AddBar restores when keyboard closes
```gherkin
Given AddBar is hidden because the keyboard is open
When the user blurs the input and visualViewport height returns to full
Then AddBar is visible again at its sticky position
```

## AC-3: Non-mobile environments unaffected
```gherkin
Given a browser without window.visualViewport (SSR, older desktop)
When the component mounts
Then AddBar renders normally and never hides (effect is a no-op)
```

## AC-4: No regression on existing dropdown behavior
```gherkin
Given AddBar is visible
When the user taps "+ Add Item"
Then the dropdown opens with all 5 existing items (Song, Section Header, Reading, Prayer, Transition, Stage Note)
```
