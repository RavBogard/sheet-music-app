<objective>
## Goal
Close B01 from the v4.3 audit. Musicians currently get zero feedback when user-initiated writes fail silently (quota, network, permission). This plan introduces one shared `reportSaveError(err, action)` helper and wires it into seven `.catch(() => {})` sites on user-visible paths.

## Purpose
The v4.2 milestone explicitly targeted "bulletproof and easy and intuitive" before band onboarding. A musician adjusting transposition, editing a track, sending a monitor command, marking a notification read, or tweaking metronome speed should see an error toast if the write doesn't land — not have the UI behave as if it succeeded.

## Output
- `src/lib/save-error.ts` exports `reportSaveError(err, action, opts?)` → logs + `toast.error("Couldn't save ${action}")`
- Seven call sites migrated from `.catch(() => {})` to `.catch(reportSaveError.bind(null, ..., 'action label'))`
- Unit tests for the helper (no mocking toast globally — the helper calls `toast.error` via `sonner`, test verifies delegate)
- tsc clean, full suite green, next build green

## Non-goals
- Does NOT touch the ~20 `.catch` sites that are legitimately silent (server loads with null fallback, fire-and-forget background sync, cache-check reads, monitor retry loops)
- Does NOT add retry logic
- Does NOT change write semantics (success paths untouched)
</objective>

    Create `src/lib/save-error.ts`:
    ```ts
    import { toast } from "sonner"
    import { logger } from "@/lib/logger"

    export interface ReportSaveErrorOpts { silent?: boolean }

    export function reportSaveError(err: unknown, action: string, opts?: ReportSaveErrorOpts): void {
        logger.warn(`[save] ${action} failed:`, err)
        if (!opts?.silent) {
            toast.error(`Couldn't save ${action} — try again`)
        }
    }
    ```
    Test file mocks `sonner` and `logger`:
    - With opts.silent=true → no toast call, logger.warn called
    - Default → toast.error called with expected string, logger.warn called
    - Returns undefined
