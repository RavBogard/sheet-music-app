  <name>Task 1: Fix memory leaks in alert-store and congregation-store</name>
  <files>src/lib/alert-store.ts, src/lib/congregation-store.ts</files>
  <action>
    **alert-store.ts**: The `onSnapshot` listener is created but never unsubscribed. The `initialized` flag prevents re-init but there's no cleanup path.
    
    Fix: Store the unsubscribe function and expose a `destroy()` method:
    1. Add `unsubscribe` to the store state (not exposed publicly — internal)
    2. In `init()`, capture the return of `onSnapshot` (it returns an unsubscribe fn)
    3. Add a `destroy()` method that calls unsubscribe and resets `initialized`
    4. Also make `init()` return the unsubscribe fn (matches congregation-store pattern)
    
    **congregation-store.ts**: Already returns `unsub` from `init()` but the `isInitialized` flag is never reset on cleanup, preventing re-initialization.
    
    Fix: When unsub is called, also reset `isInitialized`:
    1. Wrap the returned unsub in a function that also sets `isInitialized: false`
    2. This allows the store to re-initialize if needed (e.g., after auth change)
  </action>
  <verify>npx tsc --noEmit; grep "unsubscribe\|destroy\|unsub" src/lib/alert-store.ts</verify>
  <done>AC-1, AC-2 satisfied: Both stores clean up listeners properly</done>
</task>
