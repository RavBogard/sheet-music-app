<objective>
## Goal
Make the two self-service MCP token-mint paths stamp the token's `orgId` from
the minting user's `orgIds` custom claim (default crc when absent), so a non-CRC
tenant member (e.g. David) who self-mints or runs Claude Desktop's OAuth flow
gets a correctly-scoped bearer — and onboards exactly like Daniel does (log in →
connected), with no manual raw-token handoff.

## Purpose
Daniel surfaced (2026-06-08) that `/api/mcp/tokens` and `/api/mcp/oauth/token`
both call `createMcpToken(uid, label)` with no org arg, hard-defaulting the token
to `crc`. Since caller org is resolved FROM the token doc (v11-02-01 decision),
a BL member self-minting would land in CRC's tenant — a latent cross-tenant
mis-scope. This closes the gap so self-service onboarding is org-correct.

## Output
- `getPrimaryOrgForMinting(uid)` in `src/lib/org/membership.ts` (thin wrapper
  over the existing `getUserOrgIds`).
- Both mint routes pass the resolved org as `createMcpToken`'s 3rd arg.
- Unit test for the resolver + emulator test proving claim→token-org end-to-end.
- Deployed to prod; David's existing manual bearer keeps working.
</objective>
