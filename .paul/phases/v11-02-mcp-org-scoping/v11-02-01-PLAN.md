<objective>
## Goal
Plumb the caller's tenant (`orgId`) from the MCP bearer token through to every
tool handler's execution context — **behavior-neutral** (everything resolves to
`crc`). This is the resolution spine the rest of v11-02 (read filtering, write
stamping, David's bearer) builds on. After this plan, every `/api/mcp` request
carries a resolved `orgId` in `AuthInfo.extra`, readable by any handler via a
single `orgFrom(extra)` helper, and every existing prod bearer is backfilled to
`orgId: "crc"`.

## Purpose
v11.0 makes the app multi-tenant. The MCP server is Daniel's (and soon David's)
PRIMARY authoring surface, so the tenant a caller acts in MUST be resolvable on
every tool call before any read can be filtered or any write stamped (v11-02-02 /
v11-02-03). Resolving org from the **bearer token** (not per-request Auth claims)
makes a bearer the unit of authoring identity: David's Brothers Lazaroff bearer
always acts as BL; Daniel's CRC bearer always acts as CRC — with zero extra
Firestore reads (verifyBearer already reads the token doc).

## Output
- `verifyBearer` returns a resolved `orgId` (default `crc` when the token doc has
  no `orgId` field — backward-compat, mirrors v11-01 `.get('orgIds',[])`).
- All 4 `mcpTokens` mint sites stamp `orgId` (minted children inherit the caller's
  org; everything else defaults `crc`).
- `orgFrom(extra)` helper in `src/lib/mcp/org-context.ts`, exported + unit-tested,
  ready for v11-02-02/03 to consume.
- Idempotent prod backfill stamping `orgId: "crc"` on every existing `mcpTokens`
  doc, run via a `.mjs` runner (dry-run inspected, then `--apply`).
</objective>

