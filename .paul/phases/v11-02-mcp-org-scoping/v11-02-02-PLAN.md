<objective>
## Goal
Org-scope every MCP **read** over the five tenant collections so a caller only
ever sees their own tenant's data. A CRC bearer sees only CRC; a Brothers
Lazaroff bearer sees only BL (empty today); cross-tenant reads are a hard wall.
This is the security-critical core of v11-02 — once BL data exists, an unscoped
read is a data-leak-class bug (milestone constraint 3).

## Purpose
MCP tools run on the Admin SDK, which **bypasses Firestore rules** — so the
v11-01-04 rules are NOT a backstop for MCP reads. The application layer is the
ONLY control. v11-02-01 made the caller's `orgId` resolvable via `orgFrom(extra)`;
this plan consumes it to filter/verify every read so David's BL authoring never
surfaces CRC's library/setlists and vice-versa.

## Output
- The 5 read tools over stamped collections are org-scoped:
  list_setlists, get_setlist, search_library, get_song, list_library,
  search_chart_text.
- Shared read helpers (`getAllSongs`/`getSongById`/`getAllSetlists`) surface
  `orgId` additively (non-breaking for app/print callers).
- Two scoping patterns: **list/search → filter to callerOrg**; **get-by-id →
  verify doc.orgId === callerOrg, else not-found** (hard cross-tenant wall).
- Emulator test proving CRC↔BL isolation across all 6 tools.
</objective>
