<objective>
## Goal
Turn the raw document text produced by v70-04's `extractDocumentText` into a
Zod-validated structured setlist shape `{ sections[], tracks[] }` via Gemini,
behind a new `POST /api/setlists/import/extract-structure` route. Malformed or
unparseable Gemini output is surfaced as a typed, human-reviewable failure —
never a crash.

## Purpose
This is Wave 3's core slice of the v7.0 "feed a doc, get a setlist" pipeline.
v70-04 shipped raw-text extraction; v70-05 adds the AI structure pass.
Downstream, v70-06 resolves `tracks` against the library + recordings, and
v70-07 builds the interview form + commit on top of this output. Backend slice
only — no UI (the ImporterModal "Document" option lands in v70-07).

## Output
- `src/lib/setlist-import/extract-structure.ts` — `extractSetlistStructure(text)`
  + the `SetlistStructure` Zod schema; discriminated never-throws result.
- `POST /api/setlists/import/extract-structure` — JSON route, sibling of
  `import/extract-document` + `import/parse` + `import/execute`.
- Unit tests mirroring `extract-document.test.ts` (mocked Gemini).
</objective>

<acceptance_criteria>

## AC-1: Well-formed Gemini output → validated structure
```gherkin
Given raw setlist document text and a Gemini response that is valid JSON
  matching the SetlistStructure schema (possibly wrapped in markdown ```json fences)
When extractSetlistStructure(text) runs
Then it returns { ok: true, sections, tracks } with sections and tracks parsed
  through the Zod schema, and each track carries title plus optional
  key / vocalLead / sectionName / referenceLink / notes fields
```

## AC-2: Malformed Gemini output → typed human-reviewable failure
```gherkin
Given a Gemini response that is not valid JSON, OR valid JSON that fails
  Zod validation, OR an empty/whitespace response
When extractSetlistStructure(text) runs
Then it returns { ok: false, reason: 'malformed' } (or 'empty') with a
  human-readable message AND the raw Gemini output string, so a human can
  review what the model actually produced — and extractSetlistStructure
  never throws
```

## AC-3: Gemini/config errors → typed failure, not a crash
```gherkin
Given the Gemini API key is missing OR the Gemini call throws/rejects
When extractSetlistStructure(text) runs
Then it returns { ok: false, reason: 'gemini_error' } with the underlying
  message, and never throws
```

## AC-4: The route wraps the lib with validation + error mapping
```gherkin
Given an authenticated POST to /api/setlists/import/extract-structure
When the request body is { text: string }
Then a successful extraction returns 200 { success: true, sections, tracks };
  a malformed/empty extraction returns 422 { error, raw }; a missing/blank
  text body returns 400; gemini_error returns 502; and an unauthenticated
  request is rejected by createApiHandler before the lib is reached
```

<task type="auto">
  <name>Task 1: Create extract-structure lib with Zod schema and Gemini call</name>
  <files>src/lib/setlist-import/extract-structure.ts</files>
  <action>
    Create the structured-extraction lib, following extract-document.ts's
    discriminated-never-throws shape.

    1. Define the Zod schema `SetlistStructureSchema`:
       - `sections`: array of `{ name: string, order: number }`
       - `tracks`: array of `{ title: string, key?: string, vocalLead?: string,
         sectionName?: string, referenceLink?: string, notes?: string,
         order: number }`
       Export the inferred type `SetlistStructure`.
       Use `.optional()` for the optional fields (NOT `.nullable()`) and make
       the prompt instruct Gemini to OMIT unknown fields rather than emit null —
       but ALSO accept null defensively by `.nullish()` on the optional fields,
       since Gemini commonly emits null. Normalize null → undefined after parse.

    2. Define the discriminated result type `StructureResult`:
       - `{ ok: true; sections; tracks }`
       - `{ ok: false; reason: 'malformed' | 'empty' | 'gemini_error';
            message: string; raw?: string }`
       The `raw` field carries Gemini's raw output on 'malformed'/'empty' so a
       human can review it (the "surfaces for human review" requirement).

    3. Implement `extractSetlistStructure(text: string): Promise<StructureResult>`:
       - If `text.trim()` is empty → `{ ok: false, reason: 'empty', message }`.
       - Call Gemini via `geminiFlash()` from `@/lib/gemini` (reuses the
         chord-detection model setup — gemini-3-flash-preview). Wrap the whole
         Gemini call (model construction + generateContent) in try/catch →
         `{ ok: false, reason: 'gemini_error', message }`. Note: `geminiFlash()`
         itself throws if `GOOGLE_GENERATIVE_AI_API_KEY` is unset — that throw
         must be caught here too.
       - Use `generationConfig: { temperature: 0.1 }` (matches import/parse).
       - Prompt: instruct Gemini it is a setlist-structure parser; given raw
         document text, return a JSON object with exactly two root keys
         `sections` and `tracks`. Describe each field. Critically: use the term
         "Vocal Lead" for the lead vocalist field (per project terminology —
         never "Lead"/"Leader"). Tell it to assign each track a `sectionName`
         matching one of the section names when the doc groups songs under
         headings, to preserve document order via the `order` integers, and to
         omit fields it cannot determine.
       - Strip markdown fences from the response exactly like import/parse does
         (`.replace(/```json/g,'').replace(/```/g,'').trim()`), then
         `JSON.parse` inside try/catch. Parse failure → `{ ok: false,
         reason: 'malformed', message, raw: <gemini text> }`.
       - Run the parsed object through `SetlistStructureSchema.safeParse`. On
         failure → `{ ok: false, reason: 'malformed', message: <zod summary>,
         raw: <gemini text> }`.
       - On success, normalize any null optional fields to undefined and return
         `{ ok: true, sections, tracks }`.

    Avoid: throwing for any expected failure mode (empty/malformed/gemini_error
    are all returned, never thrown) — the route depends on this so it needs no
    try/catch sprawl, exactly like extract-document.ts. Do NOT touch Firestore,
    the library, or recordings — resolution/matching is v70-06's job.
  </action>
  <verify>npx tsc --noEmit (lib typechecks); schema + result type exported</verify>
  <done>AC-1 / AC-2 / AC-3 satisfied: extractSetlistStructure returns a typed
    discriminated result for well-formed, malformed, empty, and gemini-error
    inputs and never throws</done>
</task>

<task type="auto">
  <name>Task 2: Create the extract-structure API route</name>
  <files>src/app/api/setlists/import/extract-structure/route.ts</files>
  <action>
    Create `POST /api/setlists/import/extract-structure` as a sibling of
    `import/extract-document` and `import/parse`.

    - Use `createApiHandler` from `@/lib/api-wrapper` with a Zod `schema` of
      `z.object({ text: z.string() })` (the wrapper validates the body and
      exposes it as `ctx.body`). Default auth (no `role` gate) — matches
      import/parse + import/extract-document ("any authenticated user").
    - `export const maxDuration = 60` (Gemini calls are slow — matches
      import/parse + import/extract-document).
    - Apply `checkRateLimit(ctx.req, 'upload')` first (same as the sibling
      routes), returning its response if limited.
    - Read `text` from `ctx.body`. If `!text || !text.trim()` → 400
      `{ error: 'No text provided' }` (defensive — schema allows empty string).
    - Call `extractSetlistStructure(text)`.
    - Map the result:
      - `ok: true` → 200 `{ success: true, sections, tracks }`
      - `ok: false, reason: 'gemini_error'` → 502 `{ error: result.message }`
      - `ok: false, reason: 'malformed' | 'empty'` → 422
        `{ error: result.message, raw: result.raw }` (raw included so the
        client/human can review the model output)
    - Do NOT add a try/catch around extractSetlistStructure — it never throws.

    Avoid: a `role` gate (parse + extract-document have none); creating a new
    route namespace (must be a sibling under /api/setlists/import/).
  </action>
  <verify>npx next build — route compiles and appears as
    `ƒ /api/setlists/import/extract-structure` in the route list</verify>
  <done>AC-4 satisfied: the route validates the body, rate-limits, calls the
    lib, and maps ok/malformed/empty/gemini_error to 200/422/422/502</done>
</task>
