<objective>
## Goal
Add destructive action confirmations (SwipeToDelete, role change), unsaved changes warning for template editor, maxDuration for scheduling-reminder cron, and error handling for notification mutations.

## Purpose
Musicians using the app during live services can accidentally delete tracks or lose template edits. Admins can accidentally change roles. These are the UX safety issues from the v3.1 bugsweep.

## Output
5 files hardened with confirmation dialogs, unsaved changes guard, cron config, and error handling.
</objective>

<acceptance_criteria>

## AC-1: SwipeToDelete shows confirmation before deleting
```gherkin
Given a user swipes a track past the delete threshold
When the swipe completes
Then a confirmation dialog appears before onDelete() is called
And the user must explicitly confirm to proceed with deletion
```

## AC-2: Role change requires confirmation
```gherkin
Given an admin changes a user's role via the dropdown
When a new role is selected
Then a confirmation dialog shows the old and new role
And the role only changes after explicit confirmation
```

## AC-3: Template editor warns about unsaved changes
```gherkin
Given the template editor has unsaved changes (dirty state)
When the user navigates away or closes the browser
Then a beforeunload warning is shown
```

## AC-4: scheduling-reminder has maxDuration
```gherkin
Given the scheduling-reminder cron route
When it processes many assignments
Then it has sufficient maxDuration to complete without timeout
```

## AC-5: Notification mutations have error handling
```gherkin
Given a notification mutation (markAsRead, markAllAsRead, createNotification)
When the Firestore write fails
Then the error is logged and handled gracefully
```

</acceptance_criteria>

  <files>src/components/setlist/v2/SwipeToDelete.tsx, src/components/admin/UserRow.tsx, src/app/(main)/manage/templates/TemplateEditor.tsx</files>
  <action>
    **SwipeToDelete.tsx**: Instead of calling `onDelete()` directly when swipe threshold is met, set a `pendingDelete` state flag. Show a small inline confirmation (e.g., "Tap to confirm" text that appears, or use the existing AlertDialog). The simplest approach: add a `confirmDelete` state. When swipe threshold met, set `confirmDelete = true` and show a confirmation UI. On confirm, call `onDelete()`. On cancel, reset position.
    
    Check how AlertDialog is used elsewhere in the codebase and follow the same pattern. If the component is too minimal for a full dialog, use a simpler approach (e.g., require a second tap).
    
    **UserRow.tsx**: Wrap the `handleRoleChange` call in the Select's `onValueChange` with an AlertDialog confirmation. Store the pending role in state, show dialog with "Change [name]'s role from [old] to [new]?", then execute on confirm.
    
    **TemplateEditor.tsx**: Add a `useEffect` with `beforeunload` listener that checks the `dirty` state. When dirty is true and user tries to leave, show browser's native "unsaved changes" warning.
  </action>
