<objective>
## Goal
Make every server-side CREATE path stamp `orgId` on the docs it writes, defaulting to
`DEFAULT_ORG_ID` ("crc"), so all NEW writes carry tenant scope. Backward-compatible: every
current caller omits orgId and gets "crc", so CRC behavior is unchanged.

## Purpose
Strict org-scoped Firestore rules (v11-01-04) can only require `orgId` once BOTH existing
data is stamped (v11-01-03 backfill) AND new writes emit it (this plan). Without this, a
strict create-rule would reject every CRC write → lock-out. This plan + the backfill are
the two preconditions for safely deploying enforcement.

## Output
orgId stamped at all 5 server create sites + an emulator-backed test proving it.
</objective>

## Key design decisions (baked in — engineering calls within ratified scope)
- **orgId SOURCE in v11-01:** all CRC writes default to `DEFAULT_ORG_ID` ("crc"). The
  orgId param is OPTIONAL on each create function; existing callers omit → crc. Phase
  v11-02 wires MCP callers to pass the bearer's org; this plan only adds the param + default.
- **Tracks derive orgId from their PARENT setlist, NOT a caller param.** A track always
  belongs to a setlist; its orgId MUST equal the setlist's. addTrack/bulkAddTracks read the
  parent `setlists/{id}.orgId` (default "crc" if absent pre-backfill) and stamp it — so a
  track can never mismatch its setlist's tenant, regardless of caller.
- **createSetlistServerSide** stamps the SAME orgId on the setlist doc AND every seeded track.
