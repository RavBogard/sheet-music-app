<objective>
## Goal
Remediate the v70-08-AUDIT.md doc-import performance P1s + the cheap clustered
P2s: stop `/api/setlists/import/resolve` from doing a full uncached
`library_index` scan on every call (lean projection + short-lived cache), give
the ImporterModal client chain a resolve-fetch timeout + an `AbortController` so
closing the modal cancels in-flight work, and fold in the cheap backend P2s
(`commit-document` `maxDuration`, a single atomic batch write in
`createSetlistServerSide`, and `import 'server-only'` guards on the
mammoth/heic-convert modules).

## Purpose
This is the LAST plan of v70-08 — once it closes, the phase transitions and v7.0
becomes milestone-close-eligible (PROJECT.md constraint 12: v7.0 cannot close
until its P1 audit findings are remediated). The resolve full-scan is an
O(library size) Firestore read on a user-facing interactive step, repeated on
every retry; the missing AbortController means a closed modal keeps doing work.

## Output
- `getServerLibraryLean()` — a `.select()`-projected, short-TTL-cached library
  fetch for the resolve hot path; `resolve.ts` switched onto it.
- ImporterModal `handleDocSubmit`: resolve fetch gets an explicit timeout; all 3
  chained fetches share an `AbortController` that aborts when the modal closes.
- `commit-document` route gets `maxDuration`; `createSetlistServerSide` writes
  the parent doc + track seeds in one atomic batch.
- `import 'server-only'` guards on `extract-document.ts` and the
  `heic-convert`-importing upload route.
</objective>

<acceptance_criteria>

## AC-1: The resolve path uses a projected, cached library fetch
```gherkin
Given the /api/setlists/import/resolve route resolves a structure
When it fetches the library to match tracks
Then it reads library_index with a .select() field projection (not the full doc payload)
And a repeat resolve within the cache TTL is served from an in-process cache
  (no second full collection scan)
And the library page (which needs the full LibraryFile shape) is unaffected
```

## AC-2: The doc-import client chain has a resolve timeout and is cancellable
```gherkin
Given a user runs the document-import pipeline in ImporterModal
When the resolve fetch is issued
Then it carries an explicit timeout (parity with the extract steps)
And all three chained fetches share one AbortController
And closing the modal mid-pipeline aborts the in-flight request
```

## AC-3: commit-document is bounded and writes atomically
```gherkin
Given a document-import commit
When createSetlistServerSide persists the setlist
Then the parent setlists/{id} doc and all tracks/{id} seeds are written in a
  single atomic Firestore batch (no partial-write window)
And the commit-document route declares an explicit maxDuration
```

## AC-4: mammoth / heic-convert modules are guarded server-only
```gherkin
Given extract-document.ts (imports mammoth) and the upload route (imports heic-convert)
When the project builds
Then each carries an `import 'server-only'` guard so an accidental client
  import fails the build
And `next build` still passes (the guard does not break the server bundle)
```

<task type="auto">
  <name>Task 1: Lean projected + cached library fetch for the resolve path</name>
  <files>src/lib/server-library.ts, src/lib/setlist-import/resolve.ts</files>
  <action>
    `getServerLibrary()` does a paginated FULL scan of `library_index` with no
    `.select()` projection and no caching — and resolve.ts calls it on every
    `/resolve`. But `getServerLibrary` has another caller (`library/page.tsx`)
    that needs the full `LibraryFile` shape, so do NOT change it globally.

    In `server-library.ts`, add a new exported `getServerLibraryLean()`:
    - Paginates `library_index` the same way, but adds `.select('name',
      'mimeType')` to the query so only those fields transfer.
    - Returns `LibraryFile[]` directly (resolve.ts only reads `id`, `name`,
      `mimeType`). For each doc build `{ id: doc.id, name, mimeType, parents: [] }`
      — `parents` has a schema default so the object still satisfies
      `LibraryFile`; skip the per-doc Zod parse or use a minimal inline guard
      (name + mimeType must be strings) — the full `LibraryFileSchema.safeParse`
      is unnecessary for two projected fields.
    - Add a module-scoped short-TTL cache: a module-level
      `let cache: { files: LibraryFile[]; expiresAt: number } | null`. On call,
      if `cache && Date.now() < cache.expiresAt` return `cache.files`; otherwise
      fetch, populate the cache with a 60s TTL, return. (The audit explicitly
      offers "module-scoped with a TTL" as an acceptable approach — simpler than
      keying on lastModified, which would itself need a scan.) Keep the existing
      try/catch-returns-`[]` resilience posture.
    - Export a `__resetServerLibraryCache()` test helper that nulls the cache,
      so tests stay deterministic.

    In `resolve.ts`: change the import + the call site (`resolve.ts:~165`,
    inside `resolveSetlistStructure`'s no-injected-library branch) from
    `getServerLibrary()` → `getServerLibraryLean()`. `getServerLibrary` returns
    `{ files, lastModified }`; `getServerLibraryLean` returns `LibraryFile[]`
    directly — adjust the destructuring accordingly (`library = await
    getServerLibraryLean()`). The `opts.library` injection path for tests is
    unchanged.

    Avoid: do NOT modify `getServerLibrary` or `library/page.tsx`. Do NOT cache
    the injected-library test path. Keep the cache module-scoped (per server
    instance) — no cross-instance/Redis caching, that's over-engineering for
    synagogue scale.
  </action>
  <verify>npx vitest run src/lib/__tests__/server-library.test.ts src/lib/setlist-import/__tests__/resolve.test.ts — existing suites still pass (resolve tests inject `opts.library`, so they exercise the unchanged path). npx next build — compiles.</verify>
  <done>AC-1 satisfied: resolve uses a `.select()`-projected, TTL-cached fetch; `getServerLibrary` + library page untouched.</done>
</task>

<task type="auto">
  <name>Task 2: resolve-fetch timeout + shared AbortController in the ImporterModal doc chain</name>
  <files>src/components/setlist/importer/ImporterModal.tsx</files>
  <action>
    `handleDocSubmit` chains 3 `apiFetch` calls. Steps 1-2 pass `timeout: 60000`;
    step 3 (resolve) passes no `timeout` (falls back to apiFetch's 30s default —
    inconsistent with the siblings) and nothing aborts in-flight work when the
    modal closes. `apiFetch` already supports both a `timeout` option and a
    caller-supplied `signal` (see api-client.ts) — wire them.

    - Re-add `useRef` to the React import (plan 03 removed it; it's needed again).
    - Add a ref: `const docSubmitAbortRef = useRef<AbortController | null>(null)`.
    - At the start of `handleDocSubmit`, after the `!docFile` guard: abort any
      prior controller (`docSubmitAbortRef.current?.abort()`), create a fresh
      `const controller = new AbortController()`, store it in the ref.
    - Pass `signal: controller.signal` in the options of ALL THREE `apiFetch`
      calls (extract-document, extract-structure, resolve).
    - Add `timeout: 60000` to the resolve `apiFetch` call (parity with steps 1-2).
    - In the `finally` block, clear the ref if it still holds this controller
      (`if (docSubmitAbortRef.current === controller) docSubmitAbortRef.current = null`).
    - In the reset `useEffect` (the `[open]` effect): add an `else` branch — when
      `open` is false, `docSubmitAbortRef.current?.abort()` — so closing the
      modal cancels an in-flight pipeline. Also abort + null it inside
      `handleStartOver` (the user explicitly bailing out).
    - An aborted fetch rejects with an `AbortError`; the existing `catch` in
      `handleDocSubmit` toasts `err.message` and resets to `'input'`. That's
      acceptable, but suppress the toast for a deliberate abort: in the `catch`,
      if `err instanceof DOMException && err.name === 'AbortError'` (or the
      controller's signal is aborted), skip the `toast.error` — a user-initiated
      cancel is not an error to surface. Still reset processing state.

    Avoid: do NOT restructure the 3-route chain or collapse it into one route
    (the audit offers that as option (a) but plan 04's routing scope is the
    timeout + AbortController only — collapsing the chain is a larger
    architectural change, fold-forward). Do NOT touch handleParse/handleExecute.
  </action>
  <verify>npx next build — compiles. Re-read handleDocSubmit + the [open] effect + handleStartOver to confirm: fresh controller per run, signal on all 3 fetches, timeout:60000 on resolve, abort on close + start-over, AbortError toast suppressed.</verify>
