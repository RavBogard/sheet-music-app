<objective>
## Goal
Run the v7.0 best-practice audit: dispatch 5 parallel scope-narrowed agents
(security / accessibility / performance / code quality + data integrity / UX
consistency), each auditing the v7.0 milestone surface, then synthesize their
findings into a single severity-classified report (`v70-08-AUDIT.md`) with an
explicit routing split — P0+P1 → in-phase remediation plans, P2+P3 →
fold-forward. This plan produces the audit; it applies no fixes.

## Purpose
v70-08 is the milestone-closing audit — v7.0 cannot close until it completes.
v7.0 shipped a large new surface (image charts, recordings, the whole
doc-driven import pipeline) fast, across 8 phases in two days. This plan is the
quality gate: a structured, multi-dimension review that surfaces what was
missed, classifies it by severity, and produces the punch list that the
remediation plans (v70-08 plan 02+) work from.

## Output
- 5 per-dimension scratch files of structured findings.
- `.paul/phases/v70-08-best-practice-audit/v70-08-AUDIT.md` — the unified,
  severity-classified audit report with a routing section. Consumed by
  `/paul:plan v70-08` to author the remediation plans.
</objective>

      - **P2** — code quality / maintainability / minor correctness — should
        fix, not urgent.
      - **P3** — nice-to-have / polish / style.
    - If a dimension has no findings at a given severity, say so explicitly.

    1. **Security** (`feature-dev:code-reviewer`) — auth gates on the new API

       flow incl. interview form + preview, RecordingBindPopover, RecordingCell,
       SetlistMetaEditSheet, ImageScoreViewer): label association, focus
       management, keyboard nav, ARIA, contrast, touch-target size.
    3. **Performance** (`general-purpose`) — N+1 / unbounded Firestore reads,
       client re-render hotspots, the 3-route doc-import client chain,
       bundle-size additions (mammoth, heic-convert), slow API routes.
    4. **Code quality + data integrity** (`feature-dev:code-reviewer`) — type
