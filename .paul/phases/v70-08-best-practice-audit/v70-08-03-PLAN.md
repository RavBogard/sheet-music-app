<objective>
## Goal
Remediate the v70-08-AUDIT.md ImporterModal accessibility + UX P1s and the cheap
clustered P2s: make the file-dropzones keyboard-reachable + named (the P1 that
unblocks the entire doc-import flow for keyboard/SR users), branch the "processing"
copy off the document path, fix the destructive interview "Back" button, rename
"Lead" → "Vocal Lead" in MobileRowCard, and fold in the low-cost UX-consistency
P2s (bg-brand, formatted preview date, zero-track guard, select focus ring,
`<audio>` label, RecordingBindPopover loading state).

## Purpose
v7.0 cannot close until its P1 audit findings are remediated (PROJECT.md
constraint 12). The dropzone keyboard finding is a *cascading* P1 — document
upload gates the whole pipeline, so the (correctly-labelled) interview form and
preview are also keyboard-dead until it's fixed. This plan is the frontend
remediation pass; plan 04 (doc-import performance) follows.

## Output
- ImporterModal: keyboard-reachable + accessibly-named dropzones; doc-aware
  processing copy; honest interview back-navigation; brand-colored CTAs;
  formatted preview date; zero-track commit guard; select focus ring.
- MobileRowCard: "Vocal Lead" replaces "Lead" on the stage row card (badge +
  editor field).
- RecordingBindPopover: `<audio>` accessible names; a real loading state instead
  of a false "No recordings yet" flash.
- New focused a11y test asserting both dropzones are keyboard-reachable.
</objective>

## AC-1: File-dropzones are keyboard-reachable and accessibly named
```gherkin
Given a keyboard-only user on the ImporterModal input step
When they Tab through the modal
Then focus lands on both the CSV upload control and the Document upload control
```

```gherkin

  spreadsheet-only copy)
```

  <name>Task 1: Keyboard-accessible + accessibly-named file dropzones</name>
  <files>src/components/setlist/importer/ImporterModal.tsx, src/components/setlist/importer/__tests__/ImporterModal.a11y.test.tsx</files>
  <action>
    Both upload affordances (CSV dropzone ImporterModal.tsx:355-373, Document
    dropzone :388-406) are plain `<div onClick>` wrappers around a
    `className="hidden"` `<input type="file">` — unreachable by keyboard, and the
    headline v7.0 "Upload Document" feature is the worst-affected.

    Use the proven pattern already in RecordingBindPopover.tsx:144-154 — an
    `sr-only` `<input type="file">` with a stable `id`, associated to a styled
    `<label htmlFor={id}>` that carries the dropzone visual. A `<label>` for a
    file input is natively keyboard-focusable + activatable; no manual
    `role`/`tabIndex`/`onKeyDown` wiring needed.

    For EACH dropzone:
    - Give the `<input type="file">` a stable `id` (e.g. `csv-file-input` /
      `doc-file-input`) and change `className="hidden"` → `className="sr-only"`.
    - Convert the wrapping `<div onClick={...}>` to `<label htmlFor={id}>`,
      keeping the existing dashed-border / selected-state styling classes. Drop
      the `onClick={() => ref.current?.click()}` (the label handles activation);
      the `fileInputRef`/`docFileInputRef` refs can stay if still used by the
      reset effect, otherwise remove them.
    - Add `aria-label` to the input: "Upload a CSV file" / "Upload a
      service-outline document".
    - Surface the selected-file state to assistive tech: add
      `aria-live="polite"` to the `<p>` that renders the filename / placeholder
      text (the one showing `csvFile.name` / `docFile.name`), so a SR user hears
      the filename when a file is chosen — selection state must not be
      border-color-only.

    Add a focused a11y test `ImporterModal.a11y.test.tsx`:
    - Render `<ImporterModal open onOpenChange={() => {}} />`.
    - Assert both file inputs are queryable by their accessible name
      (`getByLabelText(/upload a csv file/i)`, `/upload a service-outline
      document/i`) and are NOT `display:none` (i.e. not `.hidden` — `sr-only`
      keeps them in the a11y tree + tab order).
    - Keep the test minimal and resilient — assert reachability/naming, do not
      snapshot the whole modal.

    Avoid: do NOT change `handleFileSelect` / `handleDocSelect` logic, the
    mutual-exclusion state resets, or the submit-button wiring. Do NOT switch to
    a `role="button"` div approach — the `<label htmlFor>` pattern is simpler,
    already proven here, and keeps the real input in the a11y tree.
  </action>
