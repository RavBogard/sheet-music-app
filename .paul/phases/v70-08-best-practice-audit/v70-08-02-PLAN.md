<objective>
## Goal
Harden the v7.0 document-import API surface against the P1/P2 security + validation
findings in v70-08-AUDIT.md: role-gate the 3 upstream import routes, validate
`eventDate` at the schema boundary, replace `z.array(z.any())` write-route schemas
with real Zod shapes, reject unsupported MIME early + cap PDF page count, and
resolve (or explicitly fold-forward) the `recordings/file/[id]` weak-auth finding.

## Purpose
v7.0 cannot close until its P1 audit findings are remediated (PROJECT.md constraint
12). The doc-import pipeline's first three routes currently let any signed-in
`member` drive billed Gemini calls and enumerate the full library — the single
highest-priority finding in the audit. This plan closes the backend-security
cluster; plans 03 (a11y/UX) and 04 (performance) follow.

## Output
- 5 import-route files hardened (role gates, real schemas, MIME/page caps).
- `extract-document.ts` lib gains an early MIME gate + PDF page-count cap.
- New unit tests for the page-cap + MIME-gate behavior in the existing
  `extract-document.test.ts`.
- `recordings/file/[id]` either properly re-authed OR a documented residual-risk
  fold-forward entry appended to v70-08-AUDIT.md.
</objective>

<acceptance_criteria>

## AC-1: Upstream doc-import routes are band_leader-gated
```gherkin
Given a signed-in user whose role is `member` (not band_leader)
When they POST to extract-document, extract-structure, or resolve
Then the request is rejected with a 403 before any Gemini call or library scan runs
And a band_leader making the same request still succeeds
```

## AC-2: commit-document rejects an unparseable eventDate at the schema boundary
```gherkin
Given a POST to commit-document with eventDate set to a non-date string
When the request is validated
Then it is rejected with a 400 schema error (not a 500 RangeError)
And a valid `<input type=date>` value (e.g. "2026-05-15") still passes
```

## AC-3: Write-route array payloads are validated with real Zod shapes
```gherkin
Given a POST to commit-document or execute with a structurally-wrong
  sections/tracks/items payload (e.g. a track missing `title`)
When the request is validated
Then it is rejected with a 400 schema error
And a well-formed payload produced by the resolve route still passes
```

## AC-4: extract-document rejects unsupported MIME early and caps PDF pages
```gherkin
Given a POST to extract-document with a file whose type is not docx/pdf/txt
When the route runs
Then it returns 400 "unsupported format" without invoking mammoth/pdfjs
And given a PDF exceeding the page cap
Then extraction stops at the cap (or returns a clear 400) rather than parsing unbounded pages
```

## AC-5: recordings/file weak-auth finding is resolved or explicitly folded forward
```gherkin
Given the recordings/file/[id] route currently accepts forgeable Sec-Fetch-* headers
When this plan completes
Then either the route enforces a real auth boundary (session cookie or signed URL)
Or v70-08-AUDIT.md carries a documented residual-risk fold-forward entry with rationale
```

<task type="auto">
  <name>Task 2: Replace z.array(z.any()) schemas on commit-document + execute with real Zod shapes</name>
  <files>src/app/api/setlists/import/commit-document/route.ts, src/app/api/setlists/import/execute/route.ts, src/lib/setlist-import/extract-structure.ts</files>
  <action>
    commit-document (P2, cheap):
    - It currently does `sections: z.array(z.any()), tracks: z.array(z.any())`.
      The resolve route already validates its OUTPUT shape is the resolved
      structure. Reuse the real shapes: `SetlistStructureSchema` in
      extract-structure.ts exports `SectionSchema`-backed `sections` and
      `TrackSchema`-backed `tracks`. The committed payload is the *resolved*
      structure (tracks carry `libraryMatch`, `missingChart`, `recordingCandidates`
      added by resolve.ts). Check `src/lib/setlist-import/resolve.ts` for the
      `ResolvedTrack` type and define/extend an exported Zod schema for it
      (a `ResolvedTrackSchema` extending `TrackSchema`) — put the schema next to
      the `ResolvedTrack` type in resolve.ts if that's where the type lives, or
      extend `SetlistStructureSchema` in extract-structure.ts. Use it in the
      commit-document `schema` for `sections` + `tracks`. Keep the metadata fields
      (name/eventDate/serviceType/rabbi) as-is (eventDate already fixed in Task 1).
    - The handler casts `body.sections as SetlistSection[]` / `body.tracks as
      ResolvedTrack[]` — once the schema validates the real shape those casts can
      stay (they're now sound) but are no longer load-bearing.

    execute (P2, cheap):
    - It currently does `items: z.array(z.any()).min(1)`. The handler reads each
      item as `ParsedItem` (type: 'header'|'song', title?, key?, chartUrl?,
      performer?, referenceLink?, chartError?, libraryMatchId?, libraryMatchName?).
      Define a `ParsedItemSchema` zod object matching that interface (all fields
      optional except `type` which is `z.enum(['header','song'])`) and use
      `z.array(ParsedItemSchema).min(1)`. Keep the `ParsedItem` TS interface or
      derive it via `z.infer` — your call, but do not change the handler logic.

    Avoid: over-tightening. Resolve/extract output uses `.nullish()` on optional
    fields — mirror that, don't force `.optional()` only, or valid payloads from
    the live pipeline will 400. Run the resolve + extract-structure lib tests after
    to confirm the shapes still round-trip.
  </action>
  <verify>npx next build passes. npx vitest run src/lib/setlist-import — resolve + extract-structure + commit suites still green. Trace one real resolve-route output object against the new schema mentally (or with a scratch test) to confirm `.nullish()` fields validate.</verify>

<task type="auto">
  <name>Task 3: MIME gate + PDF page-count cap in extract-document</name>
  <files>src/lib/setlist-import/extract-document.ts, src/app/api/setlists/import/extract-document/route.ts, src/lib/setlist-import/__tests__/extract-document.test.ts</files>
  <action>
    MIME gate (P2, cheap):
    - extract-document.ts already has `detectDocumentFormat(fileName, mimeType)`
      which returns null for unsupported types, and `extractDocumentText` already
      returns `{ ok: false, reason: 'unsupported_format' }` when format is null.
      The gap is the route does NOT reject before reading the full file into a
      Buffer. In the route, after the `file.size` check, call
      `detectDocumentFormat(file.name, file.type)` and if it returns null, return
      400 "Only .docx, .pdf, and .txt documents are supported." BEFORE
      `Buffer.from(await file.arrayBuffer())`. Export `detectDocumentFormat` is
      already exported — just import it into the route.

    PDF page cap (P2, cheap):
    - In extract-document.ts `extractPdfText`, add a `MAX_PDF_PAGES` const (use 50
      — a worship-service outline is a handful of pages; 50 is generous headroom).
      Change the loop bound to `Math.min(pdfDoc.numPages, MAX_PDF_PAGES)`. If
      `pdfDoc.numPages > MAX_PDF_PAGES`, the cleanest signal is to return the
      `extraction_failed`-style typed result — but `extractPdfText` returns a bare
      string. Either: (a) have `extractPdfText` throw a clear Error when over the
      cap (the existing try/catch in `extractDocumentText` converts it to
      `{ ok: false, reason: 'extraction_failed', message }`), or (b) add a new
      `reason: 'too_many_pages'` to `ExtractResult` and route it to a 400. Prefer
      (a) — smaller blast radius, the catch already exists. Make the thrown message
      explicit: `PDF exceeds the ${MAX_PDF_PAGES}-page limit.`

    Tests:
    - Add to extract-document.test.ts: (1) a case asserting a PDF buffer with
      >MAX_PDF_PAGES pages yields `{ ok: false }` with the page-limit message —
      mock/construct a pdfjs doc stub the way the existing PDF tests do; (2) a case
      asserting `detectDocumentFormat` returns null for an unsupported MIME (this
      may already exist — check first, only add if missing).

    Avoid: do NOT change the 25MB size cap or maxDuration. Do NOT add the
    `import 'server-only'` guards on mammoth/heic-convert — the AUDIT routes those
    to plan 04, not here.
  </action>
  <verify>npx vitest run src/lib/setlist-import/__tests__/extract-document.test.ts — new + existing cases green. npx next build passes.</verify>

      src/). The `<audio>` element can't attach a Bearer header, so the real fix
      is a session cookie the browser sends automatically.
