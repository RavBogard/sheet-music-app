<objective>

## Goal
Close the v70-01 phase: image-typed charts (PNG / JPEG) are **embedded** into generated print packets instead of skipped. Replace the `isImageTrack` SKIP guard in `print-pipeline.ts` with an `embedJpg` / `embedPng` branch that adds a letter-size page per image (aspect-preserving, centered, margined), increments `stats.appendedTracks`, and routes through the same per-track resilience the PDF path uses. Propagate `fileName` + `mimeType` through the `/api/setlist/print/personal` mapper (currently drops image tracks silently via the PDF-parse catch). Remove the now-obsolete PrintModal deferral banner.

## Purpose
v7.0 milestone constraint #11 + v70-01-01 explicit carry-forward: v70-01-01 shipped upload + view + toolbar-guard and **deferred print embed to v70-01-02 by design** — the wire payload (`fileName` + `mimeType` on `PrintTrackPayload` / `PrintTrack`) and the SKIP guard scaffolding are already in place. This plan flips the single guard from `continue` to `embed`, completing the phase so a mixed PDF+image setlist downloads as one coherent packet. Unblocks the May 15 Shir Shabbat canary path end-to-end (`dodi li (sher).png` now both viewable AND printable).

## Output
- `print-pipeline.ts`: `isImageTrack` retained as a router; new `embedImageTrack()` helper; track loop branches image → embed instead of skip; `computeContentHash` `cacheVersion` bumped (2 → 3) so stale skip-era cached PDFs don't serve
- `print/personal/route.ts`: `tracks.map()` propagates `fileName` + `mimeType` so personal packets embed images too
- `PrintModal.tsx`: image-skip banner + `isImageTrack` helper + unused `ImageIcon` import removed
- Updated `print-pipeline.test.ts` + `print-modal.test.tsx` (skip-behavior assertions → embed-behavior assertions; new image-embed coverage)

    1. Keep `isImageTrack(t: PrintTrack)` as-is — it stays the router for the embed branch.
    2. Add a helper `embedImageTrack(mergedPdf: PDFDocument, track: PrintTrack): Promise<boolean>`
       near `renderServiceFlowItem`. It must:
       - <!-- audit-added --> Wrap the ENTIRE fetch + decode + embed body in a single
         try/catch. `embedJpg` / `embedPng` THROW on malformed, CMYK, or some progressive/
         interlaced images — those throws MUST be caught and return `false`, not propagate.
         On any caught error: `logger.warn('[PrintPipeline] Image embed failed for "<title>" (fileId <id>): <reason>')`
         + return `false`. Returning `false` (never throwing) is the contract that keeps
         the rest of the packet printable.
       - `fetchFileById(track.fileId!, track.mimeType)` — pass `track.mimeType` as the
         second arg so `downloadFromStorage` resolves the correct `.png`/`.jpg` Storage object.
         If null or `buffer.byteLength === 0`: `logger.warn` + return `false`.
       - <!-- audit-added --> Oversized-image guard: an un-capped high-res photo bloats the
         merged PDF and can OOM / timeout the serverless function (main route + personal
         route `maxDuration = 120`). During APPLY, FIRST check whether `/api/library/upload`
         already enforces a byte-size cap on image uploads — if it does, document the ceiling
         in the SUMMARY and rely on it. If it does NOT, add a guard here: if
         `buffer.byteLength` exceeds a threshold (propose 10 MB), `logger.warn` + return `false`
         rather than embedding. The plan must not ship silent on image size.
       - Decide JPEG vs PNG from `fetched.contentType` first, falling back to `track.mimeType`,
         falling back to the `fileName`/`fileId` extension. `image/jpeg` (and `.jpg`/`.jpeg`)
         → `mergedPdf.embedJpg(buffer)`; `image/png` (and `.png`) → `mergedPdf.embedPng(buffer)`.
       - HEIC defensive guard: HEIC is server-converted to JPEG at upload time (v70-01-01 Task 1),
         so a raw HEIC byte stream should never reach here. If contentType/extension is
         heic/heif, `logger.warn` ("unexpected raw HEIC at print time") + return `false`
         rather than throwing — keeps the rest of the packet printable.
       - <!-- audit-added --> EXIF orientation is a KNOWN LIMITATION: `embedJpg` draws raw
         pixels and does NOT honor EXIF orientation tags. A phone photo (incl. the HEIC→JPEG
         path) may embed rotated. Do NOT chase this in APPLY — note it in the SUMMARY as a
         carry-forward limitation. The human-verify checkpoint covers "right-side-up"
         observation; if Daniel reports rotated images, that routes to a follow-up plan.
       - Add a letter-size page `mergedPdf.addPage([612, 792])`. Scale the embedded image
         aspect-preserved to fit within the margin box (margin value per /ui-ux-pro-max —
         propose 36pt / 0.5in each side as the default). Center it in the page.
         Use `image.scaleToFit(maxW, maxH)` then center via `(612 - dims.width)/2`,
         `(792 - dims.height)/2`. Draw with `page.drawImage(image, { x, y, width, height })`.
       - Optional title caption: per /ui-ux-pro-max verdict — if approved, draw `track.title`
         in Helvetica at the top margin; if not, omit. Document the verdict in SUMMARY.
       - Return `true` ONLY on a successful embed (page added + image drawn).
    3. In the track loop (currently around line 644), replace the SKIP block:
       ```
       if (isImageTrack(track)) {
           logger.info(...)
           continue
       }
       ```
       with:
       ```
       if (isImageTrack(track)) {
           trackIndex++
           onProgress?.({ phase: 'processing', currentTrack: trackIndex, totalTracks: stats.totalTracks,
               currentTitle: track.title, message: `Processing: ${track.title}` })
           const embedded = await embedImageTrack(mergedPdf, track)
           if (embedded) stats.appendedTracks++
           continue
       }
       ```
       <!-- audit-added --> DEFINITIVE (no longer a "verify during APPLY" hedge): image
       tracks DO carry `fileId`, so the `req.tracks.filter(t => t.fileId).length` at
       line 570 already counts them in `stats.totalTracks`. Therefore incrementing
       `trackIndex` + `appendedTracks` in this branch makes both progress reporting and
       `appendedTracks` accurate with no change to the line-570 filter. Do NOT modify
       the totalTracks computation.
    4. Bump `computeContentHash` `cacheVersion: 2` → `3` (rendering logic changed — stale
       skip-era cached PDFs must not serve). This is the documented mechanism on that line.
    5. Do NOT touch the transposition path, chord-cache, result-cache storage mechanism
       (other than the cacheVersion constant), `buildCoverPage`, or `renderServiceFlowItem`.
    6. Avoid: throwing on a bad image (one corrupt image must not kill the whole packet —
       mirror the PDF path's per-track try/catch resilience); embedding at native pixel size
       (un-scaled images overflow the page); re-fetching the file twice.
    7. Update `print-pipeline.test.ts`: any existing assertion that an image track is SKIPPED
       (appendedTracks NOT incremented / track absent) must flip to embed-behavior
       (appendedTracks incremented). Add at least one new case: a PNG track + a JPEG track
       in a request → both contribute to `appendedTracks`. Mock `fetchFileById` to return a
       minimal valid PNG/JPEG buffer for pdf-lib embed.
       <!-- audit-added --> At least one image fixture MUST be non-square (e.g. 2x1 or 1x2
       pixels) so the `scaleToFit` + centering math in `embedImageTrack` is actually
       exercised — a 1x1 fixture leaves AC-1's "aspect-preserved + centered" untested.
       <!-- audit-added --> Add a degraded-path case: mock `fetchFileById` to return a
       buffer that `embedJpg`/`embedPng` rejects (or return null) for one image track in a
       mixed request → assert (a) `generatePrintPdf` does NOT throw, (b) the other tracks
       still embed, (c) `appendedTracks` counts only the successful embeds, (d) a warn was
       logged for the failed track. This covers AC-6.
