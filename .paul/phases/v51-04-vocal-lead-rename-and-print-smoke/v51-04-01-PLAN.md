## Goal
Close the v5.1 milestone's three remaining bundled items in a single small plan: (1) rename every user-facing "Lead" label to "Vocal Lead" across the 5 visible surfaces (editor column header, batch action popover, mobile edit sheet, importer modal, print cover page) without touching DB-internal field names or the distinct band-leader/rabbi-leading-service concepts; (2) codify the Daniel-loop UAT cadence in PROJECT.md per postmortem action item #4; (3) HUMAN-VERIFY a gig-packet print smoke on real production end-to-end.

## Purpose
"Vocal Lead" not "Lead"/"Leader" is a standing user terminology preference (auto-memory `feedback_terminology.md`) — distinct from the band leader (perform-mode position controller, `isLeader` in SetlistRow) and from the rabbi who leads the service ("Led by: {rabbi}" on print). Last visible language inconsistency before band onboarding. Daniel-loop UAT codification is the action item that prevents future cutover-shaped phases from shipping without real-production verification (the gap that produced v5.0-hotfix). Print smoke is the standing pre-band checkpoint — the gig packet is what the band actually plays from each week, so it needs to survive the v5.0 substrate cutover and any visible label rename.

## Output
- 5 user-facing label rewrites: "Lead" → "Vocal Lead" (editor + batch + mobile + importer + print cover header)
- Boundaries preserved verbatim: `leadMusician` field, `lead` patch helper alias, `setlistLeads`/`libraryLeads`/`knownLeads` internal arrays, `LeadCell` component name, `isLeader`/`onLeaderSetPosition` (perform-mode band leader), `band_leader` UserRole, `"Led by: ${rabbi}"` print line — all untouched.

- HUMAN-VERIFY confirms label rename + print pipeline both render correctly on production for a real Erev Shabbat or Shabbat morning setlist.
