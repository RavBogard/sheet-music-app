<objective>
## Goal
Fix BUG-2 (P1): deterministic client errors that currently return HTTP 500 must return the correct status, so an agent doesn't treat them as transient/retryable. Three reported cases: `add_track_to_setlist` unknown `songId` → **404**, `reorder_setlist` bad/incomplete `orderedTrackIds` → **400**, `upload_chart` dedup name collision → **409**. Reserve 500 for genuine exceptions.

## Purpose
Claude Code (Daniel's primary authoring surface) reads HTTP-class codes to decide retry-vs-fix. A deterministic client error mislabeled 500 causes retry storms and masks real 5xx. This is the agent-facing error contract for the weekly authoring flow.

## Output
- `errors.ts`: `ERROR_CODE_MAP` gains `song_not_found:404`, `reorder_failed:400`, and the chart-dedup/conversion codes.
- `library-upload.ts` (MCP tool) + `library-upload-session.ts`: map `processChartUpload`'s discriminated `result.error` to the right status instead of a blanket `upload_failed` (500).
- A response-contract test asserting status class per machine_code (incl. positive controls).
</objective>

## ROOT CAUSE (verified vs deployed origin/master 2026-06-09)
`richError(machine_code, msg, extras?, hint?)` derives `error.code` via `codeFor(machine_code) = ERROR_CODE_MAP[machine_code] ?? 500` (unless `extras.errorCode` overrides). The three reported codes are mis-resolved:
- **`song_not_found`** — NOT in `ERROR_CODE_MAP` → 500. Used by `add_track_to_setlist`/`update_track`/`swap_chart` (setlist-write.ts:367/503/608), `update_song` (song-metadata.ts:286), `get_song` (index.ts:430). All mean "not found" → should be **404**.
- **`reorder_failed`** — NOT in map → 500. Used ONLY at `reorderSetlist` (setlist-write.ts:840), on a caller-supplied bad/incomplete `orderedTrackIds` set (the `"kind" in result` branch already handles stale_version etc., so this remaining path is pure caller input). Hint already says "orderedTrackIds must list every current track id exactly once." → should be **400**.
- **`upload_failed`** — NOT in map → 500, and it's a CATCH-ALL: the MCP wrappers (`upload_chart` library-upload.ts:180, a 2nd site ~:625, `save_scraped_chart` ~:1040, `finalize_chart_upload` library-upload-session.ts:506) all do `richError("upload_failed", result.error, …)`. But `result.error` from `processChartUpload` (src/lib/library-upload.ts) is ALREADY a discriminated enum: `"too_large" | "empty_file" | "duplicate_exact" | "duplicate_similar" | "convert_failed" | "server_error"` (+ maybe more). The dedup collision (`duplicate_exact`/`duplicate_similar`) is the report's 409 case; today it's buried in the message with a 500 code.

POSITIVE CONTROLS (already correct — must stay): `delete_chart` bonded → 409 `chart_in_use`; stale `lastSeenVersion` → 409 `stale_version`; propose/get not-found → 404.
