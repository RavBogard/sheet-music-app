<objective>
## Goal
Close the two P3 polish findings the stress test surfaced, both server-side:
- **BUG-6:** the broslaz PWA manifest (`/manifest-brotherslazaroff.json`) is served the HTML
  app shell (307→/login) instead of the static JSON, so PWA install is broken on broslaz.
- **F-6:** cold landing fires `/api/auth/qr` + `/api/web-vitals` and 429s, because the 6-iPad
  fleet shares ONE NAT IP against the 60/min `api` rate-limit bucket.

## Purpose
Both bugs degrade the band/consumer surface that the project exists to serve:
- BUG-6 blocks broslaz musicians from installing the home-screen PWA (the intended iPad
  Perform launch path). The CRC manifest (`/manifest.json`) already works — this restores parity.
- F-6's 429s drop `/api/web-vitals` beacons on the slowest (cold) cohort — which also corrupts
  the v11.3-04 deferred RUM TTFB UAT (the cold slice is the one we need to measure). Fixing the
  NAT-shared bucket protects both the QR sign-in flow AND that pending measurement.

## Output
- `src/proxy.ts` — matcher excludes org-suffixed manifest variants, not just `manifest.json`.
- `src/lib/rate-limit.ts` — new generous IP-keyed `telemetry` tier for NAT-shared public
  poll/beacon endpoints (mirrors the ratified `chart`-tier fleet rationale).
- `src/app/api/auth/qr/route.ts` + `src/app/api/web-vitals/route.ts` — repointed to `telemetry`.
- Regression tests in the existing `proxy-auth.test.ts` + `rate-limit.test.ts`.
</objective>
