## AC-1: Monitor command rule requires known type
```gherkin
Given a client writes to monitor-live/commands/pending/{id}
When the command's `type` field is not in the known set (set_bus_master, set_send_level, set_send_on, set_matrix_fader, set_matrix_on)
Then the rule denies the write
And the existing uid + createdAt checks still apply
```

## AC-2: Monitor command rule requires shape-consistent fields
```gherkin
Given a valid type
When busIndex/channelIndex/matrixIndex are present

And `value` must be a number or boolean
```

<task type="auto">
  <name>Task 1: Tighten monitor-live/commands/pending rule</name>
  <files>firestore.rules</files>
  <action>
    Replace the current rule (lines 261-267) with:

      match /monitor-live/commands/pending/{commandId} {
        allow read: if false; // Bridge reads via Admin SDK
        allow create: if isSignedIn()
                      && request.resource.data.uid == request.auth.uid
                      && request.resource.data.createdAt is number
                      && request.resource.data.type in [
                          'set_bus_master',
                          'set_send_level',
                          'set_send_on',
                          'set_matrix_fader',
                          'set_matrix_on'
                      ]
                      && (!('busIndex' in request.resource.data)     || request.resource.data.busIndex is int)
                      && (!('channelIndex' in request.resource.data) || request.resource.data.channelIndex is int)
                      && (!('matrixIndex' in request.resource.data)  || request.resource.data.matrixIndex is int)
                      && (!('value' in request.resource.data)        || request.resource.data.value is number
                                                                       || request.resource.data.value is bool);
        allow update, delete: if false; // Bridge deletes via Admin SDK
      }

    Deploy via `firebase deploy --only firestore:rules` (Claude runs CLI — no user action needed).

    Do NOT:
      - Restrict the type list further (would break future command types without a code+rules co-deploy)
      - Add payload-size limits (Firestore already caps docs at 1 MiB — overkill here)
      - Touch any other rule
  </action>
