<objective>
## Goal
Harden Firestore security rules (lock down config/admins writes, add missing collection rules, protect system collections) and run npm audit fix to resolve 21 known vulnerabilities.

## Purpose
Firestore rules gaps allow authenticated non-admins to potentially write to sensitive config documents. Missing wildcard deny-all rule means any new collection added in the future is open by default. The 21 npm vulnerabilities (11 high) need resolution.

## Output
Hardened firestore.rules and clean npm audit report.

<task type="auto">
  <name>Task 1: Harden Firestore rules</name>
  <files>firestore.rules</files>
  <action>
    Three specific fixes to firestore.rules:
    
    1. **Lock config/admins to read-only from client:**
       Currently `config/admins` allows `write: if isAdmin()`. Problem: the admins doc itself is used in the `isAdmin()` function, creating a bootstrap-only write path that should be server-only.
       Change to: `allow write: if false;` — admin bootstrap writes already go through Admin SDK (bypasses rules). Add a comment explaining this.
    
    2. **Add wildcard deny-all at the end:**
       After all existing match blocks (but still inside the `match /databases/{database}/documents` block), add:
       ```
       // Deny-all fallback — any collection not explicitly matched above is locked
       match /{document=**} {
         allow read, write: if false;
       }
       ```
       This prevents new collections from being accidentally accessible.
    
    3. **Verify system collections are locked:**
       Audit that these collections all have `allow write: if false`:
       - auditLogs (line ~239 — OK)
       - scheduling_history (line ~279 — OK)
       - songUsage (line ~250 — OK)
       - library_index (line ~212 — OK)
       - qr-sessions (line ~287 — OK)
       - bridge-setup-codes (line ~292 — OK)
       If any are missing the write lock, add it.
    
    Do NOT change any other rules. Keep all existing read/write permissions for users, setlists, templates, etc.
  </action>
  <verify>Review the diff to confirm only config/admins write rule and wildcard deny-all were changed; deploy test with Firebase emulator if available, or manual review</verify>
  <done>AC-1, AC-2, AC-3 satisfied: config/admins locked, wildcard deny-all added, system collections verified</done>
</task>

    Accept low-severity transitive vulnerabilities that can't be safely fixed.
  </action>
