# v11.5-05-02 SUMMARY — Q5 (title strip) + F4 (key resolution)

Consumer setlist-detail (`/perform/setlist/[id]` → `SetlistRow`) display
correctness on both tenants. Read-time + display-only; no Firestore writes, no
rules. Q5 intentionally changes the CRC render (NOT byte-identical — the audit
flagged ".pdf" on CRC too).

## What shipped

### Q5 — strip stray chart/doc extensions on consumer titles
- New pure, client-safe helper `displayChartTitle()` (`src/lib/format/chart-title.ts`)
  anchored to a known trailing extension set (`pdf|docx?|musicxml|mxl|xml|txt|rtf|pages|png|jpe?g|webp`);
  idempotent, preserves mid-title dots ("Russian Sher No. 3").
- `SetlistRow` computes `const title = displayChartTitle(track.title)` once and
  uses it in the song title, openable-non-song title, muted-non-song title, and
  the `aria-label`. The HEADER label still renders raw `track.title` (user-typed
  section name, not a filename). Did NOT refactor the ~11 other inline strip sites
  (out of scope).

### F4 — resolve a missing track.key from library_index at SSR read time
- Generalized `server-tracks.ts`'s `enrichMissingMimeTypes` →
  `enrichMissingFromLibraryIndex`: the SAME batched `library_index.getAll` now
  fills a missing `mimeType` AND/OR a missing `key`. Selects rows missing either,
  reads both fields, fills each only when absent + present. mimeType behavior
  byte-preserved; zero extra reads. Reaches anon/musician viewers via the SSR
  frame (`initial.tracks`) — they never hydrate the leader-only `useLibraryStore`.
- `SetlistRow`'s `displayKey` already had NO org gate, so the badge renders for
  any track with a non-empty `key` — F4 just needed the data on the row.

## Verify-first probe (Task 1) — VERDICT (B): authoring data gap

`qAzY0sJJGcad8mUqEZF0`, 18 songs) via a throwaway BL bearer (minted + REVOKED) +
Admin-SDK reads. Findings: `.paul/research/v11-5-05-02-f4-bl-key-probe.md`.

- Sampled fileIds: `library_index.key` = **null** AND `songs.defaults.key` = **null**.
