<objective>
## Goal
Disarm the four silent-degrade foot-guns that let today's auth incident happen quietly:
1. Env vars declared optional in schema but required at runtime (silent cookie skips, silent 500s).
2. `auth_bounce_count` cookie set without `path`, disarming the `>3 → /auth-error` loop-breaker.
3. `initAdmin()` return value ignored at call sites, so missing creds surface as opaque 500s instead of diagnosable errors.
4. No written checklist for "deploy secret → verify → then ship code," so the env-var-ordering mistake is easy to repeat.

## Purpose
Today's 28-minute prod lockout was not caused by clever code. It was caused by the system *tolerating* missing configuration. Every hotfix since v4.3 Phase 9 started has had to work around "it silently returned 200 with fewer cookies than expected." The principled fix is to make the failure modes loud: fail-fast on missing secrets, arm the escape hatch, and write down the deploy order.

## Output
- `SESSION_ROLE_SECRET`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `CRON_SECRET` marked required-in-production in `env.mjs` (still optional when `SKIP_ENV_VALIDATION=1` for tests).
- `signRoleCookie` throws in production if the secret is missing (was: silent `null` return + warn). Dev/test keeps the warn-and-skip for local ergonomics.
- Every call to `initAdmin()` across the API surface checks the return value and returns a clear 500 before touching `getAuth()` / `getFirestore()`.
- `auth_bounce_count` cookie is set with `path: '/'` so the 10-second bounce counter actually accumulates across paths, re-arming the `>3 → /auth-error` fallback.
- `docs/DEPLOY-CHECKLIST.md` with the secret-then-code deploy order codified.
- `10-01-SUMMARY.md`.
</objective>
