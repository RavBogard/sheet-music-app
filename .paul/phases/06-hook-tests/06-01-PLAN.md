## AC-1: use-media-query tests
```gherkin
Given the useMediaQuery hook
When rendered with a CSS media query string
Then it returns false initially (SSR default)
And updates to true when matchMedia reports a match
And responds to change events
```

## AC-2: use-wake-lock tests
```gherkin
Given the useWakeLock hook
When requestWakeLock is called
Then it acquires a Wake Lock sentinel via navigator.wakeLock.request
And sets isLocked to true
And auto-reacquires on visibility change when shouldLock is active
And handles NotAllowedError gracefully
```

## AC-3: use-metronome tests
```gherkin
Given the useMetronome hook
When start/togglePlay is called
Then isPlaying becomes true and isBeat pulses on interval
And stop clears the interval
And BPM changes while playing restart the interval
```

## AC-4: use-library tests
```gherkin
Given the useLibrary hook
When the user is authenticated
Then it fetches from /api/library/list?all=true
And hydrates the Zustand library store with response data
And when force=true, sets cache: 'no-store'
```

## AC-5: use-batch-selection tests
```gherkin
Given the useBatchSelection hook
When toggleSelectId is called
Then it toggles the ID in the selected set
And handleBatchDelete removes selected tracks and shows undo toast
And handleBatchDuplicate inserts copies after last selected
And exitSelectMode clears selection
```

## AC-6: use-monitor-access tests
```gherkin
Given the useMonitorAccess hook
When the user is an admin
Then hasAccess is true
And when a non-admin has a bus assigned
Then hasAccess is true
And when the user has no access path
Then hasAccess is false
```
