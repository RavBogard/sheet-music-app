<objective>
## Goal
P0 LIVE-SERVICE FIX: the website Gig Packet ("Full Packet (PDFs)") silently drops
every `text/plain` (scraped chord) chart, because `print-pipeline.ts` only
`PDFDocument.load`s PDF charts (+ embeds images) — text bytes throw, get caught,
and are skipped. David's CRC Camp Sabra sets are entirely/mostly text/plain → the
packet comes out as a cover page with zero charts. Teach the web print pipeline to
render text charts to monospace PDF pages (chord-over-lyric, transpose-aware), and
unify on one shared renderer also used by MCP `generate_gig_packet`.

## Purpose
The band can't print their charts for this weekend's camp sets. Diagnosis is
data-confirmed: `verify_setlist_charts` shows the Staff Concert set is 14/14
`mimeType: text/plain` (all "ok"/reachable); the all-PDF Juneteenth set prints
fine. Root cause is a latent format gap, newly hit because these sets are scraped
text charts (the Perform iPad view renders them fine via `TextScoreViewer`; print
was never taught the format).

## Output
- NEW `src/lib/pdf/text-chart-pdf.ts` — shared, framework-agnostic server renderer:
  `toWinAnsi`, `isChordToken`/`isChordLine` (mirrors TextScoreViewer), column-
  preserving `transposeChartText`, and `renderTextChartToPdf(pdf,title,text,opts)`.
- Web `print-pipeline.ts`: a text-chart branch (render instead of drop).
- MCP `library-download.ts`: refactored to call the shared renderer (delete its
  local `renderTextChart`/`toWinAnsi`), so MCP + web stay byte-consistent.
</objective>

<acceptance_criteria>

## AC-1: Web Full Packet renders text charts (was: dropped)
```gherkin
Given a setlist whose bonded charts are text/plain (e.g. Camp Sabra Staff Concert)
When a Full Packet (coverOnly=false) is generated via /api/setlist/print
Then each text chart is rendered as monospace Courier PDF page(s) appended to the packet
And appendedTracks counts them (the packet is no longer cover-only)
```

## AC-2: Transpose applies to text charts (per-musician packet)
```gherkin
Given a text chord chart and a non-zero per-track transposition
When the packet renders that chart
Then chord tokens are transposed via music-math transposeChord, anchored at their
  original columns (chord-over-lyric alignment preserved), non-chord lines unchanged
And transposition 0 returns the chart text byte-identical (no drift)
```

## AC-3: Unicode-safe, never throws mid-packet
```gherkin
Given a scraped chart containing smart quotes / em-dashes / non-WinAnsi chars
When rendered with pdf-lib StandardFonts.Courier (WinAnsi-only)
Then toWinAnsi pre-substitutes common artifacts and maps the rest to '?', so
  drawText never throws and the rest of the packet still prints
```

## AC-4: MCP and web share one renderer
```gherkin
Given both generate_gig_packet (MCP) and generatePrintPdf (web)
When either renders a text chart
Then both call src/lib/pdf/text-chart-pdf.ts renderTextChartToPdf (one source of truth);
  MCP behavior stays equivalent (no transpose arg) and its emulator tests still pass
```
