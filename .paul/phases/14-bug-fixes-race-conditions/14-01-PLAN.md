<acceptance_criteria>

## AC-1: Firestore Notification Security Rule Tightened
```gherkin
Given a signed-in user who is not an admin
When they attempt to create a notification document under another user's notifications subcollection
Then the Firestore security rule denies the write
And only admin users or the notification recipient can create notifications
```

## AC-2: N+1 Query in Scheduling Reminder Eliminated
```gherkin
Given a cron job with 20 pending assignment reminders for 8 unique musicians
When the scheduling-reminder route executes
Then musician preference docs are fetched in batch (max 2 Firestore reads for 8 musicians)
And not 20 individual reads (one per assignment)
```

## AC-3: use-offline AbortController Prevents State Updates After Unmount
```gherkin
Given the offline download component is mounted and a download is in progress
When the component unmounts before the download completes
Then the fetch is aborted via AbortController
And no state updates are attempted on the unmounted component
```

## AC-4: auth-context syncSessionCookie Has Error Handler
```gherkin
Given a user signs in and syncSessionCookie is called
When the cookie sync promise rejects
Then the error is caught and logged
And the app does not show an unhandled promise rejection
And loading state still resolves (sessionReady = true)
```

## AC-5: Missing .catch() Handlers Added to Library Components
```gherkin
Given any promise in SongChartsLibrary, LibraryFileRow, or AddSongsModal
When the promise rejects
Then the rejection is caught (logged or silently handled for non-critical operations)
And no unhandled promise rejection occurs
```

## AC-6: BPM Upload Validation Prevents NaN
```gherkin
Given a library upload request with bpm="invalid"
When the upload route processes the form data
Then NaN is not stored in Firestore
And bpm is set to undefined (treated as not provided)
```

## AC-7: use-safe-firestore-sync Non-Null Assertion Fixed
```gherkin
Given useSafeFirestoreSync encounters a setup error
When the catch block runs and timeoutId was never set
Then the code safely checks timeoutId existence without non-null assertion
And clearTimeout is only called when timeoutId is defined
```

  <action>
    1. **firestore.rules — Tighten notification create rule (line ~75):**
       Change `allow create: if isSignedIn();` to restrict creation to admin users only:
       `allow create: if isSignedIn() && (isAdmin() || isBandLeader());`
       Rationale: Notifications are created server-side via admin SDK (bypasses rules). Client-side creation should only be allowed for admin/band-leader users sending notifications. Regular band members should never create notifications for others.

    2. **scheduling-reminder/route.ts — Batch-fetch musician preferences (~line 73):**
       Before the assignment loop:
       - Collect all unique `musicianUid` values from `snap.docs`
       - Batch-fetch musician docs using `db.getAll(...refs)` (Firestore admin SDK supports getAll for up to 100 docs)
       - Build a Map<string, prefs> from the batch result
       Inside the loop: replace the per-loop `db.collection('users').doc(a.musicianUid).get()` with a Map lookup.

       Avoid: Using `where('__name__', 'in', uids)` which is limited to 30. Use `db.getAll()` instead which handles up to 100 refs.

    3. **use-offline.ts — Add AbortController to downloadFile (~line 44):**
       - Create an `AbortController` at the start of `downloadFile`
       - Pass `{ signal: controller.signal }` to the fetch call
       - In the cleanup/unmount effect, call `controller.abort()` for any in-progress downloads
       - Track active controllers via a ref: `const controllersRef = useRef<Map<string, AbortController>>(new Map())`
       - In downloadFile: store controller in map, remove on completion
       - In useEffect cleanup: abort all active controllers
       - Wrap state updates after fetch in a guard: `if (!signal.aborted) { setDownloading(...) }`

    4. **auth-context.tsx — Add .catch() to syncSessionCookie (~line 137):**
       Add `.catch((err) => { logger.error("syncSessionCookie rejected:", err); sessionReady = true; if (profileReady) setLoading(false); })` to the promise chain.
       This ensures that even if the cookie sync fails, the app finishes loading instead of hanging.

    Avoid: Changing any auth logic beyond adding error handling. Do not modify Firestore security rules beyond the notifications subcollection.
