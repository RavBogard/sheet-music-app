    **assign/route.ts (line 42):** Replace `(setlistDoc.data()?.tracks ?? []) as any[]` with a local interface `{ fileId?: string; title?: string }[]` and map from that.

    **calendar-feed/route.ts (line 63):** Replace `for (const a of assignments as any[])` with a local `SchedulingAssignmentDoc` interface covering the fields accessed (id, eventDate, instrument, status, setlistName, setlistId). Type `assignments` properly from the `.map()` call on line 47.

    **calendar-feed/route.ts (lines 119-120) and remind/route.ts (lines 129-130):** Replace the `'seconds' in (eventDate as any)` / `(eventDate as any).seconds` pattern with a type guard:
    ```ts
    function hasSeconds(v: unknown): v is { seconds: number } {
      return typeof v === 'object' && v !== null && 'seconds' in v && typeof (v as Record<string, unknown>).seconds === 'number'
    }
    ```
    Then use `if (hasSeconds(eventDate))` instead of the `as any` checks. Define this helper in each file locally (only 2 files, not worth a shared module).

    **remind/route.ts (line 35):** Replace `as Array<any>` with a local `PendingAssignment` interface covering the fields accessed (id, eventDate, musicianEmail, musicianName, musicianPhone, musicianUid, setlistName, instrument).

    **suggest/route.ts (lines 78-81):** The `as any` on line 81 exists because `instrumentMatch` is added conditionally. Fix by defining a proper `SuggestionResult` type that extends the base musician type with `instrumentMatch: boolean`. Use this type explicitly instead of spreading and casting.

    **suggest/route.ts (line 100):** Replace `(m as any).instrumentMatch` with proper type access from the `SuggestionResult` type.

    **chat/route.ts (lines 156, 159):** `templateRequest.templateKey as any` is cast to `ServiceType` but template keys include values like `shir_shabbat`, `bnei_mitzvah_saturday`, etc. that aren't in the `ServiceType` union. Fix by either:
    - Widening `ServiceType` in liturgical-calendar.ts to include all template keys, OR
    - Creating a `TemplateKey` type in liturgical-templates.ts and using `ServiceContext & { type: string }` for template-generated contexts.
    Choose the second approach: use `type: string` for the template context since template keys are a superset of service types. This avoids changing the ServiceType union which other code depends on.

    **liturgical-templates.ts (line 421):** `(context as any).rabbi` — Add an optional `rabbi?: string` property to `ServiceContext` in liturgical-calendar.ts. This is cleaner than an intersection type since `rabbi` is used in multiple places and is a natural part of service context.
