<objective>
## Goal
Fix two route-level harness / error-contract bugs that both sit on the `/test-login`
sign-in path:
- **BUG-9** — `proxy.ts` bounces an unauth `GET /test-login` to `/login` (307) before
  the page can consume its `?code=`, so the loginable-test-account browser harness can
  never sign in.
- **BUG-7** — `GET /api/auth/qr?code=<malformed>` (a code containing `/` or other
  non-`[A-Z0-9]` chars) throws on the Firestore `.doc(code)` lookup and returns **500**;
  the v11.2 error contract requires a **4xx** for caller-supplied bad input.

Each fix ships with a regression test that cites the stress-report coverage cell it covers.

## Purpose
These broke the Brothers Lazaroff stress-run pre-flights and violate the error contract.
No consumer-facing behavior changes — `/test-login` is an intended-public pre-auth harness
page (same posture as `/qr` and `/login`), and the QR poll endpoint is already public. This
restores intended behavior and tightens an error code; it does not widen access to any
real user data. CRC and broslaz both get the identical fix (shared surface — tenancy
invariant 4 preserved by construction).

## Output
- `src/proxy.ts` — `/test-login` added to the public allow-list (exact match).
- `src/__tests__/proxy-auth.test.ts` — BUG-9 regression (+ a negative no-over-broadening case).
- `src/app/api/auth/qr/route.ts` — GET validates `code` format → 400 before touching Firestore.
- `src/app/api/auth/qr/__tests__/route.test.ts` — BUG-7 regression (new file).
</objective>

```gherkin
  And legitimate /test-login codes (6-char uppercase alphanumeric, minted by POST generateCode) still pass
```
