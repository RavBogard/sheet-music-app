## AC-1: QR Session Binding
```gherkin
Given a QR session in "pending" status
When a phone user PUTs to approve it
Then the session is validated: must be pending, not expired, not already approved
And the approvedBy UID is recorded on the session doc
And re-approval of the same session returns 409
```

## AC-2: AI Concurrency Safety
```gherkin
Given the AI concurrency semaphore with 2 max slots
When an AI call throws an error
Then the slot is always released (try/finally pattern)
And a 30-second timeout auto-releases stuck slots
And deadlock is impossible even with repeated failures
```

## AC-3: Rate Limit Hardening
```gherkin
Given the rate limiting system
When Upstash Redis is unavailable
Then the in-memory fallback is used (fail-closed, not fail-open)
And /auth/session POST has rate limiting applied
```

## AC-4: Drive API Safety
```gherkin
Given the DriveClient
When sanitizeQuery is called with special characters
Then all Drive API query special characters are escaped (not just single quotes)
And recursive listAllFiles uses bounded concurrency (max 5 parallel)
And all API calls have a 30-second timeout via AbortController
```

<task type="auto">
  <name>Task 2: Fix AI concurrency deadlock and add timeout</name>
  <files>src/lib/ai-concurrency.ts</files>
  <action>
    Current issue: If a caller acquires a slot but throws before calling releaseAiSlot(),
    the slot is permanently consumed. With MAX=2, two such failures deadlock all AI features.

    Fix:
    1. Add a `withAiSlot<T>(fn: () => Promise<T>): Promise<T>` wrapper that:
       - Calls acquireAiSlot()
       - Runs fn() in a try/finally that always calls releaseAiSlot()
       - This is the RECOMMENDED way to use the semaphore
    2. Add a timeout to acquireAiSlot():
       - Default 30 seconds
       - If slot not acquired within timeout, reject with Error("AI slot timeout")
       - This prevents infinite queue waits
    3. Keep the existing acquireAiSlot/releaseAiSlot exports for backward compatibility
    4. Export withAiSlot as the preferred API
  </action>
  <verify>npm test -- --reporter=verbose 2>&1 | tail -5</verify>
  <done>AC-2 satisfied: AI concurrency has try/finally wrapper and timeout</done>
</task>

<task type="auto">
  <name>Task 4: Drive API safety — query escaping, bounded recursion, timeouts</name>
  <files>src/lib/google-drive.ts</files>
  <action>
    **1. Query escaping (line ~158):**
    Replace the simple `replace(/'/g, "\\'")` with a proper escape function:
    ```typescript
    function sanitizeDriveQuery(input: string): string {
        // Escape backslashes first, then single quotes
        return input.replace(/\\/g, '\\\\').replace(/'/g, "\\'")
    }
    ```
    The Drive API query language only needs backslash and single-quote escaping
    (it's not SQL — operators like `and`, `or` are keywords, not injectable via name contains).

    **2. Bounded recursion in listAllFiles (line ~124):**
    Replace `Promise.all(folders.map(...))` with a bounded concurrency helper:
    ```typescript
    // Process subfolders with max 5 concurrent requests
    async function mapWithConcurrency<T, R>(
        items: T[],
        fn: (item: T) => Promise<R>,
        limit: number
    ): Promise<R[]> {
        const results: R[] = []
        let index = 0
        async function worker() {
            while (index < items.length) {
                const i = index++
                results[i] = await fn(items[i])
            }
        }
        await Promise.all(Array.from({ length: Math.min(limit, items.length) }, () => worker()))
        return results
    }
    ```
    Use `mapWithConcurrency(folders, folder => this.listAllFiles(folder.id), 5)` instead of `Promise.all`.

    **3. Request timeout:**
    Add AbortController with 30-second timeout to the withRetry wrapper:
    - Create AbortController at the start of withRetry
    - Set a 30-second timeout that calls abort()
    - Pass the signal to the operation if possible
    - Note: googleapis may not support AbortSignal directly, so implement as a
      Promise.race between the operation and a timeout rejection
    - Clean up the timeout on success or final failure
  </action>
  <verify>npm test -- --reporter=verbose 2>&1 | tail -5</verify>
