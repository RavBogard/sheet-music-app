<objective>
## Goal
Migrate 11 API routes (2 admin + 9 library) from manual `withAuth` pattern to the standardized `createApiHandler` wrapper, and fix HTTP status codes where applicable (201 for resource creation).

## Purpose
Eliminates boilerplate auth/error handling, unifies route patterns, and ensures error responses are automatically sanitized (no internal details leaked). Every migrated route gets consistent auth, body validation, and error logging for free.

## Output
11 route files migrated to createApiHandler pattern. Reduced withAuth direct usage from 32 to 21 routes.
</objective>

<task type="auto">
  <name>Task 1: Migrate 2 admin routes to createApiHandler</name>
  <files>src/app/api/admin/set-sound-engineer/route.ts, src/app/api/admin/set-upload-permission/route.ts</files>
  <action>
    For each route, apply this migration pattern:

    **Before (withAuth pattern):**
    ```typescript
    import { withAuth } from "@/lib/api-auth"
    export async function POST(req: NextRequest) {
      const auth = await withAuth(req, 'admin')
      if (auth instanceof NextResponse) return auth
      // ... handler logic
    }
    ```

    **After (createApiHandler pattern):**
    ```typescript
    import { createApiHandler } from "@/lib/api-wrapper"
    import { z } from "zod"  // if body validation needed
    const schema = z.object({ ... })  // extract from inline validation
    export const POST = createApiHandler(
      async (ctx) => {
        // Rate limiting (if present): keep as first line
        // const limited = await checkRateLimit(ctx.req, 'api')
        // if (limited) return limited
        // ... handler logic using ctx.auth, ctx.body, ctx.req
      },
      { role: 'admin', schema }
    )
    ```

    Key migration rules:
    - Replace `withAuth` import with `createApiHandler` import from `@/lib/api-wrapper`
    - Extract inline body validation into a Zod schema (if the route manually validates body fields)
    - Move rate limiting inside the handler as the first line (createApiHandler doesn't handle it)
    - Replace `auth.uid` with `ctx.auth.uid`, `req` with `ctx.req`, body with `ctx.body`
    - Remove the manual try/catch outer wrapper (createApiHandler handles it)
    - Keep inner try/catches for specific operations (e.g., Firestore ops that need custom error messages)
    - Remove the `import { withAuth } from "@/lib/api-auth"` line
    - If `initAdmin()` is called, keep it — createApiHandler doesn't handle that
  </action>
  <verify>
    1. `npx tsc --noEmit` passes
    2. `grep -rn 'from "@/lib/api-auth"' src/app/api/admin/set-sound-engineer/route.ts src/app/api/admin/set-upload-permission/route.ts` — empty (no direct withAuth import)
    3. `grep -rn 'createApiHandler' src/app/api/admin/set-sound-engineer/route.ts src/app/api/admin/set-upload-permission/route.ts` — both files match
  </verify>
  <done>AC-1 partially satisfied: 2 admin routes migrated</done>

  <action>
    Apply the same migration pattern from Task 1 to all 9 library routes.

    **Additional considerations for library routes:**

    1. **Multiple HTTP methods:** Some routes export multiple methods (GET + POST, or POST + PATCH). Each method becomes a separate `export const METHOD = createApiHandler(...)` call. Share the Zod schema if body shape is the same.

    2. **Role requirements:** Check each route's `withAuth(req, role)` call:
       - `'band_leader'` → `{ role: 'band_leader' }`
       - No role argument → `{}` (any authenticated user)

    3. **Body validation:** If the route manually checks `!fileId` or `typeof x !== 'string'`, convert these to a Zod schema passed to createApiHandler options. Remove the manual checks.

    4. **Rate limiting:** If `checkRateLimit` is called, move it inside the handler as the first line. Keep the same rate category ('api' or 'ai').

    5. **HTTP status codes:** For routes that create new resources:
       - `library/archive` POST (creating archive entry) → 201
       - `library/save-generated` POST (saving generated chart) → 201
       - `library/upload` POST (uploading new file) → 201
       - Keep existing status codes for update/query operations

    6. **revalidatePath calls:** Keep these as-is inside the handler — they're Next.js cache invalidation, not auth-related.

    7. **initAdmin() calls:** Keep these — createApiHandler doesn't initialize Firebase Admin.
  </action>
