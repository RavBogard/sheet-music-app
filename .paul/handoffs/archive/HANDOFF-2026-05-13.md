## Open Issues (UAT — surfaced after push)

Both classified as **SPEC issues** per checkpoints.md diagnostic — NOT v60-09 code bugs.

### Issue 1 — Picker doesn't show recently-added songs (e.g., "Lechu Goldman")

**Root cause (CONFIRMED via direct Firestore admin SDK reads):**
- "Lechu Goldman" is a **Google Drive SHORTCUT** at `library_index/1jgs72zwhfEvqsqeeCFMw8Th7Zsk0mVJj`
- `mimeType: "application/vnd.google-apps.shortcut"` with `shortcutTargetId: "1kofaBcizbOP3VsM7jbnqXLle5KcLz_-a"`
- The v54-01-01 bootstrap had a MIME-type filter (PDF + MusicXML only) — shortcuts were intentionally filtered out of songs/*
- cron-sync (`/api/cron/sync`) writes library_index entries from Drive but does NOT mirror to songs/*
- Net: 134 docs are in `library_index` (498 total) but missing from `songs/*` (364 total — exactly the v54-01-01 bootstrap count)
- v60-09's listener IS working correctly — the doc simply doesn't exist in songs/* to deliver

**Library section still shows the song** because it reads `library_index.name` ("Lechu Goldman.pdf") and serves the PDF via Firebase Storage (Drive shortcut was resolved during the `storageCopiedAt` step on 2026-05-12). `/perform/{id}` works for the same reason.

**Fix path (out of v60-09 scope):** New follow-up phase — call it v60-11 or v6.1-something. Options:
1. **Resolve-shortcuts-at-sync.** Modify the Drive cron-sync to detect shortcuts, fetch the target file's metadata, write library_index with the target's mime type + name. Bootstrap then naturally includes them.
2. **Treat-shortcuts-as-first-class.** Drop the MIME filter at songs/* mirror time; write every library_index entry to songs/* regardless of mime, using `name` as the title (after `.pdf` suffix strip if present).
3. **Hybrid:** keep the strict MIME filter but add a separate shortcut-handler that resolves and mirrors. Cleanest but most code.

**My recommendation:** Option 2 (drop the MIME filter at the songs mirror layer specifically). Shortcuts work fine at Storage and /perform/{id}; only the picker's songs/* filter excluded them. Bootstrap rationale was MIME-type purity in songs/* — but `status: 'active' | 'archived'` is a better picker-filter than mime-type-implicit.

### Issue 2 — Every setlist (including brand-new ones) shows "Failed — retry — This setlist isn't on the server (was deleted or never synced)"

**Source:** `src/lib/sync/init.ts:104` `RemoteDocMissingError` thrown on UPDATE against a doc that returned `!snap.exists()` in the transaction. Daniel created a new setlist after deleting an old one and the new one immediately showed the error.

**NOT v60-09 territory.** No engine/sync changes in this phase. Suspected causes (untested):
- Client Firestore stuck state from back-to-back v60-08/09/10 deploys today (service-worker controllerchange + IDB version race). The firebase.ts auto-recovery path reloads after SW update; if that happened mid-edit, outbox rows could end up pointing to never-landed parent setlists.
- Auth token issue where client reads work (Library shows songs) but client writes fail silently in offline persistence, leaving the local client thinking addDoc succeeded while the server never received it.

**Recommended diagnostic for Daniel:** Chrome → Site settings → centralreform.live → Clear browsing data + re-sign-in. Force a fresh Firestore client state. If issue persists, it's a real bug warranting investigation — a separate phase (v60-12 or similar) for sync-engine resilience.

### Latent Issue 3 — `subscribe.ts` missing `recoverFromFirestoreShutdown` call

Found while debugging Issue 1. `src/lib/songs/subscribe.ts` error handler logs warn but doesn't call `recoverFromFirestoreShutdown` from `@/lib/firebase`. The 5 other snapshot listeners in the codebase (`use-monitor-connection.ts`, `use-safe-firestore-sync.ts`, `alert-store.ts`, `firestore-monitor-client.ts`, `notification-store.ts`) all do. v60-09 omitted it.

**Symptoms it would cause:** After a service-worker deploy, if the songs listener dies with "Firestore shutting down", it stays dead silently. Users would need to manually reload to recover the listener.

**Fix:** Add `recoverFromFirestoreShutdown(err)` to the error handler in `subscribe.ts:101-103`. ~3 LOC. Fold into the next follow-up phase or hotfix.
