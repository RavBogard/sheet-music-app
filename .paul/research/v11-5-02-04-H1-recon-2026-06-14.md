## Design fork to settle in the PLAN (bake decision)
Per-chart calibration storage:
- **Option A (per-device, localStorage via zustand persist):** add `chartCalibrations: Record<fileId, {zoom; crop?}>` to store + partialize. Instant, no network, NOT shared across band members/devices.
- **Option B (per-chart shared, Firestore):** `track.calibration` (mirror transposition) or `songs/{id}`/`library_index` map keyed by uid, written via applyEdit / edit_library_entry. Shared; needs a write seam + read on load.
- **Recommended MVP:** mirror `transposition` — a per-track `calibration?: { zoom?: number }` field via the SAME applyEdit path (shared across the band, like the live-director writes), restored on chart load like transposition; crop reserved (greenfield, defer to keep scope). PLUS add PDF fit-to-width (copy SmartScoreViewer's fitBase loop into PDFViewer) so "landscape auto-fit" covers PDFs (the gap). User calibration multiplies on top of the auto-fit baseline.
