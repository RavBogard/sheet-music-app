## ✅ P0 CHART-LOAD FIRE — FIXED + VERIFIED LIVE (2026-06-14)

Daniel reported: many/most charts FAILING TO LOAD on `/perform/setlist/7e005452-...`.
**Root cause (CONFIRMED by live probe):** Plan 01 H3 (`c687db99ee`) advertised `Accept-Ranges`
on EVERY response from `/api/drive/file/[fileId]` — which serves CHART bytes (PDF/text), not
just audio. pdf.js range-fetched; the route is public + CDN-cached (s-maxage 7d), so Vercel's
edge cached the 206 partials and replayed them as truncated `200`s (a 100-byte body as a
complete 200 for a 372KB PDF) → pdf.js got a truncated PDF → charts failed en masse.
**Fix (`ba38ad67b2`):** (1) `/api/drive/file/[fileId]` uses Range ONLY for `audio/*`; charts
return a plain 200 with NO Accept-Ranges (pre-H3 behavior). (2) `byteRangeResponse` marks
206/416 `Cache-Control: no-store` so partials can't be CDN-cached. **Verified live:** a chart
now returns `Accept-Ranges: ABSENT` and a Range request returns the FULL 372461 bytes (was a
100-byte truncated 200). New deployment busted the poisoned CDN cache (MISS→clean). Regression
test: `src/app/api/drive/file/[fileId]/route.test.ts` (6/6). H3 audio seeking preserved.

**No further fire action needed.** NEXT = resume H1 (write the PLAN from the recon note below).
