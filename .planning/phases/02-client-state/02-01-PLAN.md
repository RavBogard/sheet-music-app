# Phase 2: Client State & Caching Restructure

## Goal
Phase 2 focuses on restructuring the Transposer client caching and fetching logic to rely on the Phase 1 Vision API (`/api/ai/transposer/scan`) and the global Firestore cache, completely eliminating the old DOM text-scraping heuristics.

## Proposed Changes

### 1. Remove Deprecated Text Scanner
* **[DELETE]** [`text-scanner.ts`](file:///c:/Users/dsbog/CentralReform.live/sheet-music-app/src/lib/text-scanner.ts)
  * This removes ~250 lines of fragile heuristic DOM scraping logic.

### 2. Update Smart Transposer Hook
* **[MODIFY]** [`use-smart-transposer.ts`](file:///c:/Users/dsbog/CentralReform.live/sheet-music-app/src/hooks/use-smart-transposer.ts)
  * Remove `scanTextLayer` import and usage.
  * Simplify the `runScan` pipeline. Instead of text layer first, then AI validation:
    1. Check `loadChordCache` (already hits the global Firestore cache `/api/library/chord-cache`).
    2. On cache miss, generate a base64 image of the page using `capturePageImage`.
    3. Call the Phase 1 endpoint `POST /api/ai/transposer/scan` with the image.
    4. Save the exact Vision API coordinates to global cache via `saveChordCache(..., 'ai', true)`.
  * Clean up `mergeAiResults` as there's no longer a two-step merge process, only straight caching.

### 3. Implement Proactive Background Scanning
* **[MODIFY]** [`use-smart-transposer.ts`](file:///c:/Users/dsbog/CentralReform.live/sheet-music-app/src/hooks/use-smart-transposer.ts) (or new utility)
  * Add logic to aggressively cache adjacent pages.
  * *Approach*: When a page loads, if `pageNumber + 1` is also mounted in the DOM, silently run the image capture and `/api/ai/transposer/scan` call in the background at low priority (using `requestIdleCallback`) to pre-warm the global cache.

## Verification Plan

### Automated Tests
1. Run TS compiler: `npx tsc --noEmit` to ensure no dangling types to `text-scanner.ts`.
2. Run unit tests focusing on the transposer: `npx vitest run src/hooks/use-smart-transposer.test.ts`.

### Manual Verification
1. Load a sheet music PDF in the application.
2. Verify that `POST /api/ai/transposer/scan` is called for the current page.
3. Reload the same PDF.
4. Verify that the cache is hit (via `GET /api/library/chord-cache`) and no scan request is fired.
5. Verify chords visually overlay correctly based on the new absolute percentage positions.
