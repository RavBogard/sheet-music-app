<objective>
Fix the two foundational bugs blocking MusicXML transposition: (1) SmartScoreViewer does not initialize OSMD's TransposeCalculator, so `Sheet.Transpose` is silently ignored, and (2) PDFOverlay hardcodes `type: "pdf"` when building queue items, so MusicXML files are never identified as such.

Purpose: Without these fixes, the file-type branching in Plan 02 would have no effect -- transposition wouldn't work even if SmartScoreViewer were rendered, and MusicXML files would never be detected as musicxml type in the queue.

Output: SmartScoreViewer with working transposition, PDFOverlay with correct queue file types.
</objective>
