<objective>
Build the immersive PDF drill-down experience. When a musician taps a song, the PDF takes over the full screen with a persistent bottom bar providing setlist drawer, monitor access, song name, and prev/next navigation. The setlist stays mounted underneath -- closing the overlay returns to exact scroll position.

Purpose: This is the core performance UX -- musicians spend most of their time in this view during services. The bottom bar keeps setlist navigation and monitor mixing 1-2 taps away without breaking immersion.
Output: PDFOverlay component, PerformanceBottomBar, SetlistDrawer, and wiring into the page.
</objective>

  <action>
  Create three components per CONTEXT.md locked decisions:

  **PDFOverlay.tsx** -- Full-screen PDF takeover:
  - Fixed overlay (`fixed inset-0 z-50 bg-background flex flex-col`) rendering on top of the setlist.
  - Content area: renders `PDFViewer` (dynamically imported via `next/dynamic` with SSR disabled) with `url={/api/drive/file/${track.fileId}}`.
  - CRITICAL: When switching songs via drawer or prev/next, update the `url` prop rather than unmounting/remounting PDFViewer -- avoids "Worker was destroyed" errors (per RESEARCH.md Pitfall 1).
  - Add `pb-16` to PDF scroll container to prevent bottom bar from obscuring content (per RESEARCH.md Pitfall 6).
  - Body overflow: set `document.body.style.overflow = 'hidden'` on mount, restore on unmount -- prevents scroll position loss (per RESEARCH.md Pitfall 3).
  - Props: `track: SetlistTrack`, `tracks: SetlistTrack[]`, `currentIndex: number`, `onClose: () => void`, `onNavigate: (index: number) => void`, `isPublicView: boolean`.
  - Renders PerformanceBottomBar at the bottom.

  **PerformanceBottomBar.tsx** -- Persistent bar during PDF view:
  - Fixed at bottom (`fixed bottom-0 left-0 right-0 h-14 bg-zinc-950/95 backdrop-blur border-t border-white/10 z-[60]`).
  - Layout (left to right): setlist drawer button (List icon), monitor button (Headphones icon, hidden for public), current song name (centered, truncated), prev button (ChevronLeft), next button (ChevronRight).
  - Prev/next logic: compute `songIndices` = indexes of tracks where `(!type || type === 'song') && fileId`. Navigate only within these. Disable button at boundaries.
  - Monitor button: only show when `!isPublicView`. On tap, open a Radix Dialog/Sheet rendering `QuickMonitorPanel`. Use the glass morphism pattern for the sheet.
  - Close button (X icon) on far right to close the PDF overlay.
  - Add `pb-safe` for iOS safe area.
  - Icons from lucide-react: `List`, `Headphones`, `ChevronLeft`, `ChevronRight`, `X`.

  **SetlistDrawer.tsx** -- Slide-up overlay from bottom bar:
  - Use Radix Dialog or Sheet primitive for the slide-up animation and backdrop.
  - Shows compact version of the setlist: song titles with key badge, non-song items dimmed.
  - Highlight current song being viewed.
  - Tapping a song in the drawer: calls `onSelect(index)` which triggers PDFOverlay to switch PDF in place, then closes drawer.
  - Non-song items in drawer are visible but not tappable (no fileId).
  - Max height ~60% of viewport, scrollable, with rounded top corners.
  - Dark background consistent with the PDF overlay aesthetic.
