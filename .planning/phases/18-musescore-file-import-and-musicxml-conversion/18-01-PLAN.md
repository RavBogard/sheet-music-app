1. Install saxon-js and xslt3:
   ```bash
   cd /path/to/sheet-music-app && npm install saxon-js && npm install -D xslt3
   ```

2. Create `src/lib/xslt/mscx-to-musicxml.xsl` -- an XSLT 3.0 stylesheet that transforms MSCX XML to MusicXML `score-partwise` format. The stylesheet must handle:
   - `<Staff id="N">` elements mapping to `<part id="PN">` elements
   - `<Measure>` elements mapping to `<measure number="N">` elements
   - `<KeySig>` mapping to MusicXML `<key>` with `<fifths>` and `<mode>`
   - `<TimeSig>` mapping to MusicXML `<time>` with `<beats>` and `<beat-type>`
   - `<Chord>` + `<Note>` mapping to MusicXML `<note>` with `<pitch>` (step, alter, octave) and `<duration>`
   - `<Rest>` mapping to MusicXML `<rest>` with `<duration>`
   - `<Harmony>` (chord symbols) mapping to MusicXML `<harmony>` with `<root>` and `<kind>`
   - MuseScore 4 MSCX structure: root `<museScore>` with `<Score>` child containing `<Staff>` elements
   - Generate `<part-list>` from `<Part>` elements (instrument definitions in MSCX)
   - Use `xsl:output method="xml"` with MusicXML DOCTYPE declaration
   - Note pitch in MSCX uses `<pitch>` as a MIDI-like integer (0-127 TPC value) or `<tpc>` (tonal pitch class). Convert these to MusicXML step/alter/octave. MSCX `<pitch>` is literally the MIDI note number. Map: pitch % 12 gives the note class (0=C, 1=C#, 2=D...), pitch / 12 - 1 gives the octave.

3. Compile the XSLT to SEF format for SaxonJS:
   ```bash
   npx xslt3 -xsl:src/lib/xslt/mscx-to-musicxml.xsl -export:src/lib/xslt/mscx-to-musicxml.sef.json -t
   ```
   If xslt3 CLI compilation fails (it can be finicky with XSLT 3.0 features), fall back to loading the raw XSL at runtime via SaxonJS.transform with `stylesheetText` instead of `stylesheetFileName`. In that case, skip creating the .sef.json file and adjust the converter to read the .xsl file directly.

4. Create `src/lib/__tests__/fixtures/sample.mscx` -- a minimal valid MSCX file with:
   - `<museScore version="4.20">` root
   - One `<Part>` with instrument name
   - One `<Staff>` with 2 measures
   - Each measure containing a time signature (4/4), key signature (C major), and a few notes/rests
   - At least one `<Harmony>` chord symbol

5. Create `src/lib/__tests__/fixtures/sample.mscz` -- a ZIP archive (created programmatically via jszip in a small Node script or manually) containing the sample.mscx file. Alternatively, the test can create this fixture in a `beforeAll` hook using jszip to zip the .mscx content.
