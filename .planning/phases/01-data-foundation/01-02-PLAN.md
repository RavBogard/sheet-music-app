Three surgical changes in print-pipeline.ts, all within existing functions:

**Change 1 - Expand computeContentHash** (~line 73):
The `significant` object currently only includes `fileId`, `transposition`, `preferFlats`, `capoFret` per track, and `title`, `date`, `musicianName` at the request level. Expand it to include ALL cover-page-visible fields:

```typescript
const significant = {
    title: req.title,
    date: req.date,
    musicianName: req.musicianName,
    eventName: req.eventName,           // ADD: was missing
    tracks: req.tracks.map(t => ({
        fileId: t.fileId,
        transposition: t.transposition || 0,
        preferFlats: t.preferFlats || false,
        capoFret: t.capoFret || 0,
        title: t.title,                 // ADD: cover page field
        key: t.key || '',               // ADD: cover page field
        notes: t.notes || '',           // ADD: cover page field
        leadMusician: t.leadMusician || '', // ADD: cover page field
        tune: t.tune || '',             // ADD: new tune field
    })),
}
```

This fixes STAB-01: any change to cover page fields (key, lead, notes, tune, event name) will produce a different hash, causing a cache miss and PDF regeneration.

**Change 2 - Add Tune column to buildCoverPage** (~line 275+):
In the column position definitions, add a `colTune` position between `colTitle` and `colLead`. Redistribute column widths to accommodate. Suggested positions for the common case (no transposition column):
- colNum: 50
- colTitle: 75 (max ~17 chars)
- colTune: 200 (max ~12 chars, truncate longer names)
- colLead: 290
- colKey: 375
- colNotes: 420

When `hasTranspositions` is true, compress further (reduce maxTuneLen, maxLeadLen).

Add the "Tune" header label in the header row drawing code, following the same `drawText` pattern as "Lead" and "Key" headers.

In the track row drawing loop, for non-service-flow tracks (songs), draw the tune text at colTune position. Truncate to maxTuneLen chars. For service-flow tracks (headers, readings, etc.), skip the tune cell (same as how key/lead are skipped for service-flow).

**Change 3 - Bump cover page font sizes**:
Per CONTEXT.md decision: bump all body text from current `size: 10` to at least `size: 12`. Bump header text (column labels, service title) to `size: 14` or larger. Notes text (currently `size: 9`) should go to at least `size: 10`.

These font size bumps apply to ALL text in `buildCoverPage()` -- this is a readability fix, not the full Phase 3 redesign. Keep the same basic table layout structure.

Use Claude's discretion for exact column widths and truncation lengths per CONTEXT.md. The goal is that all columns fit on a 612pt wide page without overlap, and text is readable from arm's length on a music stand.
