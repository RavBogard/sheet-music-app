# Phase 3: Formatting & Presentation Layer

## Goal Description
The purpose of Phase 3 is to finalize the client-side presentation layer for the Smart Transposer feature. In Phase 1 and 2, we successfully extracted perfect percentage-based bounding box coordinates for every chord on the page and built a robust caching system around them. 

Phase 3 focuses on using that data to ensure the transposed chords *perfectly* cover the completely original chord print on the PDF underneath it. The text shouldn't peek through, and the size parameters provided by the Vision API (`w` and `h` percentages) should be strictly obeyed rather than falling back to heuristics when possible.

## User Review Required
> [!NOTE]
> The current `SmartTransposer.tsx` and `overlay-sizing.ts` actually do a fairly good job handling absolute percentages because they were refactored recently in preparation for this phase! 
> The main things left to do are:
> 1. Make the background color block out the underlying text strictly (it currently uses `rgba(255, 255, 255, 0.97)` which is close, but we might want it to be 100% opaque `white` or explicitly match the page color).
> 2. Ensure `overlay-sizing.ts` favors the exact bounding box height from the Vision API for font-sizing instead of applying the `H_PCT_TO_FONT_SCALE = 0.90` heuristic, which was originally built to account for DOM text line-height padding. The Vision APIs provide exact visual bounding boxes.
> 3. Clean up the `addingChordAt` click logic in `use-smart-transposer.ts` to ensure it seamlessly connects with the popover when adding new chords manually via double-click.
