# CentralReform v3.1.0 — Deployment Guide

Step-by-step instructions for deploying all v3.1.0 features to production.

---

## Step 1: Deploy Firestore Rules

The new rules add support for congregation config, presence, and annotations.

1. Open a terminal in the project root
2. Run:
   ```bash
   firebase deploy --only firestore:rules
   ```
3. Verify in the [Firebase Console](https://console.firebase.google.com) → Firestore → Rules tab

**What changed:**
- Added `config/congregation` — read for members, write for admins
- `setlists/{id}/presence/{uid}` — live sync presence (already in file)
- `users/{uid}/annotations/{fileId}` — chart annotations (already in file)

---

## Step 2: Create the Congregation Config Document

The app works without this (falls back to hardcoded CRC defaults), but creating it lets you change branding without a code deploy.

1. Go to [Firebase Console](https://console.firebase.google.com) → Firestore
2. Navigate to (or create) collection: **`config`**
3. Add document with ID: **`congregation`**
4. Add these fields:

| Field | Type | Value |
|-------|------|-------|
| `name` | string | `Central Reform Congregation` |
| `shortName` | string | `CRC Music` |
| `location` | string | `St. Louis, MO` |
| `logoUrl` | string | `/logo.jpg` |
| `description` | string | `Digital Sheet Music Library for CRC Musicians` |
| `themeColor` | string | `#7c3aed` |
| `driveFolderId` | string | *(your Google Drive folder ID)* |
| `printFooter` | string | `Generated by CRC Music Books` |
| `features` | map | *(see below)* |

5. For the `features` field, add a map with these boolean values:

| Key | Type | Value |
|-----|------|-------|
| `monitor` | boolean | `true` |
| `ai` | boolean | `true` |
| `audio` | boolean | `true` |
| `annotations` | boolean | `true` |
| `collaboration` | boolean | `true` |

> **Tip:** Setting any feature to `false` hides it from the nav and UI immediately — no redeploy needed.

## Step 3: Deploy the Web App

```bash
# From project root:
npm run build
# Then deploy however you normally do (Vercel, Firebase Hosting, etc.)
```

If using Vercel, just push to your deploy branch — it builds automatically.

If using Firebase Hosting:
```bash
firebase deploy --only hosting
```

## Step 4: Test the New Features

### Live Sync (D1)
1. Open a setlist in the editor on two devices
2. You should see each other's avatar in the setlist header
3. Toggle the **LIVE** button (red pulsing badge)
4. Tap a track — the other device should get a "Jump to song" toast

### Annotations (D2)
1. Open any song in perform mode
2. Tap the **pencil icon** in the toolbar
3. The annotation toolbar slides in — try drawing, adding text, changing colors
4. Exit and re-enter: your annotations should persist
5. Annotations are per-user, so each musician sees only their own

### Congregation Config (E1)
1. Check that the login page shows your congregation name (not hardcoded "CRC")
2. Check that the homepage greeting uses the configured `shortName`
3. Try toggling `features.monitor` to `false` in Firestore — the Monitor nav item should disappear

### Onboarding (B1)
1. Have a new person sign in with Google
2. They should see a welcome card explaining their account is pending
3. Approve them in Admin → People
4. On their next visit, they should get the "set up your instrument" prompt

### Print (B3)
1. Open a setlist → Print
2. You should see three options: Standard, Just Me, and Select Musicians
3. "Just Me" generates a single PDF with your transpositions applied

## Step 5: Bridge Server (if using X32 monitors)

The bridge server now has Docker support, a health check endpoint, and proper service management.

See [`bridge/README.md`](bridge/README.md) for full instructions. The short version:

**Docker (recommended):**
```bash
cd bridge
# Place service-account-key.json here
docker compose up -d
```

**Windows Service:**
```bash
cd bridge
npm install && npm run build
npm install -g node-windows
npm run install-service
```

**Verify it's running:**
```bash
curl http://localhost:9001/health
# → { "status": "ok", "uptime": 42, "x32Connected": true, "clients": 0 }
```

- [ ] Annotations draw and persist on charts

- [ ] Bridge health check responds (if using monitors)

## Rollback

If something goes wrong:

**Web app:** Redeploy the previous version from Vercel/Firebase Hosting dashboard.

**Firestore rules:** In Firebase Console → Firestore → Rules → click the previous version in the history dropdown.

**Congregation config:** Delete the `config/congregation` document — the app falls back to hardcoded CRC defaults.

**Bridge:** `docker compose down` or `npm run uninstall-service` and go back to the previous version.
