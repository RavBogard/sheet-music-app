# CentralReform v3.1.0 — Deploy Checklist (No Terminal Required)

Everything you need to do, all in the browser.

---

## 1. Deploy Firestore Rules

1. Go to **[Firebase Console](https://console.firebase.google.com)** → your project → **Firestore Database** → **Rules** tab
2. **Select all** the existing rules and **replace** with the following:

```
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    function isSignedIn() {
      return request.auth != null;
    }

    function isOwner(resource) {
      return isSignedIn() && resource.data.ownerId == request.auth.uid;
    }

    function isAdmin() {
      return request.auth.uid == '93Xn3DbS0bSNb8zmfzLyfOMX1Ai3' 
          || request.auth.token.role == 'admin';
    }

    function isLeader() {
      return isAdmin() || request.auth.token.role == 'leader';
    }

    function isMember() {
      return isLeader() || request.auth.token.role == 'member';
    }

    match /users/{userId} {
      allow read: if (isSignedIn() && request.auth.uid == userId) || isAdmin();
      allow write: if (isSignedIn() && request.auth.uid == userId) || isAdmin();

      match /setlists/{docId} {
        allow read, write: if isSignedIn() && request.auth.uid == userId;
      }

      match /songPreferences/{fileId} {
        allow read, write: if isSignedIn() && request.auth.uid == userId;
      }

      match /annotations/{fileId} {
        allow read, write: if isSignedIn() && request.auth.uid == userId;
      }

      match /preferences/{docId} {
        allow read, write: if isSignedIn() && request.auth.uid == userId;
      }
    }

    match /setlists/{setlistId} {
      allow read: if (resource.data.isPublic == true) || isOwner(resource);

      allow create: if isSignedIn() 
                    && request.resource.data.ownerId == request.auth.uid
                    && (request.resource.data.isPublic != true || isLeader());

      allow update: if isOwner(resource) 
                    || (resource.data.isPublic == true && isLeader());

      allow delete: if isOwner(resource) || isAdmin();

      match /presence/{odinguid} {
        allow read: if isSignedIn();
        allow write: if isSignedIn() && request.auth.uid == odinguid;
        allow delete: if isSignedIn() && request.auth.uid == odinguid;
      }
    }
    
    match /publicSetlists/{docId} {
      allow read: if true;
      allow write: if false;
    }

    match /config/congregation {
      allow read: if isSignedIn();
      allow write: if isAdmin();
    }

    match /config/monitor {
      allow read: if isSignedIn();
      allow write: if isAdmin()
                   || (isSignedIn() && request.auth.uid in resource.data.authorizedUsers);
    }
  }
}
```

3. Click **Publish**

## 2. Create the Congregation Config Document

1. Still in **Firestore Database** → **Data** tab
2. If a `config` collection already exists (it should — `config/monitor` is there), click into it. If not, click **Start collection**, name it `config`
3. Click **Add document**
4. Set the **Document ID** to: `congregation` (type it manually, don't auto-generate)
5. Add these fields one by one:

| Field name | Type | Value |
|-----------|------|-------|
| `name` | string | `Central Reform Congregation` |
| `shortName` | string | `CRC Music` |
| `location` | string | `St. Louis, MO` |
| `logoUrl` | string | `/logo.jpg` |
| `description` | string | `Digital Sheet Music Library for CRC Musicians` |
| `themeColor` | string | `#7c3aed` |
| `driveFolderId` | string | *(paste your Google Drive folder ID here)* |
| `printFooter` | string | `Generated by CRC Music Books` |

6. Now add the `features` field:
   - Click **Add field**
   - Field name: `features`
   - Type: **map**
   - Click the **+** inside the map to add each sub-field:

| Field name | Type | Value |
|-----------|------|-------|
| `monitor` | boolean | `true` |
| `ai` | boolean | `true` |
| `audio` | boolean | `true` |
| `annotations` | boolean | `true` |
| `collaboration` | boolean | `true` |

7. Click **Save**

> **Tip:** You can toggle any feature to `false` later and it immediately hides from the app — no redeploy needed.

## 3. Deploy the Web App

**If you're on Vercel:** It's already done. The code was pushed to GitHub, and Vercel auto-deploys from your branch. Check your [Vercel dashboard](https://vercel.com/dashboard) to confirm the build succeeded.

**If you're on Firebase Hosting:** You'll need a terminal for this one — `firebase deploy --only hosting`. (This is the one step that can't be browser-only with Firebase Hosting.)

## 4. Test the New Features

Open your deployed app and walk through these:

### Quick smoke test
- [ ] App loads, no blank screen
- [ ] Login page shows "Central Reform Congregation" (from Firestore config, not hardcoded)

### Onboarding (B1)
- [ ] Sign in with a Google account that doesn't have access yet
- [ ] Should see a welcome card: "Your account is being reviewed"
- [ ] Approve them in Admin → they should see instrument setup prompt on next visit

### Library (B4)
- [ ] Open Library on your phone — you should see 7-8 rows without scrolling (was 4)

### Print (B3)
- [ ] Open a setlist → tap Print
- [ ] Should see three options: **Standard**, **Just Me**, **Select Musicians**
- [ ] "Just Me" should generate your personal transposed packet

### Performance Mode (C1-C3)
- [ ] Open a setlist → tap Perform
- [ ] **First time:** you should see a gesture tutorial overlay — tap "Got it"
- [ ] **Swipe down** from the top of the screen — it should exit perform mode
- [ ] **Home button** should return you to the setlist you came from (not the homepage)
- [ ] **On desktop/laptop:** Arrow keys scroll, PageDown/PageUp advance songs, Escape exits

### Live Sync (D1)
- [ ] Open the same setlist on two devices (or two browser tabs)
- [ ] You should see the other device's avatar in the setlist header
- [ ] Toggle the **LIVE** button → tap a song → other device gets a toast notification

### Annotations (D2)
- [ ] In perform mode, tap the **pencil icon** in the toolbar
- [ ] Draw on the chart, add text notes, try different colors
- [ ] Exit and come back — your annotations should still be there

### Feature Flags (E1)
- [ ] In Firestore, set `config/congregation → features → annotations` to `false`
- [ ] Reload the app — the annotation pencil icon should disappear
- [ ] Set it back to `true`

### Admin (A6)
- [ ] Open Admin page — sections should be collapsible accordions
- [ ] Section with pending users should auto-expand

## 5. Bridge Server (only if using X32 monitors)

This one does require the production PC. Three options are in `bridge/README.md` in the repo. The easiest:

**Docker:** Place `service-account-key.json` in the `bridge/` folder, then run `docker compose up -d`.

**Windows Service:** Run `npm install && npm run build && npm run install-service`.

**Verify:** Visit `http://[production-pc-ip]:9001/health` in your browser — should return `{"status":"ok"}`.

## If Something Goes Wrong

| Problem | Fix |
|---------|-----|
| App shows wrong branding | Edit the `config/congregation` document in Firestore Console |
| Feature shouldn't be visible | Set its flag to `false` in `config/congregation → features` |
| Rules causing permission errors | In Firestore → Rules tab, click the clock icon to revert to previous version |
| Need to roll back the whole app | In Vercel dashboard → Deployments → click "..." on previous deploy → Promote to Production |
| Annotations/presence not working | Check that Firestore rules were published (Step 1) |
