## Step 2: Create the `config` Collection

Your Firestore currently has: `digitized_charts`, `library_index`, `publicSetlists`, `setlists`, `users`. You need to add a `config` collection with one document.

### Create the congregation config document

1. In the **Data** tab (where you are now), click **+ Start collection**
2. **Collection ID:** `config`
3. Click **Next** — it will ask you to add the first document
4. **Document ID:** type `congregation` (don't use auto-ID)
5. Add these fields one at a time. For each field, click **Add field** after the previous one:

| Field name | Type | Value |
|-----------|------|-------|
| `name` | string | `Central Reform Congregation` |
| `shortName` | string | `CRC Music` |
| `location` | string | `St. Louis, MO` |
| `logoUrl` | string | `/logo.jpg` |
| `description` | string | `Digital Sheet Music Library for CRC Musicians` |
| `themeColor` | string | `#7c3aed` |
| `driveFolderId` | string | *(your Google Drive root folder ID — the one the app syncs from)* |
| `printFooter` | string | `Generated by CRC Music Books` |

6. Now add the **features** field:
   - Click **Add field**
   - Field name: `features`
   - Type: change the dropdown from "string" to **map**
   - Click the **+** button that appears inside the map to add sub-fields:

| Field name | Type | Value |
|-----------|------|-------|
| `ai` | boolean | `true` |
| `annotations` | boolean | `true` |
| `audio` | boolean | `true` |
| `collaboration` | boolean | `true` |
| `monitor` | boolean | `true` |

7. Click **Save**

### What this gives you

The app reads this document on load. You can now:
- **Rename the app** by editing `shortName` — it updates everywhere instantly
- **Disable features** by flipping any boolean to `false` — the nav item and UI disappear without a redeploy
- **Change the print footer** — next time someone generates a gig packet, it uses the new text

> **Finding your Drive folder ID:** Open your CRC Music Google Drive folder in a browser. The URL looks like `https://drive.google.com/drive/folders/1abc123xyz`. The part after `/folders/` is your folder ID. If you're not sure, leave `driveFolderId` as an empty string for now — the library sync uses a server-side env variable for this anyway, so it won't break anything.

## Step 3: Verify the Deploy

Vercel auto-deployed when the code was pushed to GitHub. Open your app and check:

### Quick smoke test
- [ ] App loads normally
- [ ] Homepage greeting shows your name

### New features to try

**Library (phone):** Open the Library on your phone — rows should be noticeably more compact, fitting 7-8 songs on screen instead of 4.

**Print:** Open any setlist → tap the print/download icon. You should now see three options: **Standard**, **Just Me** (your personal transposed packet in one tap), and **Select Musicians** (checkboxes to pick who to print for).

**Performance mode:** Open a setlist → tap Perform.
- First time: you'll see a gesture tutorial overlay. Tap "Got it"
- Swipe down from the top of the screen — should exit perform mode
- The Home button should return you to the setlist you came from, not the homepage
- On a laptop: Arrow keys and PageDown/PageUp scroll and advance songs. Escape exits. Space toggles the toolbar.

**Annotations:** In perform mode, tap the pencil icon in the toolbar. Draw on the chart, add text, change colors. Exit and come back — your marks should persist.

**Live sync:** Open the same setlist on two devices or two browser tabs. You should see the other session's avatar in the setlist header. Toggle the LIVE button, tap a song — the other device gets a notification.

**Admin:** The admin page sections should now be collapsible accordions, with the People section auto-expanding if there are pending users.

**Feature flags:** Go back to Firestore → `config/congregation` → set `features.annotations` to `false`. Reload the app — the pencil icon should disappear from the performance toolbar. Set it back to `true` when done.

## If Something Goes Wrong

| Problem | Fix |
|---------|-----|
| App shows wrong branding | Edit `config/congregation` in Firestore |
| Feature showing that shouldn't | Set its flag to `false` in `config/congregation → features` |
| Permission errors on new features | Check that rules were published (Firestore → Rules tab) |
| Need to roll back the app | Vercel dashboard → Deployments → "..." on previous deploy → Promote to Production |
| Annotations or presence not saving | The rules handle this — make sure the published rules include the `annotations` and `presence` matches |
