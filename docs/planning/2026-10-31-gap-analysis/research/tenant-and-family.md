# Research: tenant-and-family (2026-10-31)

Area: Part A, Brothers Lazaroff (BL) as a full peer product. Part B, the family seams (Overlays, Beit Mitzvah portal, shireishabbat books, Haftarah). Read-only; no data written, no test data created.

## 1. How it works today

**Tenancy is a code table plus an `orgs/{id}` config doc.** The host sets `x-org-id` in the proxy; `getOrgConfig` falls back to `src/lib/org/config-code.ts` for `crc` and `brotherslazaroff`. BL is `vocabulary.mode: "band"` (`config-code.ts:195`), features `{mixer:false, driveInbox:false, schedulingEmails:false, todayFeed:true, notifyBand:true, perform:true}` (`config-code.ts:210`). Band mode only does two things in the UI: it hides the service-type selector and rabbi field (`src/lib/org/vocab.ts:21`, used in exactly three components: `CreationWizard.tsx:73`, `SetlistMetaEditSheet.tsx:107`, `SetlistCards.tsx:222,368`) and renames setlist to "set" through `BL_VOCAB` (`config-code.ts:65`). BL's MCP connector gets a generated guide (`src/lib/mcp/agent-guide.ts:157-205`): an intro, three fact lines, then the shared propose/confirm/commit core. BL has 95 of the 109 authoring tools (golden `p6-tool-lists-before.json` minus the 14 dropped in `P6-BL-FLAGS.md`).

**Setlist memory for BL** (last commit `6f1b397a`): `memoryServiceType` (`src/lib/profiles/keys.ts:36`) puts every BL choice under the stored `serviceType`, else the single scope `"gig"`. So "keep it" works per song for BL, across all gigs together.

**Family data flow.** Overlays reads `list_setlists`/`get_setlist`/`get_congregation_context` through a scoped bearer (`RETURN-OVERLAYS-ASKS` section 1). `today.json` (`src/lib/today/types.ts`) is metadata-only: setlistId, name, serviceType, eventDate, startsAt, book, startFolio, rabbi, stream. Books arrive as committed snapshots in `src/data/books/*.json` via `scripts/ops/sync-books.mjs` from shireishabbat `dist-app/`. The Beit Mitzvah portal calls a CRC-only endpoint `POST /api/integrations/beit-mitzvah/v1` (`ensure`/`projection`/`resource`; `docs/planning/2026-10-20-beit-mitzvah-service-bridge/CONTRACT.md`). The Haftarah plugin has no connection to this app at all.

## 3. Big bets

1. **Gig object for BL (the "show sheet").** Problem: BL has sets but no show. Sketch: `gig` block on a setlist (TF-01), set totals with target lengths (TF-02), segue flags (TF-03), a one-page "show sheet" PDF (venue, load-in, times, set order, keys, who sings) and per-contact parts (TF-09). Risk: `Setlist` is shared with CRC and emitted to Overlays; keep every field optional and BL-visible only. Effort L.
2. **Band-mode as a real mode, not a hide list.** Problem: band mode removes two fields and leaves liturgy tools, text and views in place (TF-05/06/07/08). Sketch: one `profile: "congregation" | "band"` on the org config that selects tool list, agent guide text, templates, matrix, print/email wording and legal copy from one table; the frozen CRC set is retired with Daniel's wording. Risk: BL tool-list golden changes; every shared surface needs both-tenant tests (per `CLAUDE.md`). Effort L.
3. **One "week" spine for the family.** Problem: Daniel names Friday and Shabbat in 3 products (TF-12). Sketch: `weekKey` + `occasion` on the setlist, emitted in `today.json`; Haftarah `start_week` and Overlays `create_service` read it from `today.json` or `get_setlist`; the parasha chip shows in the setlist header. Metadata only. Risk: reshaping a file the reader parses (`today/types.ts` says do not reshape without the reader); additive keys are safe. Effort M-L.
4. **Beit Mitzvah ceremony card in the setlist.** Problem: slot, rehearsal dates, reading names live only in the portal (TF-13). Sketch: a read-only chip on bridge-created setlists from the bridge projection (names and refs only), with a "this service came from the portal" link both ways. Risk: privacy (student names stay out; use "service slot + refs"); the bridge is CRC-only by contract. Effort M.
5. **Family smoke test.** Problem: three seams with no proof (TF-11/13/17). Sketch: a weekly Monday check run by the existing cron: build a read of the next setlist via the Overlays bearer scope, ensure the BM endpoint answers, compare `list_books` to the registry file. Report in `/api/health`. Risk: cron cost, scoped-token handling. Effort M.
