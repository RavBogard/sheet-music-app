## 🔴 CRITICAL — Fix Immediately

### 1. Middleware Blocks Public Routes (`/perform/*`, `/qr/*`)

**File:** `src/middleware.ts` (lines 22, 28, 37–40)

The middleware redirects unauthenticated users to `/login` for any route not in the `publicRoutes` array — which is only `['/login', '/']`. This breaks:

- **Performance view** — `/perform/[id]` and `/perform/setlist/[id]` serve public setlists to musicians who may not be signed in
- **QR code sign-in** — `/qr/[code]` is literally the page you use *before* you have a session
- **Public setlist editor view** — `/setlists/[id]?public=true`

**Impact:** Anyone clicking a shared setlist link or scanning a QR code without an existing session gets redirected to login. This is a showstopper for the performance workflow.

**Fix:** Expand `publicRoutes` to use prefix matching:
```ts
const publicPrefixes = ['/login', '/perform', '/qr']
const isPublicRoute = 
    request.nextUrl.pathname === '/' || 
    publicPrefixes.some(p => request.nextUrl.pathname.startsWith(p))
```

Also consider adding `/setlists/` with a `?public=true` query param check, since the setlist editor page supports public viewing.

### 2. Orphan Pruner Queries Wrong Firestore Collection — Potential Data Destruction

**File:** `src/app/api/admin/prune-orphans/route.ts` (line 21)

The route queries `drive_files` to build its set of valid file IDs:
```ts
const filesSnap = await db.collection("drive_files").get()
```

But the canonical library collection used everywhere else in the app is `library_index`. If `drive_files` is empty or doesn't exist, the pruner's `validFileIds` set will be empty, causing it to classify **every** track's `fileId` as orphaned — and unlink them all.

**Impact:** Running "Scrub Database" in the admin panel could strip all file references from all setlists. This is a catastrophic, irreversible data loss bug.

**Fix:** Change to `library_index`:
```ts
const filesSnap = await db.collection("library_index").get()
```

The same `drive_files` vs `library_index` mismatch exists in `src/app/api/admin/analytics/route.ts` (line 33), which would report 0 library files.

### 3. `framer-motion` Re-added to PerformerView (Contradicts Phase 1 Removal)

**File:** `src/components/views/PerformerView.tsx` (line 6)

We removed `framer-motion` entirely in Phase 1 to eliminate ~45KB from the bundle. The Gemini session re-added it as a dependency in `package.json` and re-introduced `motion` / `AnimatePresence` imports in `PerformerView`. This is the **performance-critical** path — the view every musician sees on stage.

**Impact:** 45KB+ bundle regression on the most latency-sensitive page. Also, framer-motion was specifically removed from the project; having it back in `package.json` means any component could accidentally import it again.

**Fix:** Replace with CSS animations (the swipe transition is a simple fade/slide that CSS handles natively) and remove `framer-motion` from `package.json`.

## 🟠 SIGNIFICANT — Fix Before Next Deploy

### 4. `test-gemini` API Route Has No Authentication

**File:** `src/app/api/test-gemini/route.ts`

This route is a GET endpoint with zero auth checks. It calls the Gemini API using your `GOOGLE_GENERATIVE_AI_API_KEY`, fetches a hardcoded Google Sheets URL, and returns detailed trace/timing data. Anyone on the internet can call it to burn your API quota and see internal infrastructure details.

**Fix:** Either delete this route (it's clearly a development artifact) or add `withAuth(request, 'admin')`.

### 5. Committed Service Worker Contains Stale Precache Manifest

**Files:** `public/sw.js`, `public/workbox-ac21e85f.js`

These are build-time artifacts generated by `@ducanh2912/next-pwa`. They're committed to git, which means:

- The committed `sw.js` still calls `self.skipWaiting()` despite the config comment saying "skipWaiting removed"
- The precache manifest references chunk hashes from the build that generated them, not the current build. Vercel regenerates these at deploy time, so the committed versions are always stale
- They'll cause merge conflicts on every build

**Fix:** Add to `.gitignore`:
```
public/sw.js
public/sw.js.map
public/workbox-*.js
public/workbox-*.js.map
```
Then `git rm --cached public/sw.js public/workbox-ac21e85f.js`.

### 6. Icon Files: 4 Identical Copies + Dynamic Route Conflicts

**Files:** `public/icon-192.png`, `public/icon-512.png`, `src/app/icon.png`, `src/app/apple-icon.png`

All four files are byte-identical (md5: `ada4f36d...`, 213,673 bytes each). Problems:

- `icon-192.png` and `icon-512.png` should be different resolutions — they're the same file
- `src/app/icon.png` conflicts with `src/app/icon.tsx` (Next.js prefers the `.tsx` route handler, making the `.png` dead weight)
- `src/app/apple-icon.png` conflicts with `src/app/apple-icon.tsx` (same issue)
- Both `.tsx` files have ESLint `jsx-a11y/alt-text` warnings on their `<img>` tags

**Fix:** Remove the static duplicates (`src/app/icon.png`, `src/app/apple-icon.png`). Regenerate `public/icon-192.png` and `public/icon-512.png` at proper resolutions (or remove them if the manifest is using the dynamic `/icon` and `/apple-icon` routes). Add `alt=""` to the `<img>` tags in the `.tsx` files.

### 7. Middleware Admin Route Check Uses Wrong Role Name

**File:** `src/middleware.ts` (line 55)

```ts
if (role !== 'admin' && role !== 'leader') {
```

The middleware checks for `leader`, but the app's canonical role name is `band_leader`. The `leader` string is a legacy backward-compat value. If any admin users have been assigned the modern `band_leader` role, they'll be blocked from the admin panel by middleware even though the client-side and API auth all handle `band_leader` correctly.

**Fix:**
```ts
if (role !== 'admin' && role !== 'leader' && role !== 'band_leader') {
```

---

### 8. `DeveloperToolsSection` Also Misses `band_leader` Role

**File:** `src/components/admin/DeveloperToolsSection.tsx` (line 14)

```ts
if (profile?.role !== "band_leader" && profile?.role !== "admin") return null
```

Conversely, this checks for `band_leader` but not the legacy `leader`. A user with the old `leader` role won't see the developer tools section.

**Fix:** Use `isBandLeader` from `useAuth()` which handles both:
```ts
const { isBandLeader } = useAuth()
if (!isBandLeader) return null
```

### 10. `_serverGreeting` Underscore Prefix Is Misleading

**File:** `src/app/(main)/DashboardClient.tsx` (line 33)

```ts
const initialGreeting = _serverGreeting || getContextualGreeting(...)
```

The underscore was likely added to suppress an earlier ESLint warning. Now that it's used, the prefix is misleading.

**Fix:** Rename back to `serverGreeting`.

Uses `<style jsx global>` for the swipe animation keyframes. While Next.js technically supports styled-jsx in client components, it has had intermittent hydration issues in the App Router. Safer to move the `@keyframes swipe-anim` to `globals.css`.

### 16. `ignoreBuildErrors` and `ignoreDuringBuilds` in `next.config.ts`

```ts
eslint: { ignoreDuringBuilds: true },
typescript: { ignoreBuildErrors: true },
```

These were likely needed during rapid development but mean that TypeScript errors and ESLint violations won't block deploys. Now that CI runs both checks, these flags create a false safety net — a deploy can succeed even if CI fails.

---

### 17. `typescript: { ignoreBuildErrors: true }` Masks Real Errors

With this flag, the `papaparse` missing types issue I found (and fixed by running `npm install`) would have silently deployed. In production, this could cause runtime crashes that TypeScript would have caught at build time.
