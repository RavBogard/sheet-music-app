## Session 2 — Auth Route Standardization

**2a. Migrate 12 routes from raw verifyIdToken to requireAuth** (A3)

All these routes manually call `verifyIdToken` instead of using the standard `requireAuth()` wrapper:

```
admin/prune/execute/route.ts
admin/prune/scan/route.ts
admin/set-role/route.ts
admin/migrate-storage/reset/route.ts
admin/migrate-storage/route.ts
ai/omr/route.ts
ai/transposer/route.ts
chat/route.ts
drive/save/route.ts
library/chord-cache/route.ts
library/save-generated/route.ts
setlist/transfer/route.ts
```

Current pattern in these files:
```ts
const token = req.headers.get("Authorization")?.split(" ")[1]
const decoded = await verifyIdToken(token)
```

Target pattern:
```ts
const auth = await requireAuth(req)  // throws NextResponse on failure
```

Note: `requireAuth` currently **throws** the error response rather than returning it. This is consistent but unusual — each route needs try/catch wrapping. Consider refactoring requireAuth to return a union type instead, which would be cleaner, but that's a bigger change.

**Estimated time: 30–45 min** (mechanical, but each route needs testing)

## Session 3 — Notification Triggers

The notification infrastructure exists (store, bell, Firestore rules) but nothing ever *creates* notifications. The bell will always show 0.

**3a. Wire notification triggers into setlist operations** (C3)

Insert `broadcastNotification` calls at these points:

| Trigger | Location | Notification |
|---------|----------|-------------|
| Setlist published | `setlistService.makePublic()` | "Shabbat Service setlist published" to all members |
| Tracks updated | `setlistService.updateSetlist()` (when tracks change) | "Shabbat Service was updated (7 tracks)" to all members |
| Role changed | `updateUserRole()` in PeopleSection | "Your role was changed to member" to the affected user |

Challenge: `broadcastNotification` needs a list of member UIDs. Options:
- Query `users` collection where `role in ['member', 'leader', 'admin']` at notification time
- Or pass member list through from the calling context

Simplest: query at notification time. It's a fire-and-forget async call.

**3b. "What's new" indicator on homepage** (C3)
- Track `lastVisitedAt` in user preferences (write on app load)
- On YourWeekSection, show a "New" badge on setlists with `updatedAt > lastVisitedAt`
- Lightweight: just one Firestore read + comparison

**Estimated time: 45–60 min**
